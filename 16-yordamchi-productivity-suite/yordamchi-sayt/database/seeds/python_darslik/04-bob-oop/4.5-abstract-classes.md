# Abstract classes (abc moduli)

## Bu darsda nimalarni o'rganasiz

- Abstrakt klass (abstract class) nima ekanini va nega kerakligini tushunasiz
- `abc` moduli va `@abstractmethod` dekoratoridan foydalana olasiz
- Abstrakt klass va oddiy meros orasidagi farqni tushuntira olasiz
- Interfeys (interface) tushunchasini Python kontekstida qo'llay olasiz

## Nazariy qism

### Muammo — nega oddiy meros ba'zan yetarli emas

4.2-darsda ko'rgan `Hayvon` klassini eslang:

```python
class Hayvon:
    def ovoz_chiqar(self):
        print("Hayvon ovoz chiqarmoqda...")
```

Muammo: hech kim `Hayvon`ning bevosita obyektini yaratmasligi, faqat `It`, `Mushuk` kabi **aniq** avlodlarini yaratishi kerak — chunki "umumiy Hayvon" tushunchasi juda mavhum. Lekin oddiy Python kodi buni **majburlamaydi**:

```python
hayvon = Hayvon()    # bu texnik jihatdan ishlaydi, lekin mantiqan noto'g'ri!
hayvon.ovoz_chiqar()
```

**Abstrakt klass** — aynan shu muammoni hal qiladi: u "faqat meros olish uchun mo'ljallangan, o'zining bevosita obyekti yaratilmasligi kerak bo'lgan" klassni belgilaydi.

### `abc` moduli — Abstract Base Class

```python
from abc import ABC, abstractmethod

class Hayvon(ABC):              # ABC'dan meros oladi — bu klass ABSTRAKT
    @abstractmethod
    def ovoz_chiqar(self):       # bu metod HAR BIR avlod klassda MAJBURIY qayta yozilishi kerak
        pass                       # tanasi kerak emas — bu faqat "shablon"


hayvon = Hayvon()    # TypeError: Can't instantiate abstract class Hayvon with abstract method ovoz_chiqar
```

`ABC` (Abstract Base Class) — `abc` modulidagi maxsus klass, undan meros olish klassni "abstrakt" qiladi. `@abstractmethod` — belgilangan metodni **majburiy** qiladi: agar avlod klass uni qayta yozmasa, o'sha avlod klassning ham obyektini yaratib bo'lmaydi.

```python
class It(Hayvon):
    def ovoz_chiqar(self):     # MAJBURIY — bu yo'q bo'lsa, It ham abstrakt bo'lib qoladi
        print("Vov-vov!")


it1 = It()          # ishlaydi — chunki It ovoz_chiqar()ni amalga oshirgan
it1.ovoz_chiqar()    # Vov-vov!


class Mushuk(Hayvon):
    pass    # ovoz_chiqar() yozilmagan!

mushuk1 = Mushuk()   # TypeError: Can't instantiate abstract class Mushuk with abstract method ovoz_chiqar
```

### Abstrakt klass — bir nechta abstrakt metod bilan

```python
from abc import ABC, abstractmethod

class TolovUsuli(ABC):
    @abstractmethod
    def tolov_qil(self, summa):
        pass

    @abstractmethod
    def bekor_qil(self, tranzaksiya_id):
        pass

    def malumot(self):    # bu — ODDIY metod, abstrakt EMAS, avlodlar uni meros olishi mumkin (majburiy emas)
        return f"To'lov usuli: {type(self).__name__}"


class KartaTolov(TolovUsuli):
    def tolov_qil(self, summa):
        print(f"{summa} so'm kartadan yechildi")

    def bekor_qil(self, tranzaksiya_id):
        print(f"Tranzaksiya #{tranzaksiya_id} bekor qilindi")


karta = KartaTolov()
karta.tolov_qil(50000)
print(karta.malumot())    # To'lov usuli: KartaTolov — oddiy metod, meros orqali ishlaydi
```

Diqqat qiling: abstrakt klass ham **oddiy** metodlarga ega bo'lishi mumkin (`malumot()`) — faqat `@abstractmethod` bilan belgilanganlari majburiy, qolganlari oddiy meros kabi ishlaydi.

### Nega bu muhim — "interfeys shartnomasi" (contract)

Abstrakt klasslar — bir nechta dasturchi (yoki jamoa) katta loyihada ishlaganda **"shartnoma"** vazifasini bajaradi: agar kimdir yangi `TolovUsuli` avlodini qo'shmoqchi bo'lsa, Python ularga `tolov_qil` va `bekor_qil` metodlarini albatta yozishni **majburlaydi** — aks holda kod ishga tushmaydi (import vaqtida emas, balki obyekt yaratishga urinishda xato chiqadi). Bu — katta jamoaviy loyihalarda izchillikni ta'minlashning oddiy, lekin kuchli usuli.

### Abstrakt klass vs oddiy meros — qachon qaysi birini tanlash

| Holat | Yechim |
|---|---|
| Ota klassning o'zi hech qachon to'g'ridan-to'g'ri ishlatilmasligi kerak | Abstrakt klass (`ABC`) |
| Bola klasslar **albatta** ma'lum metodlarni amalga oshirishi shart | `@abstractmethod` |
| Ota klass ba'zan o'zi ham to'g'ridan-to'g'ri ishlatilishi mumkin | Oddiy klass (4.2-4.3-darslardagi kabi) |
| Faqat umumiy kodni ulashish kerak, majburiylik kerak emas | Oddiy meros |

### Duck typing vs Abstract Base Class — Python'ning ikki yondashuvi

4.3-darsda ko'rgan "duck typing" — hech qanday majburiy tekshiruvsiz, "agar metod mavjud bo'lsa, ishlataveramiz" tamoyiliga asoslanadi. `ABC` esa — bu erkinlikni **cheklab**, aniq shartnoma o'rnatadi. Ikkalasi ham Python'da to'g'ri va keng qo'llaniladi: kichik skriptlar va prototiplarda duck typing yetarli, katta va bir nechta dasturchi ishlaydigan loyihalarda esa `ABC` xatolarni **erta** (obyekt yaratishga urinishda) aniqlashga yordam beradi.

## Amaliy misol

Turli fayl formatlarini eksport qiluvchi tizim:

```python
# eksport_tizimi.py

from abc import ABC, abstractmethod
import json


class Eksportchi(ABC):
    @abstractmethod
    def eksport_qil(self, malumot):
        """Berilgan ma'lumotni tegishli formatga o'girib, satr sifatida qaytaradi."""
        pass

    def fayl_kengaytmasi(self):    # oddiy metod — standart holat, kerak bo'lsa override qilinadi
        return ".txt"


class JSONEksportchi(Eksportchi):
    def eksport_qil(self, malumot):
        return json.dumps(malumot, ensure_ascii=False, indent=2)

    def fayl_kengaytmasi(self):
        return ".json"


class CSVEksportchi(Eksportchi):
    def eksport_qil(self, malumot):
        # malumot - dict'lardan iborat ro'yxat deb faraz qilinadi
        if not malumot:
            return ""
        sarlavhalar = malumot[0].keys()
        qatorlar = [",".join(sarlavhalar)]
        for element in malumot:
            qatorlar.append(",".join(str(element[k]) for k in sarlavhalar))
        return "\n".join(qatorlar)

    def fayl_kengaytmasi(self):
        return ".csv"


mahsulotlar = [
    {"nom": "Noutbuk", "narx": 8500000},
    {"nom": "Sichqoncha", "narx": 150000},
]

eksportchilar = [JSONEksportchi(), CSVEksportchi()]

for eksportchi in eksportchilar:
    natija = eksportchi.eksport_qil(mahsulotlar)
    kengaytma = eksportchi.fayl_kengaytmasi()
    print(f"--- natija{kengaytma} ---")
    print(natija)
    print()
```

Bu misol — abstrakt klass va polimorfizmni birlashtiradi: `eksportchilar` ro'yxatidagi har bir obyekt **kafolatlangan holda** `eksport_qil()` metodiga ega (chunki `Eksportchi` buni majburlaydi), va sikl ularning aniq turini bilishi shart emas.

## Keng tarqalgan xatolar

**Xato 1:** `ABC`dan meros olishni unutish, faqat `@abstractmethod`ni ishlatish.
❌ 
```python
class Hayvon:    # ABC'dan meros olinmagan!
    @abstractmethod
    def ovoz_chiqar(self):
        pass

hayvon = Hayvon()   # bu ISHLAYDI! Xato bermaydi — @abstractmethod hech narsani majburlamaydi
```
✅ To'g'ri: `@abstractmethod` faqat `ABC`dan (yoki `ABCMeta` metaklassidan) meros olgan klasslarda ishlaydi: `class Hayvon(ABC):`.

**Xato 2:** barcha abstrakt metodlarni amalga oshirmasdan obyekt yaratishga urinish va xato sababini tushunmaslik.
❌ `TypeError: Can't instantiate abstract class ... with abstract method ...` xatosini ko'rib, "klassda xato bor" deb umumiy qidirish.
✅ To'g'ri: xato xabari **aniq qaysi metod** amalga oshirilmaganini ko'rsatadi — o'sha metodni avlod klassda yozing.

**Xato 3:** har bir kichik loyihada ham `ABC` ishlatishga harakat qilish (ortiqcha murakkablik).
❌ Ikki-uchta klassdan iborat kichik skriptda ham rasmiy `ABC` va `@abstractmethod` qurish — bu haddan tashqari "muhandislik" (over-engineering) bo'lishi mumkin.
✅ To'g'ri: `ABC`ni asosan **katta**, bir nechta dasturchi ishlaydigan yoki uzoq muddat qo'llab-quvvatlanadigan loyihalarda, aniq "bu interfeys albatta amalga oshirilishi kerak" degan holatlarda ishlating; kichik skriptlarda oddiy duck typing ko'pincha yetarli.

## Mashq/topshiriq

**(Oson)** `Shakl(ABC)` abstrakt klassini yarating — `yuza(self)` abstrakt metodi bilan, so'ng `Kvadrat(Shakl)` klassini yozib, `yuza()`ni amalga oshiring.

**(O'rtacha)** `Bildirishnoma(ABC)` abstrakt klassini yarating — `yubor(self, xabar)` abstrakt metodi bilan. Undan `EmailBildirishnoma` va `SMSBildirishnoma` klasslarini hosil qiling, har biri `yubor()`ni o'ziga xos (masalan, `print(f"Email: {xabar}")`) tarzda amalga oshirsin.

**(Qiyin)** `MalumotlarOmbori(ABC)` abstrakt klassini yarating — `saqlash(self, kalit, qiymat)` va `olish(self, kalit)` abstrakt metodlari bilan. `XotiraOmbori` (oddiy `dict` orqali xotirada saqlaydigan) va `FaylOmbori` (JSON faylga saqlaydigan, `json.dump`/`json.load` yordamida) klasslarini yozing. So'ng ikkalasini ham bir xil test funksiyasi orqali (obyekt turi muhim bo'lmagan holda) sinab ko'ring.

class MalumotlarOmbori(ABC):
    @abstractmethod
    def saqlash(self, kalit, qiymat):
        pass
    @abstractmethod
    def olish(self, kalit):
        pass

class XotiraOmbori(MalumotlarOmbori):
    def __init__(self):
        self._data = {}
    def saqlash(self, kalit, qiymat):
        self._data[kalit] = qiymat
    def olish(self, kalit):
        return self._data.get(kalit)

class FaylOmbori(MalumotlarOmbori):
    def __init__(self, fayl_nomi):

    def saqlash(self, kalit, qiymat):
        import json
        try:
            with open(self.fayl_nomi) as f:
                data = json.load(f)
        except FileNotFoundError:

        with open(self.fayl_nomi, "w") as f:
            json.dump(data, f)
    def olish(self, kalit):
        import json
        with open(self.fayl_nomi) as f:

## Qisqacha xulosa

Abstrakt klass (`ABC` + `@abstractmethod`) — "faqat meros olish uchun mo'ljallangan, bevosita obyekt yaratib bo'lmaydigan" klass yaratish va bola klasslarga ma'lum metodlarni amalga oshirishni **majburlash** imkonini beradi; bu — Python'ning erkinroq "duck typing" yondashuviga qarama-qarshi, balki uni to'ldiruvchi, katta va jamoaviy loyihalarda izchillikni ta'minlovchi qat'iyroq vosita — bu bilan 4-bobda o'rganilgan OOP'ning to'rtta ustuni (inkapsulyatsiya, meros, polimorfizm va abstraksiya) to'liq yakunlandi.
