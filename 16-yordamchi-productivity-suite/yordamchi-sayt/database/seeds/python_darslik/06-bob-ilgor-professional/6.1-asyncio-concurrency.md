# Asyncio va concurrency (threading/multiprocessing/GIL)

## Bu darsda nimalarni o'rganasiz

- GIL (Global Interpreter Lock) nima ekanini va u nimaga ta'sir qilishini tushunasiz
- `threading`, `multiprocessing` va `asyncio` orasidagi farqni va qachon qaysi birini tanlashni bilasiz
- `async`/`await` sintaksisi bilan asosiy asinxron kod yoza olasiz
- Python 3.13+ dagi "free-threaded" rejim haqida umumiy tushunchaga ega bo'lasiz

## Nazariy qism

### Nega concurrency (parallellik) kerak

Ba'zi vazifalar **kutish**ni talab qiladi (tarmoq so'rovi, fayl o'qish, ma'lumotlar bazasiga so'rov) — bu vaqtda protsessor bekor turadi. Boshqa vazifalar esa **haqiqiy hisoblash** talab qiladi (murakkab matematik amallar, rasm qayta ishlash). Python bu ikkala holat uchun turli vositalar taklif qiladi.

### GIL (Global Interpreter Lock) — Python'ning muhim cheklovi

**GIL** — CPython (Python'ning eng ko'p ishlatiladigan versiyasi) interpretatorining ichki mexanizmi bo'lib, **bir vaqtning o'zida faqat bitta thread (oqim) Python baytkodini bajarishi** mumkinligini ta'minlaydi — hatto kompyuteringizda 8 yoki 16 ta protsessor yadrosi bo'lsa ham. Bu — Python'ning eng ko'p muhokama qilinadigan cheklovlaridan biri.

```python
import threading
import time

def hisoblash():
    natija = sum(i * i for i in range(10_000_000))

# Ikkita thread — lekin GIL tufayli haqiqiy PARALLEL ishlamaydi (CPU-intensiv ish uchun)
boshlanish = time.time()
t1 = threading.Thread(target=hisoblash)
t2 = threading.Thread(target=hisoblash)
t1.start(); t2.start()
t1.join(); t2.join()
print(f"Ikkita thread: {time.time() - boshlanish:.2f} soniya")   # bitta thread'dan sezilarli tezroq EMAS
```

### `threading` — I/O-intensiv vazifalar uchun

GIL CPU-intensiv hisoblashlarga to'sqinlik qilsa-da, **I/O kutish** vaqtida (tarmoq, fayl, baza) GIL vaqtincha "bo'shatiladi" — shuning uchun `threading` aynan **I/O-intensiv** vazifalarda (bir nechta veb-saytdan bir vaqtda ma'lumot olish) juda samarali:

```python
import threading
import time

def sorov_yuborish(nom, kutish_vaqti):
    time.sleep(kutish_vaqti)    # tarmoq so'rovini simulyatsiya qiladi
    print(f"{nom} tugadi")

boshlanish = time.time()

threadlar = []
for i in range(5):
    t = threading.Thread(target=sorov_yuborish, args=(f"So'rov-{i}", 1))
    threadlar.append(t)
    t.start()

for t in threadlar:
    t.join()    # barcha threadlar tugashini kutish

print(f"Jami vaqt: {time.time() - boshlanish:.2f} soniya")   # ~1 soniya (5 emas!) — parallel kutish
```

### `multiprocessing` — CPU-intensiv vazifalar uchun

CPU-intensiv (haqiqiy hisoblash talab qiluvchi) vazifalar uchun `multiprocessing` ishlatiladi — u GIL cheklovini **aylanib o'tadi**, chunki har bir process (jarayon) o'zining **alohida** Python interpretatoriga (va shuning uchun alohida GIL'ga) ega:

```python
import multiprocessing
import time

def og_ir_hisoblash(n):
    return sum(i * i for i in range(n))

if __name__ == "__main__":     # multiprocessing uchun bu SHART!
    boshlanish = time.time()

    with multiprocessing.Pool(processes=4) as pool:
        natijalar = pool.map(og_ir_hisoblash, [10_000_000] * 4)

    print(f"4 ta jarayon: {time.time() - boshlanish:.2f} soniya")   # sezilarli tezroq (haqiqiy parallel)
```

> ⚠️ **`if __name__ == "__main__":` majburiy.** `multiprocessing` yangi Python jarayonlarini yaratganda asosiy faylni qayta import qiladi — agar bu tekshiruv bo'lmasa, cheksiz jarayon yaratish sikliga tushib qolish xavfi bor.

### Qaysi birini tanlash — amaliy qoida

| Vazifa turi | Vosita | Sabab |
|---|---|---|
| Tarmoq so'rovlari, fayl/baza kutish (I/O-intensiv) | `asyncio` (tavsiya etiladi) yoki `threading` | GIL I/O kutishda bo'shaydi |
| Matematik hisoblash, rasm/video qayta ishlash (CPU-intensiv) | `multiprocessing` | Har bir jarayon o'z GIL'iga ega |
| Bir nechta tarmoq so'rovini bitta jarayon ichida samarali boshqarish | `asyncio` | Eng yengil, eng ko'p miqyoslanadigan (scalable) yechim |

### `asyncio` — `async`/`await` bilan asinxron dasturlash

`asyncio` — bitta thread ichida, **event loop** yordamida ko'plab I/O-intensiv vazifalarni samarali boshqaradigan zamonaviy Python yondashuvi (Django+Aiogram darsligida ham keng ishlatilgan edi):

```python
import asyncio
import time

async def sorov_yuborish(nom, kutish_vaqti):
    print(f"{nom} boshlandi")
    await asyncio.sleep(kutish_vaqti)    # time.sleep() EMAS! asyncio.sleep() — boshqa vazifalarga "yo'l beradi"
    print(f"{nom} tugadi")


async def main():
    boshlanish = time.time()
    # barcha so'rovlarni PARALLEL (bir vaqtda) ishga tushirish
    await asyncio.gather(
        sorov_yuborish("So'rov-1", 1),
        sorov_yuborish("So'rov-2", 1),
        sorov_yuborish("So'rov-3", 1),
    )
    print(f"Jami vaqt: {time.time() - boshlanish:.2f} soniya")   # ~1 soniya, 3 emas!


asyncio.run(main())    # asinxron kodni ishga tushirishning standart usuli
```

`async def` — funksiyani **coroutine**ga aylantiradi (uni to'g'ridan-to'g'ri chaqirish o'rniga, `await` bilan yoki `asyncio.run()` orqali ishga tushirish kerak). `await` — "bu operatsiya tugashini kut, lekin shu paytda boshqa vazifalarga imkoniyat ber" degan ma'noni bildiradi.

### `asyncio.gather` — bir nechta vazifani parallel bajarish

```python
async def malumot_ol(id):
    await asyncio.sleep(0.5)    # API so'rovini simulyatsiya qiladi
    return f"Ma'lumot-{id}"


async def main():
    # ❌ SEKIN usul — ketma-ket bajarish:
    natija1 = await malumot_ol(1)
    natija2 = await malumot_ol(2)
    # jami ~1 soniya

    # ✅ TEZ usul — parallel bajarish:
    natijalar = await asyncio.gather(malumot_ol(1), malumot_ol(2))
    # jami ~0.5 soniya


asyncio.run(main())
```

### Python 3.13+ — "free-threaded" rejim haqida qisqacha

> 📌 **2025-2026 yangiliklari:** Python 3.13 va 3.14'da GIL'ni **butunlay o'chirib qo'yish** imkonini beruvchi eksperimental "free-threaded" (GIL'siz) rejim taqdim etildi (`python3.13t` maxsus build orqali). Bu rejim haqiqiy multi-core parallellikni `threading` orqali ham CPU-intensiv vazifalarda mumkin qiladi, lekin hali **eksperimental** hisoblanadi — ko'plab kutubxonalar hali to'liq moslashmagan. Bu kursda standart (GIL bilan) Python ishlatiladi, chunki u hozircha eng barqaror va keng qo'llab-quvvatlanadigan variant.

## Amaliy misol

Bir nechta "veb-sahifa"dan (simulyatsiya qilingan) ma'lumot olishni uchta usul bilan solishtirish:

```python
# concurrency_solishtirish.py
import asyncio
import time


async def sahifa_yukla(nom):
    await asyncio.sleep(1)     # tarmoq kechikishini simulyatsiya qiladi
    return f"{nom} yuklandi"


async def ketma_ket():
    boshlanish = time.time()
    for i in range(5):
        await sahifa_yukla(f"Sahifa-{i}")
    print(f"Ketma-ket: {time.time() - boshlanish:.2f} soniya")    # ~5 soniya


async def parallel():
    boshlanish = time.time()
    vazifalar = [sahifa_yukla(f"Sahifa-{i}") for i in range(5)]
    await asyncio.gather(*vazifalar)
    print(f"Parallel (asyncio): {time.time() - boshlanish:.2f} soniya")    # ~1 soniya


async def main():
    await ketma_ket()
    await parallel()


asyncio.run(main())
```

Bu misol — real loyihalarda (masalan, 5 ta turli API'dan bir vaqtning o'zida ma'lumot olish) `asyncio.gather()`ning nechog'lik katta tezlik farqini berishini aniq ko'rsatadi.

## Keng tarqalgan xatolar

**Xato 1:** `async def` ichida `time.sleep()` ishlatish (`asyncio.sleep()` o'rniga).
❌ 
```python
async def vazifa():
    time.sleep(1)    # bu BUTUN event loop'ni BLOKLAYDI, boshqa vazifalar kuta olmaydi!
```
✅ To'g'ri: asinxron kod ichida har doim `await asyncio.sleep(...)` (yoki boshqa asinxron-mos funksiyalarni, masalan `aiohttp`, `httpx.AsyncClient`) ishlating.

**Xato 2:** `await`ni unutish.
❌ `natija = malumot_ol(1)` — bu `natija`ga haqiqiy natija emas, **coroutine obyekt**ni saqlaydi (funksiya hali bajarilmagan!).
✅ To'g'ri: `natija = await malumot_ol(1)` — `await` coroutine'ni haqiqatan "kutib", natijasini oladi.

**Xato 3:** CPU-intensiv vazifa uchun `asyncio` yoki `threading`dan foydalanish, GIL cheklovini unutish.
❌ Og'ir matematik hisoblashni `asyncio.gather()` yoki bir nechta `threading.Thread` bilan "tezlashtirishga" urinish — natija deyarli o'zgarmaydi, chunki GIL CPU-intensiv ishni haqiqiy parallel qilishga yo'l qo'ymaydi.
✅ To'g'ri: CPU-intensiv vazifalar uchun `multiprocessing` ishlating — bu haqiqiy parallel hisoblashni ta'minlaydi.

## Mashq/topshiriq

**(Oson)** `asyncio.sleep(2)` bilan 2 soniya "kutuvchi" `async def kutish()` funksiyasini yozing va uni `asyncio.run()` orqali ishga tushiring, boshlanish va tugash vaqtini chiqaring.

**(O'rtacha)** Uchta `async def` funksiya yozing, har biri turli vaqt (`1`, `2`, `3` soniya) kutsin, so'ng `asyncio.gather()` orqali ularni parallel ishga tushiring va jami vaqt eng uzun kutish vaqtiga (3 soniyaga) yaqin bo'lishini tekshiring (9 soniya emas).

**(Qiyin)** `multiprocessing.Pool` yordamida `1` dan `4000000` gacha bo'lgan sonlar orasidan tub sonlarni 4 ta jarayonda parallel qidirishni amalga oshiring (ro'yxatni 4 qismga bo'lib, har biriga alohida jarayon ajratib), so'ng natijani bitta jarayonda (oddiy `for`) bajarilgan vaqt bilan solishtiring.

## Qisqacha xulosa

GIL — CPython'da bir vaqtda faqat bitta thread Python baytkodini bajarishini ta'minlaydigan cheklov bo'lib, u I/O-intensiv vazifalarda (`threading`, ayniqsa `asyncio`) muammo tug'dirmaydi, lekin CPU-intensiv vazifalarda haqiqiy parallellikka to'sqinlik qiladi (bu holatda `multiprocessing` kerak); `asyncio` (`async def`/`await`/`asyncio.gather()`) — bitta thread ichida ko'plab I/O operatsiyalarini samarali boshqarishning zamonaviy, eng ko'p tavsiya etiladigan usuli bo'lib, bu Django+Aiogram darsligida ko'rilgan `sync_to_async`/`async_to_sync` mexanizmlarining nazariy asosini tashkil qiladi; Python 3.13+dagi eksperimental "free-threaded" rejim esa kelajakda bu manzarani o'zgartirishi mumkin, lekin hozircha standart, GIL bilan ishlaydigan Python asosiy tanlov bo'lib qolmoqda.
