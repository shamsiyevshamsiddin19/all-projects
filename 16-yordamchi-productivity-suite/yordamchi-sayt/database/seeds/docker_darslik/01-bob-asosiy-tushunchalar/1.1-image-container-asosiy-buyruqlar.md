# Image va Container asoslari, asosiy buyruqlar

## Bu darsda nimalarni o'rganasiz

- `docker run` yordamida konteyner ishga tushira olasiz va uning parametrlarini tushunasiz
- `docker ps`, `docker stop`, `docker rm` orqali konteynerlarni boshqara olasiz
- Konteynerning "hayot sikli" (lifecycle) qanday ishlashini tushunasiz
- Port va nom berish (naming) mexanizmlarini qo'llay olasiz

## Nazariy qism

### `docker run` — konteyner ishga tushirishning asosiy buyrug'i

```bash
docker run <image_nomi>
```

Bu buyruq — 0.1-darsda ko'rganimizdek, agar image mahalliy mavjud bo'lmasa, uni avtomatik yuklaydi va konteyner yaratib ishga tushiradi. Amalda ko'proq parametrlar bilan ishlatiladi:

```bash
docker run -d --name mening_nginx -p 8080:80 nginx
```

| Bayroq | Ma'nosi |
|---|---|
| `-d` | **Detached** rejim — konteyner fon jarayoni sifatida ishga tushadi, terminal band bo'lmaydi |
| `--name <nom>` | Konteynerga o'qilishi oson nom berish (aks holda Docker tasodifiy nom — `happy_einstein` kabi — beradi) |
| `-p <host_port>:<konteyner_port>` | Host (kompyuteringiz) portini konteyner ichidagi portga "bog'lash" (port mapping) |
| `-e <O'ZGARUVCHI>=<qiymat>` | Konteyner ichiga muhit o'zgaruvchisi (environment variable) uzatish |
| `-v <host_yol>:<konteyner_yol>` | Volume yoki bind mount — fayllarni host va konteyner orasida ulashish (3-bobda batafsil) |
| `--rm` | Konteyner to'xtagach, uni **avtomatik o'chirish** (test uchun juda qulay) |
| `-it` | Interaktiv rejim (`-i`) + terminal (`-t`) — konteyner ichiga "kirib" ishlash uchun |

### Port mapping — nega kerak

```bash
docker run -d --name veb_server -p 8080:80 nginx
```

`nginx` konteyneri ichida veb-server **80-portda** ishlaydi (bu — konteyner ichidagi, izolyatsiya qilingan port, tashqi dunyo uni ko'rmaydi). `-p 8080:80` — host kompyuteringizning **8080-portini** konteynerning 80-portiga "bog'laydi", shunda brauzerda `http://localhost:8080` manzilini ochsangiz, so'rov konteyner ichidagi Nginx'ga yo'naltiriladi.

```
Host kompyuter (localhost:8080)  --->  Docker konteyner (ichkarida :80 da Nginx)
```

### Konteynerlar ro'yxatini ko'rish — `docker ps`

```bash
docker ps            # faqat ISHLAYOTGAN konteynerlar
docker ps -a          # BARCHA konteynerlar (to'xtatilganlar ham)
```

Natija namunasi:

```
CONTAINER ID   IMAGE   COMMAND                  STATUS         PORTS                  NAMES
a1b2c3d4e5f6   nginx   "/docker-entrypoint.…"   Up 2 minutes   0.0.0.0:8080->80/tcp   mening_nginx
```

| Ustun | Ma'nosi |
|---|---|
| `CONTAINER ID` | Har bir konteynerning noyob identifikatori (qisqartirilgan) |
| `IMAGE` | Qaysi image asosida yaratilgani |
| `STATUS` | Holati (`Up` — ishlayapti, `Exited` — to'xtagan) |
| `PORTS` | Qaysi portlar bog'langani |
| `NAMES` | Konteyner nomi |

### Konteynerni to'xtatish, qayta ishga tushirish va o'chirish

```bash
docker stop mening_nginx      # konteynerni "yumshoq" to'xtatadi (SIGTERM signali bilan)
docker start mening_nginx      # to'xtatilgan konteynerni QAYTA ishga tushiradi
docker restart mening_nginx     # to'xtatib, darhol qayta ishga tushiradi

docker rm mening_nginx           # TO'XTATILGAN konteynerni butunlay O'CHIRADI
docker rm -f mening_nginx         # ishlayotgan konteynerni MAJBURAN to'xtatib, o'chiradi
```

> ⚠️ **`docker stop` va `docker rm` orasidagi farqni tushunish muhim.** `stop` — konteynerni **to'xtatadi**, lekin u hali mavjud (`docker ps -a`da ko'rinadi), uni `docker start` bilan qayta ishga tushirish mumkin. `rm` — konteynerni **butunlay o'chiradi** (fayl tizimidan ham), uni qayta tiklab bo'lmaydi — agar konteyner ichida saqlangan ma'lumot (masalan, baza) volume'ga yozilmagan bo'lsa, u **butunlay yo'qoladi** (3-bobda bu muammoning yechimini — volume'larni ko'ramiz).

### Konteynerning hayot sikli (lifecycle)

```
docker run  →  [ISHLAMOQDA]  →  docker stop  →  [TO'XTATILGAN]  →  docker start  →  [ISHLAMOQDA]
                                        │
                                        └──  docker rm  →  [O'CHIRILGAN, MAVJUD EMAS]
```

### `--rm` bayrog'i — vaqtinchalik konteynerlar uchun

Test yoki bir martalik vazifalar uchun konteyner ishlatilib bo'lgach, uni qo'lda `docker rm` bilan o'chirish o'rniga, `--rm` bayrog'i bilan ishga tushirish qulay — konteyner to'xtagach **avtomatik** o'chadi:

```bash
docker run --rm -it ubuntu bash
# konteyner ichida ishlab bo'lgach, 'exit' yozganingizda konteyner avtomatik o'chib ketadi
```

### Interaktiv rejim — `-it` va konteyner ichiga kirish

```bash
docker run -it ubuntu bash
```

Bu buyruq — `ubuntu` image'i asosida konteyner yaratadi, va uning ichida **interaktiv terminal** (`bash`) ochadi — siz xuddi alohida, kichik Linux kompyuterga "kirgandek" buyruqlar yoza olasiz:

```bash
root@a1b2c3d4e5f6:/# ls
root@a1b2c3d4e5f6:/# apt update && apt install curl -y
root@a1b2c3d4e5f6:/# exit    # konteynerdan chiqish (agar --rm bo'lsa, konteyner shu yerda o'chadi)
```

Bu — Docker'ni birinchi marta o'rganayotganda "konteyner ichida nima bor" ekanini his qilishning eng yaxshi usuli.

### Konteyner ichida buyruq bajarish — `docker exec`

Agar konteyner allaqachon fon rejimida (`-d`) ishlayotgan bo'lsa-yu, unga "kirish" kerak bo'lsa:

```bash
docker exec -it mening_nginx bash    # ishlayotgan konteyner ICHIGA kirish
docker exec mening_nginx ls /etc/nginx    # konteyner ichida BITTA buyruq bajarish (kirmasdan)
```

`docker exec` — `docker run`dan farqli o'laroq, **yangi** konteyner yaratmaydi, balki **allaqachon ishlayotgan** konteyner ichida qo'shimcha jarayon (masalan, terminal sessiya) ochadi.

## Amaliy misol

To'liq ish tsikli — Nginx veb-serverini ishga tushirish, tekshirish va boshqarish:

```bash
# 1. Nginx konteynerini fon rejimida, nom va port bilan ishga tushirish
docker run -d --name mening_veb_server -p 8080:80 nginx

# 2. Ishlayotganini tekshirish
docker ps

# 3. Brauzerda http://localhost:8080 ni ochish (yoki terminaldan tekshirish)
curl http://localhost:8080

# 4. Konteyner ichidagi Nginx konfiguratsiya faylini ko'rish
docker exec mening_veb_server cat /etc/nginx/nginx.conf

# 5. Konteyner loglarini ko'rish (Nginx'ga kelgan so'rovlar)
docker logs mening_veb_server

# 6. Konteynerni to'xtatish
docker stop mening_veb_server

# 7. Endi to'xtatilgan holda ham ro'yxatda ko'rinadi
docker ps -a

# 8. Qayta ishga tushirish
docker start mening_veb_server

# 9. Butunlay tozalash — to'xtatib, o'chirish
docker stop mening_veb_server
docker rm mening_veb_server
```

## Keng tarqalgan xatolar

**Xato 1:** bir xil nom bilan ikkinchi konteyner ishga tushirishga urinish.
❌ `docker run --name mening_nginx nginx` — agar `mening_nginx` nomli konteyner (hatto to'xtatilgan holda ham) allaqachon mavjud bo'lsa, `Conflict. The container name "/mening_nginx" is already in use` xatosi chiqadi.
✅ To'g'ri: avval eski konteynerni o'chiring (`docker rm mening_nginx`) yoki yangisiga boshqa nom bering.

**Xato 2:** portni allaqachon band bo'lgan holda ishlatishga urinish.
❌ `docker run -p 8080:80 nginx` — agar 8080-port kompyuteringizda boshqa dastur (yoki boshqa konteyner) tomonidan allaqachon band bo'lsa, `Bind for 0.0.0.0:8080 failed: port is already allocated` xatosi chiqadi.
✅ To'g'ri: boshqa, bo'sh portni tanlang (`-p 8081:80`) yoki band qilgan konteynerni to'xtating (`docker ps` bilan aniqlab, `docker stop`).

**Xato 3:** `docker rm`ni ishlayotgan konteynerga `-f` bayrog'isiz qo'llashga urinish.
❌ `docker rm mening_nginx` — agar konteyner hali **ishlayotgan** bo'lsa, `Error response from daemon: You cannot remove a running container` xatosi beradi.
✅ To'g'ri: avval `docker stop mening_nginx`, so'ng `docker rm mening_nginx` (yoki bitta qadamda `docker rm -f mening_nginx`).

## Mashq/topshiriq

**(Oson)** `nginx` image'ini `mening_sayt` nomi bilan, 9000-portda (host) ishga tushiring, `docker ps` bilan tekshiring, so'ng to'xtatib o'chiring.

**(O'rtacha)** `docker run -it --rm ubuntu bash` orqali Ubuntu konteyneriga kiring, ichida `cat /etc/os-release` buyrug'i bilan qaysi Ubuntu versiyasi ekanini tekshiring, so'ng `exit` bilan chiqib, konteyner avtomatik o'chganini `docker ps -a` orqali tasdiqlang.

**(Qiyin)** Ikkita alohida Nginx konteynerini (`sayt1` va `sayt2` nomlari bilan) turli portlarda (masalan, 8081 va 8082) bir vaqtda ishga tushiring, `docker ps` orqali ikkalasi ham ishlayotganini tasdiqlang, so'ng `docker exec` orqali har birining ichidagi `/usr/share/nginx/html/index.html` fayli mazmunini ko'ring va ular bir xil ekanini tushuntirib bering (chunki bir xil image'dan yaratilgan).

<details>
<summary>Javoblarni ko'rish</summary>

1. `docker run -d --name mening_sayt -p 9000:80 nginx`, `docker ps`, `docker stop mening_sayt`, `docker rm mening_sayt`.
2. `docker run -it --rm ubuntu bash`, ichida `cat /etc/os-release`, `exit`, so'ng `docker ps -a` — konteyner ro'yxatda **ko'rinmaydi**, chunki `--rm` uni avtomatik o'chirgan.
3. `docker run -d --name sayt1 -p 8081:80 nginx` va `docker run -d --name sayt2 -p 8082:80 nginx`; `docker exec sayt1 cat /usr/share/nginx/html/index.html` va `docker exec sayt2 cat /usr/share/nginx/html/index.html` — ikkalasi bir xil standart Nginx "Welcome" sahifasini ko'rsatadi, chunki ikkalasi ham **bir xil** `nginx` image'idan (o'zgarmas andozadan) yaratilgan, faqat ular — bu image'ning ikkita mustaqil, izolyatsiya qilingan namunasi (instance).

## Qisqacha xulosa

`docker run` — image asosida yangi konteyner yaratib ishga tushiradi (`-d` fon rejimi, `-p` port bog'lash, `--name` nom berish, `--rm` avtomatik o'chirish uchun); `docker ps`/`docker ps -a` — konteynerlar holatini ko'rsatadi, `docker stop`/`docker start`/`docker restart` — konteynerning ishlash holatini boshqaradi, `docker rm` esa uni butunlay o'chiradi (faqat to'xtatilgan konteynerlar uchun, yoki `-f` bilan majburan); `docker exec` — allaqachon ishlayotgan konteyner ichida qo'shimcha buyruq yoki interaktiv sessiya ochadi — bu buyruqlar to'plami Docker bilan kundalik ishlashning asosini tashkil qiladi.
