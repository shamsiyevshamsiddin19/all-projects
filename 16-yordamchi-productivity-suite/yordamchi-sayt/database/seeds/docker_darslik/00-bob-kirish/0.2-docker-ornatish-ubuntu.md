# Docker Engine'ni Ubuntu'ga o'rnatish

## Bu darsda nimalarni o'rganasiz

- Docker Engine'ni Ubuntu'ga rasmiy usulda, `apt` repozitoriyasi orqali o'rnata olasiz
- `sudo` siz (root huquqisiz) `docker` buyrug'ini ishlatish uchun foydalanuvchini sozlay olasiz
- O'rnatishni tekshirish va Docker xizmatini (service) boshqarishni bilasiz
- Docker Desktop va Docker Engine orasidagi farqni tushuntira olasiz

## Nazariy qism

### Docker Engine vs Docker Desktop

| Variant | Qachon ishlatiladi |
|---|---|
| **Docker Engine** | Linux serverlarda (Ubuntu kabi) — faqat buyruq qatori (CLI), grafik interfeyssiz, eng yengil va tezkor |
| **Docker Desktop** | Windows/macOS'da — grafik interfeys bilan, ichida virtual mashina orqali Linux muhitini simulyatsiya qiladi |

Ubuntu serverida (yoki Ubuntu ishchi kompyuterida) biz to'g'ridan-to'g'ri **Docker Engine**ni o'rnatamiz — bu eng tejamkor va production serverlarida ishlatiladigan standart usul (Docker Desktop asosan Windows/macOS foydalanuvchilari uchun mo'ljallangan, Linux'da unga ehtiyoj yo'q, chunki Linux yadrosi konteynerlarni to'g'ridan-to'g'ri qo'llab-quvvatlaydi).

### O'rnatish usullari — nega rasmiy `apt` repozitoriyasi tavsiya etiladi

Docker'ni Ubuntu'ga bir necha usulda o'rnatish mumkin: Ubuntu'ning o'z standart repozitoriyasidan (`sudo apt install docker.io`), `snap` orqali, yoki Docker'ning **rasmiy** `apt` repozitoriyasidan. Ushbu kursda **rasmiy repozitoriya** usuli tanlangan, chunki u har doim eng so'nggi barqaror Docker versiyasini beradi (Ubuntu'ning standart repozitoriyasi ko'pincha eskiroq versiyani taqdim etadi).

### 1-qadam: eski versiyalarni olib tashlash (agar mavjud bo'lsa)

```bash
sudo apt remove docker docker-engine docker.io containerd runc
```

Bu buyruq xato bersa ham (agar bu paketlar o'rnatilmagan bo'lsa) — bu normal holat, xavotir olmang.

### 2-qadam: kerakli paketlarni o'rnatish va Docker'ning rasmiy GPG kalitini qo'shish

```bash
sudo apt update
sudo apt install ca-certificates curl -y

sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

GPG kalit — Docker'ning rasmiy paketlari haqiqiy va o'zgartirilmaganligini tasdiqlash uchun kerak (xavfsizlik maqsadida — bu tizimga faqat ishonchli manbadan kelgan dasturiy ta'minot o'rnatilishini kafolatlaydi).

### 3-qadam: Docker'ning rasmiy repozitoriyasini qo'shish

```bash
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
```

Bu buyruq — tizimingiz arxitekturasini (`amd64`, `arm64` va h.k.) va Ubuntu versiyasi kod nomini (masalan, `noble` — 24.04 uchun) **avtomatik aniqlab**, mos repozitoriya manzilini qo'shadi.

### 4-qadam: Docker Engine'ni o'rnatish

```bash
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin -y
```

| Paket | Vazifasi |
|---|---|
| `docker-ce` | Docker Engine'ning o'zi (server, "Community Edition") |
| `docker-ce-cli` | Buyruq qatori interfeysi (`docker` buyrug'i) |
| `containerd.io` | Konteynerlarni past darajada boshqaruvchi runtime |
| `docker-buildx-plugin` | Zamonaviy, kengaytirilgan image qurish vositasi (`docker build` ichida ishlatiladi) |
| `docker-compose-plugin` | `docker compose` buyrug'i (4-bobda batafsil — **standalone `docker-compose` emas**, zamonaviy `docker compose` plagin ko'rinishida) |

> 📌 **Muhim: `docker-compose` va `docker compose` farqi.** Eski qo'llanmalarda ko'pincha alohida `docker-compose` (chiziqcha bilan, alohida dastur) ko'rasiz. 2023-yildan boshlab Docker rasmiy ravishda `docker compose` (bo'sh joy bilan, `docker`ning **plagini**) ni standart va tavsiya etiladigan usul deb e'lon qildi. Ushbu kursda faqat zamonaviy `docker compose` (bo'sh joy bilan) sintaksisi ishlatiladi.

### 5-qadam: o'rnatishni tekshirish

```bash
sudo docker run hello-world
```

Agar tabriknoma matni (0.1-darsda ko'rgan) chiqsa — o'rnatish muvaffaqiyatli yakunlangan.

### 6-qadam: `sudo`siz `docker` buyrug'ini ishlatish

Standart holda `docker` buyrug'ini faqat `root` (yoki `sudo` orqali) ishlatish mumkin, chunki Docker daemon `root` huquqlari bilan ishlaydi. Har safar `sudo docker ...` yozish noqulay, shuning uchun joriy foydalanuvchini `docker` guruhiga qo'shamiz:

```bash
sudo usermod -aG docker $USER
newgrp docker    # yangi guruh sozlamasini joriy terminal sessiyasiga qo'llash
```

> ⚠️ **Muhim: xavfsizlik ogohlantirishi.** `docker` guruhiga qo'shilgan foydalanuvchi aslida **root bilan bir xil** huquvlarga ega bo'ladi (chunki Docker konteynerlar orqali tizimga to'liq kirish imkoniyatini beradi). Bu — development (shaxsiy/o'quv) muhitida odatiy va qulay, lekin **ishonchsiz** foydalanuvchilarga production serverida `docker` guruhini berish xavfsizlik xatarini tug'diradi.

Sozlamani to'liq qo'llash uchun terminalni qayta ishga tushirish (yoki tizimdan chiqib qayta kirish) tavsiya etiladi. Tekshirish:

```bash
docker run hello-world    # endi sudo SHART EMAS
```

### Docker xizmatini (service) boshqarish

Docker — Ubuntu'da **systemd** xizmati sifatida ishlaydi (avtomatik ishga tushiriladi), lekin uni qo'lda boshqarish kerak bo'lishi mumkin:

```bash
sudo systemctl status docker     # xizmat holatini ko'rish (active/inactive)
sudo systemctl start docker       # xizmatni ishga tushirish
sudo systemctl stop docker         # xizmatni to'xtatish
sudo systemctl restart docker      # qayta ishga tushirish
sudo systemctl enable docker        # tizim yuklanganda avtomatik ishga tushishini yoqish (standart holda allaqachon yoqilgan)
```

### O'rnatilgan versiyani tekshirish

```bash
docker --version                 # Docker Client versiyasi
docker compose version            # Docker Compose plagin versiyasi
docker info                        # Docker Engine haqida to'liq, batafsil ma'lumot
```

## Amaliy misol

To'liq o'rnatish jarayoni — boshidan oxirigacha, bitta ketma-ketlikda:

```bash
# 1. Eski versiyalarni olib tashlash (xavfsiz, xato bersa ham davom eting)
sudo apt remove docker docker-engine docker.io containerd runc

# 2. Kerakli vositalar va GPG kalit
sudo apt update
sudo apt install ca-certificates curl -y
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# 3. Repozitoriyani qo'shish
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update

# 4. O'rnatish
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin -y

# 5. sudo'siz ishlatish uchun sozlash
sudo usermod -aG docker $USER
newgrp docker

# 6. Tekshirish
docker run hello-world
docker --version
docker compose version
```

Agar barcha qadamlar xatosiz o'tsa, terminalda `docker --version` — masalan `Docker version 27.x.x` kabi natija, `docker compose version` esa `Docker Compose version v2.x.x` kabi natija chiqarishi kerak.

## Keng tarqalgan xatolar

**Xato 1:** `docker` guruhiga qo'shilgandan keyin terminalni qayta ishga tushirmasdan, hamon `permission denied` xatosiga duch kelish.
❌ `usermod -aG docker $USER` bajarilgach, darhol `docker ps` chaqirilsa, `permission denied while trying to connect to the Docker daemon socket` xatosi chiqishi mumkin.
✅ To'g'ri: `newgrp docker` buyrug'ini ishlating yoki terminal oynasini butunlay yopib, qayta oching (yoki tizimdan chiqib qayta kiring) — guruh o'zgarishi joriy sessiyaga darhol ta'sir qilmaydi.

**Xato 2:** Ubuntu'ning standart (eski) `docker.io` paketini o'rnatib, keyin rasmiy repozitoriyadan yana o'rnatishga urinib, ziddiyatlarga duch kelish.
❌ Ikkala manbadan (Ubuntu standart va Docker rasmiy) bir vaqtda o'rnatilgan Docker paketlari versiya ziddiyatlariga yoki g'alati xatolarga olib kelishi mumkin.
✅ To'g'ri: 1-qadamda ko'rsatilganidek, avval eski/standart paketlarni **butunlay olib tashlang**, so'ng faqat rasmiy repozitoriyadan o'rnating.

**Xato 3:** eski `docker-compose` (chiziqcha bilan) buyrug'ini qidirib, "topilmadi" xatosiga duch kelish.
❌ `docker-compose up` — agar faqat `docker-compose-plugin` o'rnatilgan bo'lsa (standalone `docker-compose` emas), bu buyruq `command not found` xatosini berishi mumkin.
✅ To'g'ri: zamonaviy usul — bo'sh joy bilan yoziladigan `docker compose up` (plagin sifatida, chiziqchasiz). Ushbu kursning barcha keyingi darslarida faqat shu zamonaviy sintaksis ishlatiladi.

## Mashq/topshiriq

**(Oson)** O'z Ubuntu tizimingizda (yoki mos muhitda) yuqoridagi to'liq o'rnatish ketma-ketligini bajaring va `docker run hello-world` orqali muvaffaqiyatli natija olganingizni tasdiqlang.

**(O'rtacha)** `docker info` buyrug'ini ishga tushiring va natijadan quyidagi uchta ma'lumotni toping: Docker Engine versiyasi, nechta konteyner ishlayotgani (`Running Containers`), va tizimingizdagi umumiy xotira hajmi (`Total Memory`).

**(Qiyin)** `sudo systemctl stop docker` orqali Docker xizmatini to'xtating, so'ng `docker ps` buyrug'ini ishga tushirishga urinib ko'ring va chiqqan xato xabarini o'qing — bu xabar nima haqida ekanini tushuntirib bering, so'ng `sudo systemctl start docker` bilan xizmatni qayta ishga tushirib, muammoni bartaraf eting.

<details>
<summary>Javoblarni ko'rish</summary>

1. Muvaffaqiyatli o'rnatilgan holda, `docker run hello-world` "Hello from Docker!" xabarini chiqarishi kerak.
2. `docker info` natijasida `Server Version:` qatori — Docker Engine versiyasini, `Containers:` (yoki `Running:`) qatori — ishlayotgan konteynerlar sonini, `Total Memory:` qatori — umumiy xotira hajmini ko'rsatadi.
3. Docker xizmati to'xtatilgandan so'ng, `docker ps` — `Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?` kabi xato beradi — bu Docker Engine (daemon, fon jarayoni) ishlamayotganini, va u bilan bog'lanib bo'lmayotganini bildiradi; `sudo systemctl start docker` uni qayta ishga tushiradi va muammo hal bo'ladi.

</details>

## Qisqacha xulosa

Docker Engine Ubuntu'ga rasmiy `apt` repozitoriyasi orqali (GPG kalit, repozitoriya qo'shish, `apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`) o'rnatiladi — bu usul Docker'ning eng so'nggi barqaror versiyasini kafolatlaydi; o'rnatishdan so'ng joriy foydalanuvchini `docker` guruhiga qo'shish (`usermod -aG docker $USER`) har safar `sudo` yozishdan qutqaradi, ammo bu amaliy huquqlarni kengaytirishi sababli faqat ishonchli development muhitida qilinishi kerak; zamonaviy Docker Compose endi alohida `docker-compose` emas, balki `docker compose` (bo'sh joy bilan) plagin ko'rinishida ishlatiladi — bu butun kurs davomida standart bo'lib qoladi.
