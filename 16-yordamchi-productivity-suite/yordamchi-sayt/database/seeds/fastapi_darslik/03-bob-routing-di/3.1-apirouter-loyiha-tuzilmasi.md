# APIRouter bilan loyihani tashkil etish

## Bu darsda nimalarni o'rganasiz

- Nima uchun katta loyihada barcha kodni bitta faylda saqlash muammoli ekanini tushunasiz
- `APIRouter` orqali endpoint'larni alohida modullarga bo'lishni o'rganasiz
- Real, ko'p fayldan iborat FastAPI loyiha tuzilmasini yaratasiz
- `prefix` va `tags` orqali router'larni tashkil etishni bilasiz

## Nazariy qism

### Nima uchun bitta `main.py` yetarli emas

Oldingi darslarda barcha endpoint'lar bitta `main.py` faylida yozilgan edi. Kichik loyihalar uchun bu qulay, lekin loyiha o'sishi bilan (10, 50, 100 ta endpoint), bitta fayl:

- **Navigatsiya qilish qiyinlashadi** — kerakli endpoint'ni topish uchun uzoq faylni skroll qilish kerak bo'ladi
- **Jamoaviy ishlashda konflikt ko'payadi** — bir nechta dasturchi bitta faylni tahrirlaganda, Git konfliktlari (Git darsligining 2.2-darsida ko'rilgan) tez-tez yuzaga keladi
- **Mantiqiy guruhlash yo'qoladi** — foydalanuvchilar, mahsulotlar, buyurtmalar bilan bog'liq kod bir-biriga aralashib ketadi

### `APIRouter` — yechim

**`APIRouter`** — `FastAPI` obyektining "kichik nusxasi" bo'lib, endpoint'larni alohida fayllarda guruhlash, so'ng ularni asosiy ilovaga **ulash** imkonini beradi.

```python
# routers/mahsulotlar.py
from fastapi import APIRouter

router = APIRouter()

@router.get("/mahsulotlar")
def mahsulotlar_royxati():
    return {"mahsulotlar": []}

@router.post("/mahsulotlar")
def mahsulot_yaratish():
    return {"xabar": "Yaratildi"}
```

```python
# main.py
from fastapi import FastAPI
from routers import mahsulotlar

app = FastAPI()
app.include_router(mahsulotlar.router)
```

`app.include_router()` — router ichidagi barcha endpoint'larni, asosiy `app` obyektiga "qo'shadi", xuddi ular to'g'ridan-to'g'ri `main.py`da yozilgandek ishlaydi.

### Tavsiya etiladigan loyiha tuzilmasi

```
mening-fastapi-loyiham/
├── pyproject.toml
├── uv.lock
├── .gitignore
└── app/
    ├── __init__.py
    ├── main.py                 # FastAPI obyekti, router'larni ulash
    ├── routers/
    │   ├── __init__.py
    │   ├── foydalanuvchilar.py
    │   ├── mahsulotlar.py
    │   └── buyurtmalar.py
    ├── models/
    │   ├── __init__.py
    │   └── mahsulot.py         # Pydantic modellari
    └── dependencies.py          # umumiy Dependency'lar (3.2-darsda)
```

> 📌 **Bu tuzilma — yagona "to'g'ri" yechim emas:** loyiha hajmiga qarab, tuzilma soddaroq yoki murakkabroq bo'lishi mumkin (masalan, katta loyihalarda, har bir modul — `foydalanuvchilar/`, `mahsulotlar/` — o'zining ichida `router.py`, `models.py`, `service.py` fayllariga ega bo'lishi mumkin). Yuqoridagi — o'rta hajmdagi loyihalar uchun keng tarqalgan, boshlang'ich nuqta sifatida yaxshi tuzilma.

### `prefix` — takrorlanuvchi URL qismini olib tashlash

Agar bir router ichidagi barcha endpoint'lar bir xil boshlang'ich yo'lga (masalan, `/mahsulotlar`) ega bo'lsa, uni har bir endpoint'da qayta-qayta yozish o'rniga, `prefix` orqali bir marta belgilash mumkin:

```python
# routers/mahsulotlar.py
from fastapi import APIRouter

router = APIRouter(prefix="/mahsulotlar", tags=["Mahsulotlar"])

@router.get("/")           # haqiqiy yo'l: /mahsulotlar/
def royxat():
    return {"mahsulotlar": []}

@router.get("/{mahsulot_id}")   # haqiqiy yo'l: /mahsulotlar/{mahsulot_id}
def bitta_mahsulot(mahsulot_id: int):
    return {"id": mahsulot_id}

@router.post("/")          # haqiqiy yo'l: /mahsulotlar/
def yaratish():
    return {"xabar": "Yaratildi"}
```

### `tags` — hujjatlarni guruhlash

`tags` parametri — funksionallikka ta'sir qilmaydi, lekin `/docs` sahifasida (1.1-darsda ko'rilgan Swagger UI), endpoint'larni **mantiqiy guruhlarga** ajratib ko'rsatadi:

```
/docs sahifasida ko'rinishi:

▼ Foydalanuvchilar
    GET  /foydalanuvchilar
    POST /foydalanuvchilar

▼ Mahsulotlar
    GET  /mahsulotlar
    POST /mahsulotlar
```

Bu — API kattalashgan sari, hujjat sahifasini navigatsiya qilishni sezilarli osonlashtiradi.

### Bir nechta router'ni `main.py`da ulash

```python
# main.py
from fastapi import FastAPI
from routers import foydalanuvchilar, mahsulotlar, buyurtmalar

app = FastAPI(title="Mening do'konim API")

app.include_router(foydalanuvchilar.router)
app.include_router(mahsulotlar.router)
app.include_router(buyurtmalar.router)

@app.get("/")
def salomlashish():
    return {"xabar": "API'ga xush kelibsiz"}
```

### Ichma-ich router'lar (nested routers)

Katta loyihalarda, router'larning o'zi ham boshqa router'larni o'z ichiga olishi mumkin — masalan, versiyalash uchun:

```python
# main.py
from fastapi import APIRouter, FastAPI
from routers import mahsulotlar, foydalanuvchilar

app = FastAPI()

v1_router = APIRouter(prefix="/api/v1")
v1_router.include_router(mahsulotlar.router)
v1_router.include_router(foydalanuvchilar.router)

app.include_router(v1_router)
```

Bu — barcha endpoint'larni `/api/v1/mahsulotlar`, `/api/v1/foydalanuvchilar` ko'rinishida, API versiyalash konvensiyasiga mos qiladi.

### Umumiy `dependencies` va `responses` parametrlari

`APIRouter()` — butun router uchun umumiy sozlamalarni ham qabul qilishi mumkin (masalan, barcha endpoint'lar uchun bir xil autentifikatsiya talabi — bu, 3.2-darsda Dependency Injection o'rganilgandan keyin to'liq tushunarli bo'ladi):

```python
router = APIRouter(
    prefix="/admin",
    tags=["Admin"],
    responses={404: {"description": "Topilmadi"}},
)
```

## Amaliy misol

To'liq, ko'p fayldan iborat kichik loyiha — kutubxona boshqaruvi:

```python
# app/models/kitob.py
from pydantic import BaseModel, Field

class KitobYaratish(BaseModel):
    nomi: str = Field(min_length=1, max_length=200)
    muallif: str
    yil: int = Field(ge=1450, le=2026)

class KitobJavob(BaseModel):
    id: int
    nomi: str
    muallif: str
    yil: int
```

```python
# app/routers/kitoblar.py
from fastapi import APIRouter, HTTPException, status
from app.models.kitob import KitobYaratish, KitobJavob

router = APIRouter(prefix="/kitoblar", tags=["Kitoblar"])

BAZA: dict[int, dict] = {}
KEYINGI_ID = 1

@router.get("/", response_model=list[KitobJavob])
def royxat():
    return list(BAZA.values())

@router.get("/{kitob_id}", response_model=KitobJavob)
def bitta_kitob(kitob_id: int):
    if kitob_id not in BAZA:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Kitob topilmadi")
    return BAZA[kitob_id]

@router.post("/", response_model=KitobJavob, status_code=status.HTTP_201_CREATED)
def yaratish(kitob: KitobYaratish):
    global KEYINGI_ID
    yangi = {"id": KEYINGI_ID, **kitob.model_dump()}
    BAZA[KEYINGI_ID] = yangi
    KEYINGI_ID += 1
    return yangi
```

```python
# app/routers/mualliflar.py
from fastapi import APIRouter

router = APIRouter(prefix="/mualliflar", tags=["Mualliflar"])

@router.get("/")
def royxat():
    return {"mualliflar": ["Abdulla Qodiriy", "Cho'lpon"]}
```

```python
# app/main.py
from fastapi import FastAPI
from app.routers import kitoblar, mualliflar

app = FastAPI(title="Kutubxona API")

app.include_router(kitoblar.router)
app.include_router(mualliflar.router)

@app.get("/")
def bosh_sahifa():
    return {"xabar": "Kutubxona API'siga xush kelibsiz"}
```

Ishga tushirish (loyiha ildizidan):

```bash
uv run fastapi dev app/main.py
```

`/docs` sahifasida, endi endpoint'lar "Kitoblar" va "Mualliflar" nomli ikkita alohida guruhda ko'rinadi.

## Keng tarqalgan xatolar

**Xato 1:** `router = APIRouter(prefix="/mahsulotlar")` deb belgilab, keyin endpoint'larda yana `@router.get("/mahsulotlar")` deb, prefiksni **ikki marta** yozish.
❌ Bu — natijaviy yo'lni `/mahsulotlar/mahsulotlar` qilib qo'yadi, kutilgan natijadan farq qiladi.
✅ To'g'ri: `prefix` belgilangandan so'ng, endpoint dekoratorlarida faqat **qolgan** qismni yozing (masalan, `@router.get("/")` yoki `@router.get("/{id}")`), prefiks avtomatik qo'shiladi.

**Xato 2:** `app.include_router()`ni chaqirishni butunlay unutish, natijada router'da yozilgan endpoint'lar hech qachon ishlamasligi.
❌ `APIRouter` obyektini yaratish va unga endpoint qo'shish — bu, hali uni asosiy ilovaga "ulash" degani emas; agar `include_router()` chaqirilmasa, bu endpoint'lar butunlay "ko'rinmas" bo'lib qoladi.
✅ To'g'ri: har bir yangi router yaratilgandan so'ng, darhol `main.py`da uni import qilib, `app.include_router(...)` orqali ulashni unutmang — bu, odatda, yangi router yaratishning "oxirgi qadami" sifatida yodda tutilishi kerak.

**Xato 3:** barcha endpoint'larni, mantiqiy guruhlashsiz (masalan, foydalanuvchi va mahsulot endpoint'larini bitta `routers/hammasi.py` faylida), faqat "fayllarni ajratish uchun ajratish" maqsadida bo'lish.
❌ Bu — `APIRouter`ning asosiy afzalligini (mantiqiy, tushunarli tashkil etish) yo'qqa chiqaradi, va loyiha baribir "chalkash" bo'lib qoladi.
✅ To'g'ri: router'larni har doim **biznes domeni** bo'yicha (foydalanuvchilar, mahsulotlar, buyurtmalar) ajrating — har bir router, bitta aniq, mustaqil tushunchaga mos kelishi kerak.

## Mashq/topshiriq

**(Oson)** `routers/salomlar.py` faylida, `prefix="/salom"` bilan yangi `APIRouter` yarating, ichida bitta `GET /` endpoint (haqiqiy yo'li `/salom/`) yozing va uni `main.py`ga ulang.

**(O'rtacha)** Ikkita alohida router yarating: `foydalanuvchilar.py` (`prefix="/foydalanuvchilar"`, `tags=["Foydalanuvchilar"]`) va `mahsulotlar.py` (`prefix="/mahsulotlar"`, `tags=["Mahsulotlar"]`), har birida kamida ikkita endpoint (`GET` va `POST`) bilan. `main.py`da ikkalasini ham ulang va `/docs` sahifasida ikkita alohida guruh paydo bo'lishini tekshiring.

**(Qiyin)** Amaliy misoldagi kutubxona loyihasini kengaytirib, `v1_router = APIRouter(prefix="/api/v1")` yarating, `kitoblar` va `mualliflar` router'larini shu `v1_router`ga, so'ng `v1_router`ni `app`ga ulang. Barcha endpoint manzillari qanday o'zgarganini (`/kitoblar/` dan `/api/v1/kitoblar/`ga) tushuntirib bering va bu yondashuv nima uchun API versiyalashda foydali ekanini asoslang.

## Qisqacha xulosa

`APIRouter` — FastAPI loyihasini, endpoint'larni mantiqiy modullarga (foydalanuvchilar, mahsulotlar, buyurtmalar) bo'lish orqali tashkil etish imkonini beradi; har bir router — alohida faylda yaratilib, `app.include_router()` orqali asosiy ilovaga ulanadi. `prefix` — takrorlanuvchi URL qismini bir marta belgilash, `tags` esa — `/docs` sahifasida endpoint'larni vizual guruhlash uchun ishlatiladi; router'lar ichma-ich (`v1_router.include_router(...)`) ham bo'lishi mumkin, bu — API versiyalash kabi ilg'or naqshlarni tabiiy qo'llab-quvvatlaydi. Keyingi darsda, endpoint'lar orasida umumiy mantiqni (masalan, ma'lumotlar bazasi ulanishi yoki autentifikatsiya tekshiruvi) qanday qayta ishlatishni — Dependency Injection orqali — o'rganamiz.
