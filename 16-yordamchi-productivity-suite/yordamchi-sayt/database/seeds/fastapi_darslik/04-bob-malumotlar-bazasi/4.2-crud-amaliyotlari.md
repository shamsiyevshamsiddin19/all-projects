# CRUD amaliyotlari — Create, Read, Update, Delete

## Bu darsda nimalarni o'rganasiz

- To'liq CRUD endpoint'larini SQLModel bilan yaratasiz
- `session.add()`, `session.get()`, `session.exec()` metodlarini o'rganasiz
- Filtrlash va bog'lanishlarni (relationship) SQLModel orqali qo'llashni bilasiz
- Amaliy, ma'lumotlar bazasiga ulangan to'liq API yaratasiz

## Nazariy qism

### CRUD nima

**CRUD** — deyarli har qanday API'ning asosini tashkil etuvchi to'rtta asosiy amaliyot:

| Amaliyot | HTTP metod | SQLModel metodi |
|---|---|---|
| **C**reate (yaratish) | `POST` | `session.add()` + `session.commit()` |
| **R**ead (o'qish) | `GET` | `session.get()` yoki `session.exec()` |
| **U**pdate (yangilash) | `PUT`/`PATCH` | Obyektni o'zgartirib, `session.commit()` |
| **D**elete (o'chirish) | `DELETE` | `session.delete()` + `session.commit()` |

### Create — yangi qator qo'shish

```python
from sqlmodel import Session
from fastapi import Depends
from typing import Annotated

@app.post("/kitoblar", response_model=KitobJavob, status_code=201)
def kitob_yaratish(
    kitob: KitobYaratish,
    session: Annotated[Session, Depends(session_olish)],
):
    db_kitob = Kitob.model_validate(kitob)
    session.add(db_kitob)
    session.commit()
    session.refresh(db_kitob)
    return db_kitob
```

| Metod | Vazifasi |
|---|---|
| `Kitob.model_validate(kitob)` | `KitobYaratish` (Pydantic) obyektidan, `Kitob` (jadval) obyektini yaratadi |
| `session.add(db_kitob)` | Obyektni sessiyaga "belgilaydi" (hali bazaga yozilmagan) |
| `session.commit()` | O'zgarishlarni haqiqatan **ma'lumotlar bazasiga yozadi** |
| `session.refresh(db_kitob)` | Bazadan yangi ma'lumotni (masalan, avtomatik generatsiya qilingan `id`ni) qayta o'qiydi |

### Read — bitta yozuvni ID orqali olish

```python
from fastapi import HTTPException, status

@app.get("/kitoblar/{kitob_id}", response_model=KitobJavob)
def kitob_olish(
    kitob_id: int,
    session: Annotated[Session, Depends(session_olish)],
):
    kitob = session.get(Kitob, kitob_id)
    if not kitob:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Kitob topilmadi")
    return kitob
```

`session.get(Kitob, kitob_id)` — asosiy kalit (primary key) orqali tezkor qidirish, agar topilmasa `None` qaytaradi (2.2-darsda ko'rilgan `HTTPException` bilan birga ishlatiladi).

### Read — barcha yozuvlarni olish (filtrlash bilan)

```python
from sqlmodel import select

@app.get("/kitoblar", response_model=list[KitobJavob])
def kitoblar_royxati(
    session: Annotated[Session, Depends(session_olish)],
    muallif: str | None = None,
    sahifa: int = 1,
    hajmi: int = 10,
):
    so_rov = select(Kitob)

    if muallif:
        so_rov = so_rov.where(Kitob.muallif == muallif)

    so_rov = so_rov.offset((sahifa - 1) * hajmi).limit(hajmi)

    natijalar = session.exec(so_rov).all()
    return natijalar
```

| Qism | Vazifasi |
|---|---|
| `select(Kitob)` | "Kitob jadvalidan tanla" so'rovini boshlaydi (hali bazaga yuborilmagan) |
| `.where(Kitob.muallif == muallif)` | SQL `WHERE` shartini qo'shadi |
| `.offset(...).limit(...)` | Sahifalash (1.2-darsda ko'rilgan `sahifa`/`hajmi` query parametrlari bilan bog'liq) |
| `session.exec(so_rov).all()` | So'rovni **haqiqatan bajaradi** va natijalarni ro'yxat sifatida qaytaradi |

### Update — mavjud yozuvni yangilash

```python
class KitobYangilash(SQLModel):
    nomi: str | None = None
    muallif: str | None = None
    yil: int | None = None

@app.patch("/kitoblar/{kitob_id}", response_model=KitobJavob)
def kitob_yangilash(
    kitob_id: int,
    yangilanish: KitobYangilash,
    session: Annotated[Session, Depends(session_olish)],
):
    db_kitob = session.get(Kitob, kitob_id)
    if not db_kitob:
        raise HTTPException(status_code=404, detail="Kitob topilmadi")

    yangi_malumot = yangilanish.model_dump(exclude_unset=True)
    for kalit, qiymat in yangi_malumot.items():
        setattr(db_kitob, kalit, qiymat)

    session.add(db_kitob)
    session.commit()
    session.refresh(db_kitob)
    return db_kitob
```

> 📌 **`exclude_unset=True` — muhim nuance:** bu, `model_dump()`ga faqat, so'rovda **haqiqatan yuborilgan** maydonlarni qaytarishni buyuradi (standart qiymatlar bilan to'ldirilgan, lekin so'rovda bo'lmagan maydonlarni emas). Bu — `PATCH` (qisman yangilash)ning to'g'ri ishlashi uchun **zarur**: aks holda, foydalanuvchi faqat `nomi`ni yangilamoqchi bo'lsa ham, boshqa maydonlar `None` bilan **tasodifan tozalanib** ketishi mumkin.

### Delete — yozuvni o'chirish

```python
@app.delete("/kitoblar/{kitob_id}", status_code=status.HTTP_204_NO_CONTENT)
def kitob_ochirish(
    kitob_id: int,
    session: Annotated[Session, Depends(session_olish)],
):
    kitob = session.get(Kitob, kitob_id)
    if not kitob:
        raise HTTPException(status_code=404, detail="Kitob topilmadi")

    session.delete(kitob)
    session.commit()
    return None
```

### Bog'lanishlar (Relationships) — bir-ko'pga misol

Real loyihalarda, jadvallar odatda bir-biri bilan **bog'langan** bo'ladi. Masalan, bitta muallif — ko'p kitobga ega bo'lishi mumkin (one-to-many):

```python
from sqlmodel import Relationship

class Muallif(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    ism: str

    kitoblar: list["Kitob"] = Relationship(back_populates="muallif_obj")

class Kitob(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    nomi: str
    muallif_id: int | None = Field(default=None, foreign_key="muallif.id")

    muallif_obj: Muallif | None = Relationship(back_populates="kitoblar")
```

| Qism | Vazifasi |
|---|---|
| `foreign_key="muallif.id"` | Bu ustun, `muallif` jadvalining `id`siga ishora qiladi (tashqi kalit) |
| `Relationship(back_populates=...)` | Python darajasida, ikkala klass o'rtasida avtomatik "bog'lanish" (masalan, `kitob.muallif_obj.ism` orqali kirish) yaratadi |

```python
@app.get("/mualliflar/{muallif_id}/kitoblar")
def muallif_kitoblari(muallif_id: int, session: Annotated[Session, Depends(session_olish)]):
    muallif = session.get(Muallif, muallif_id)
    if not muallif:
        raise HTTPException(404, "Muallif topilmadi")
    return muallif.kitoblar   # Relationship orqali, avtomatik yuklanadi
```

## Amaliy misol

To'liq, ma'lumotlar bazasiga ulangan CRUD API — kutubxona loyihasi:

```python
# app/routers/kitoblar.py
from typing import Annotated
from fastapi import APIRouter, Depends, HTTPException, status
from sqlmodel import Session, select

from app.database import session_olish
from app.models import Kitob, KitobYaratish, KitobJavob, KitobYangilash

router = APIRouter(prefix="/kitoblar", tags=["Kitoblar"])

@router.post("/", response_model=KitobJavob, status_code=status.HTTP_201_CREATED)
def yaratish(kitob: KitobYaratish, session: Annotated[Session, Depends(session_olish)]):
    db_kitob = Kitob.model_validate(kitob)
    session.add(db_kitob)
    session.commit()
    session.refresh(db_kitob)
    return db_kitob

@router.get("/", response_model=list[KitobJavob])
def royxat(
    session: Annotated[Session, Depends(session_olish)],
    muallif: str | None = None,
    sahifa: int = 1,
    hajmi: int = 10,
):
    so_rov = select(Kitob)
    if muallif:
        so_rov = so_rov.where(Kitob.muallif == muallif)
    so_rov = so_rov.offset((sahifa - 1) * hajmi).limit(hajmi)
    return session.exec(so_rov).all()

@router.get("/{kitob_id}", response_model=KitobJavob)
def bitta_kitob(kitob_id: int, session: Annotated[Session, Depends(session_olish)]):
    kitob = session.get(Kitob, kitob_id)
    if not kitob:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Kitob topilmadi")
    return kitob

@router.patch("/{kitob_id}", response_model=KitobJavob)
def yangilash(
    kitob_id: int,
    yangilanish: KitobYangilash,
    session: Annotated[Session, Depends(session_olish)],
):
    db_kitob = session.get(Kitob, kitob_id)
    if not db_kitob:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Kitob topilmadi")
    for kalit, qiymat in yangilanish.model_dump(exclude_unset=True).items():
        setattr(db_kitob, kalit, qiymat)
    session.add(db_kitob)
    session.commit()
    session.refresh(db_kitob)
    return db_kitob

@router.delete("/{kitob_id}", status_code=status.HTTP_204_NO_CONTENT)
def ochirish(kitob_id: int, session: Annotated[Session, Depends(session_olish)]):
    kitob = session.get(Kitob, kitob_id)
    if not kitob:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Kitob topilmadi")
    session.delete(kitob)
    session.commit()
```

Sinash:

```bash

  -H "Content-Type: application/json" \
  -d '{"nomi": "Mehrobdan chayon", "muallif": "Abdulla Qodiriy", "yil": 1929}'

curl -X DELETE http://127.0.0.1:8000/kitoblar/1
```

## Keng tarqalgan xatolar

**Xato 1:** `session.add()`dan keyin, `session.commit()`ni chaqirishni unutish.
❌ `session.add()` — o'zgarishni faqat sessiyaning **xotirasida** belgilaydi, uni haqiqatan ma'lumotlar bazasiga yozmaydi; `commit()`siz, o'zgarish sessiya yopilganda **butunlay yo'qoladi**.
✅ To'g'ri: har qanday yozish amaliyoti (`add`, `delete`, obyekt maydonini o'zgartirish) dan keyin, har doim `session.commit()`ni chaqiring.

**Xato 2:** `PATCH` endpoint'ida, `model_dump()`ni `exclude_unset=True`siz ishlatish.
❌ Bu holda, foydalanuvchi faqat bitta maydonni (masalan, `yil`) yangilamoqchi bo'lsa ham, model'dagi **barcha** boshqa maydonlar, ularning standart qiymatlari (ko'pincha `None`) bilan **qayta yoziladi**, natijada mavjud ma'lumot tasodifan yo'qoladi.
✅ To'g'ri: qisman yangilash (`PATCH`) endpoint'larida, har doim `model_dump(exclude_unset=True)` ishlating — bu, faqat haqiqatan so'rovda kelgan maydonlarni qo'llaydi.

**Xato 3:** `session.get(Kitob, kitob_id)` natijasini (u `None` bo'lishi mumkinligini) tekshirmasdan, to'g'ridan-to'g'ri undan foydalanishga urinish.
❌ Agar `kitob_id` bazada mavjud bo'lmasa, `session.get()` — `None` qaytaradi; uni tekshirmasdan `kitob.nomi`ga murojaat qilish — `AttributeError` (`'NoneType' object has no attribute 'nomi'`) xatosiga, va noaniq `500` javobiga olib keladi.
✅ To'g'ri: `session.get()` natijasini har doim tekshiring, va agar `None` bo'lsa, 2.2-darsda ko'rilgan `HTTPException(404, ...)` orqali, aniq va tushunarli xato qaytaring.

## Mashq/topshiriq

**(Oson)** `POST /kitoblar` va `GET /kitoblar/{id}` endpoint'larini, yuqoridagi naqshga asosan, `Talaba` modeli uchun (4.1-darsdagi mashqda yaratilgan) yozing.

**(O'rtacha)** `GET /kitoblar` endpoint'iga, `muallif` filtridan tashqari, `yil_dan` va `yil_gacha` (ixtiyoriy, `int`) query parametrlarini qo'shing, ular orqali faqat muayyan yillar oralig'idagi kitoblarni qaytaring (`select(Kitob).where(Kitob.yil >= yil_dan, Kitob.yil <= yil_gacha)` uslubida).

**(Qiyin)** `Muallif` va `Kitob` orasida `Relationship` (yuqoridagi nazariy qismdagi kabi) yarating. `GET /mualliflar/{muallif_id}` endpoint'i uchun, javobda muallifning **barcha kitoblari ro'yxati bilan birga** qaytarilishini ta'minlaydigan Pydantic response modelini (`MuallifJavobKitoblarBilan`, ichida `kitoblar: list[KitobJavob]` maydoni bilan) loyihalashtiring va nima uchun bu holatda `response_model`da alohida, "ichma-ich" model kerakligini tushuntirib bering.

## Qisqacha xulosa

CRUD (Create, Read, Update, Delete) — `session.add()`/`commit()` (yaratish), `session.get()`/`session.exec(select(...))` (o'qish), obyekt maydonlarini o'zgartirib `commit()` qilish (yangilash, `exclude_unset=True` bilan qisman yangilashni to'g'ri boshqarib) va `session.delete()`/`commit()` (o'chirish) orqali amalga oshiriladi; barcha operatsiyalar, 3.2-darsda ko'rilgan `Depends(session_olish)` orqali, har bir so'rov uchun avtomatik boshqariladigan sessiya ichida bajariladi. `Relationship` — jadvallar orasidagi bog'lanishlarni (bir-ko'pga, va h.k.) Python darajasida tabiiy ifodalash imkonini beradi, lekin API javobida ko'rsatish uchun, odatda alohida, ichma-ich response model talab qilinadi. Keyingi darsda, jadval strukturasini xavfsiz o'zgartirish (migratsiya) uchun Alembic vositasini o'rganamiz.
