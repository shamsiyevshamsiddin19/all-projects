# Background Tasks va WebSocket

## Bu darsda nimalarni o'rganasiz

- `BackgroundTasks` orqali so'rovdan keyin ishlaydigan vazifalarni yaratasiz
- WebSocket nima ekanini va u oddiy HTTP'dan nima bilan farqlanishini tushunasiz
- FastAPI'da WebSocket endpoint yaratishni o'rganasiz
- Real vaqtli (real-time) xususiyatlar uchun qачон har birini tanlashni bilasiz

## Nazariy qism

### Background Tasks nima

**Background Task (fon vazifasi)** — mijozga javob **darhol qaytarilib**, lekin ba'zi qo'shimcha ish (masalan, email yuborish, log yozish) — javob qaytarilgandan **keyin**, fonda bajariladigan vazifa.

### Muammo — background task'siz

```python
@app.post("/royxatdan-otish")
def royxatdan_otish(malumot: FoydalanuvchiYaratish):
    yangi_foydalanuvchi = foydalanuvchi_yaratish(malumot)
    xush_kelibsiz_email_yuborish(yangi_foydalanuvchi.email)  # 2-3 soniya kutadi!
    return yangi_foydalanuvchi
```

Bu kodda, foydalanuvchi — email yuborilib bo'lguncha (bu, tashqi xizmatga bog'liq bo'lgani uchun, sekin bo'lishi mumkin), **javobni kutishga majbur**. Bu — foydalanuvchi tajribasini yomonlashtiradi, chunki email yuborilishi, ro'yxatdan o'tish natijasi uchun **darhol muhim emas**.

### Yechim — `BackgroundTasks`

```python
from fastapi import BackgroundTasks, FastAPI

app = FastAPI()

def xush_kelibsiz_email_yuborish(email: str):
    # (haqiqiy loyihada, bu yerda SMTP orqali email yuboriladi)
    print(f"Email yuborilmoqda: {email}")

@app.post("/royxatdan-otish")
def royxatdan_otish(malumot: FoydalanuvchiYaratish, fon_vazifalari: BackgroundTasks):
    yangi_foydalanuvchi = foydalanuvchi_yaratish(malumot)
    fon_vazifalari.add_task(xush_kelibsiz_email_yuborish, yangi_foydalanuvchi.email)
    return yangi_foydalanuvchi   # DARHOL qaytariladi, email fonda yuboriladi
```

`fon_vazifalari.add_task(funksiya, *argumentlar)` — funksiyani **navbatga qo'yadi**, u javob mijozga yuborilgandan **keyin**, ishga tushadi.

### Bir nechta background task qo'shish

```python
@app.post("/buyurtma")
def buyurtma_yaratish(malumot: BuyurtmaYaratish, fon_vazifalari: BackgroundTasks):
    buyurtma = buyurtma_saqlash(malumot)
    fon_vazifalari.add_task(mijozga_email_yuborish, buyurtma.email)
    fon_vazifalari.add_task(omborni_yangilash, buyurtma.mahsulot_id)
    fon_vazifalari.add_task(log_yozish, f"Yangi buyurtma: {buyurtma.id}")
    return buyurtma
```

Vazifalar — qo'shilgan tartibda, ketma-ket bajariladi.

### `BackgroundTasks`ni Dependency ichida ishlatish

3.2-darsda ko'rilgan Dependency Injection, `BackgroundTasks` bilan ham birga ishlashi mumkin:

```python
def log_yozuvchi_dependency(fon_vazifalari: BackgroundTasks):
    fon_vazifalari.add_task(log_yozish, "Endpoint chaqirildi")

@app.get("/malumot", dependencies=[Depends(log_yozuvchi_dependency)])
def malumot_olish():
    return {"malumot": "..."}
```

> ⚠️ **Muhim cheklov:** `BackgroundTasks` — **oddiy**, qisqa muddatli vazifalar uchun mo'ljallangan (email yuborish, kichik log yozish). Agar vazifa uzoq davom etsa (bir necha daqiqa) yoki serverning o'zi qayta ishga tushishi mumkin bo'lsa (masalan, deploy paytida), **maxsus navbat tizimi** (masalan, Celery, RQ, yoki Docker darsligida ko'rilgan konteynerlashtirilgan alohida "worker" xizmati) ishlatilishi kerak — bu, ushbu darslik doirasidan tashqarida.

### WebSocket nima

Oddiy HTTP — **so'rov-javob** (request-response) modeliga asoslangan: mijoz so'rov yuboradi, server bir marta javob beradi, aloqa tugaydi. **WebSocket** — bundan farqli, **doimiy, ikki tomonlama** aloqa kanalini ochadi: server va mijoz, aloqa ochiq turgan davomida, istalgan vaqtda bir-biriga xabar yuborishi mumkin.

| Xususiyat | Oddiy HTTP | WebSocket |
|---|---|---|
| Aloqa turi | So'rov-javob, bir martalik | Doimiy, ikki tomonlama |
| Kim boshlaydi | Faqat mijoz | Ikkalasi ham (server ham xabar yubora oladi) |
| Mos qo'llanilishi | Odatiy API so'rovlari | Chat, jonli bildirishnomalar, jonli ma'lumot oqimi (masalan, birja narxlari) |

### FastAPI'da WebSocket endpoint yaratish

```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect

app = FastAPI()

@app.websocket("/ws/chat")
async def chat_endpoint(websocket: WebSocket):
    await websocket.accept()
    try:
        while True:
            xabar = await websocket.receive_text()
            await websocket.send_text(f"Siz yubordingiz: {xabar}")
    except WebSocketDisconnect:
        print("Mijoz ulanishni uzdi")
```

| Metod | Vazifasi |
|---|---|
| `await websocket.accept()` | Ulanishni qabul qiladi (majburiy, birinchi qadam) |
| `await websocket.receive_text()` | Mijozdan xabar kelishini **kutadi** |
| `await websocket.send_text(...)` | Mijozga xabar yuboradi |
| `WebSocketDisconnect` | Mijoz ulanishni uzganda "otiladigan" xato — buni tutib olish tavsiya etiladi |

> 📌 **Nima uchun `async def` shart:** WebSocket — tabiatan, uzoq muddat davomida ochiq turadigan ulanish; 0.1-darsda ko'rilgan asinxron dasturlash tamoyillari, bu yerda **majburiy** ahamiyat kasb etadi — `await websocket.receive_text()` kutayotganda, server boshqa mijozlarga xizmat ko'rsatishda davom etishi kerak.

### Bir nechta mijozni boshqarish — "ulanishlar menejeri"

Real chat ilovasida, server — bir nechta mijozga bir vaqtda xizmat ko'rsatishi va ular orasida xabar almashtirishi kerak:

```python
class UlanishlarMenejeri:
    def __init__(self):
        self.faol_ulanishlar: list[WebSocket] = []

    async def ulash(self, websocket: WebSocket):
        await websocket.accept()
        self.faol_ulanishlar.append(websocket)

    def uzish(self, websocket: WebSocket):
        self.faol_ulanishlar.remove(websocket)

    async def barchaga_yuborish(self, xabar: str):
        for ulanish in self.faol_ulanishlar:
            await ulanish.send_text(xabar)

menejer = UlanishlarMenejeri()

@app.websocket("/ws/umumiy-chat")
async def umumiy_chat(websocket: WebSocket):
    await menejer.ulash(websocket)
    try:
        while True:
            xabar = await websocket.receive_text()
            await menejer.barchaga_yuborish(xabar)
    except WebSocketDisconnect:
        menejer.uzish(websocket)
```

Bu — har bir yangi mijozni ro'yxatga oladi, va kelgan har bir xabarni, **barcha ulangan mijozlarga** yuboradi — oddiy, real vaqtli chat xizmatining asosi.

## Amaliy misol

To'liq, background task va WebSocket'ni birlashtiruvchi amaliy loyiha — buyurtma tizimi va jonli bildirishnoma:

```python
from datetime import datetime
from fastapi import FastAPI, BackgroundTasks, WebSocket, WebSocketDisconnect
from pydantic import BaseModel

app = FastAPI()

class UlanishlarMenejeri:
    def __init__(self):
        self.ulanishlar: list[WebSocket] = []

    async def ulash(self, ws: WebSocket):
        await ws.accept()
        self.ulanishlar.append(ws)

    def uzish(self, ws: WebSocket):
        if ws in self.ulanishlar:
            self.ulanishlar.remove(ws)

    async def bildirishnoma_yuborish(self, xabar: str):
        for ws in self.ulanishlar:
            await ws.send_json({"xabar": xabar, "vaqt": str(datetime.now())})

menejer = UlanishlarMenejeri()

class BuyurtmaYaratish(BaseModel):
    mahsulot: str
    miqdor: int

def buyurtma_logini_yozish(mahsulot: str, miqdor: int):
    print(f"[LOG] Yangi buyurtma: {miqdor} x {mahsulot}")

@app.post("/buyurtmalar")
async def buyurtma_yaratish(malumot: BuyurtmaYaratish, fon_vazifalari: BackgroundTasks):
    fon_vazifalari.add_task(buyurtma_logini_yozish, malumot.mahsulot, malumot.miqdor)
    await menejer.bildirishnoma_yuborish(f"Yangi buyurtma: {malumot.miqdor} x {malumot.mahsulot}")
    return {"xabar": "Buyurtma qabul qilindi", "malumot": malumot}

@app.websocket("/ws/bildirishnomalar")
async def bildirishnomalar(websocket: WebSocket):
    await menejer.ulash(websocket)
    try:
        while True:
            await websocket.receive_text()   # ulanishni "tirik" ushlab turish uchun
    except WebSocketDisconnect:
        menejer.uzish(websocket)
```

Bu tizimda: har safar yangi buyurtma yaratilganda, barcha `/ws/bildirishnomalar`ga ulangan mijozlar (masalan, admin panelidagi barcha ochiq oynalar), **darhol**, real vaqtda bildirishnoma oladi — sahifani yangilash yoki qayta-qayta so'rov yuborish (polling) shart emas.

## Keng tarqalgan xatolar

**Xato 1:** background task ichida, uzoq davom etadigan (bir necha daqiqalik) og'ir hisoblashni joylashtirish.
❌ `BackgroundTasks` — bir xil server jarayoni (process) ichida ishlaydi; juda og'ir vazifa, boshqa so'rovlarni qayta ishlash uchun zarur resurslarni band qilib qo'yishi mumkin, va agar server qayta ishga tushirilsa (masalan, deploy paytida), tugallanmagan vazifa **butunlay yo'qoladi**.
✅ To'g'ri: faqat qisqa, tezkor vazifalar (email yuborish, kichik log) uchun `BackgroundTasks` ishlating; og'ir yoki muhim (masalan, to'lov qayta ishlash) vazifalar uchun, maxsus, alohida navbat tizimini (Celery kabi) ko'rib chiqing.

**Xato 2:** WebSocket endpoint'da, `WebSocketDisconnect` xatosini tutmasdan qoldirish.
❌ Mijoz brauzerni yopganda yoki internetdan uzilganda, server bu haqda "bildirishnoma" (`WebSocketDisconnect`) oladi; agar bu tutib olinmasa, server konsolida keraksiz xato ko'rinishi, va (menejerdagi kabi) ulanishlar ro'yxatidan o'chirilmagan "o'lik" ulanishlar to'planib qolishi mumkin.
✅ To'g'ri: har bir WebSocket endpoint'da, har doim `try`/`except WebSocketDisconnect` blokidan foydalaning va uzilgan ulanishni tegishli ro'yxatdan olib tashlang (yuqoridagi `UlanishlarMenejeri.uzish()` kabi).

**Xato 3:** oddiy, tez-tez o'zgaruvchi bo'lmagan ma'lumot uchun ham (masalan, kunlik statistika), WebSocket ishlatish, oddiy `GET` so'rovi yetarli bo'lgan holatda.
❌ WebSocket — doimiy ulanishni saqlab turish uchun qo'shimcha server resurslarini talab qiladi; agar ma'lumot tez-tez o'zgarmasa, bu — ortiqcha murakkablik va resurs sarfini keltirib chiqaradi.
✅ To'g'ri: WebSocket'ni faqat **haqiqatan real vaqtli, tez-tez yangilanadigan** ma'lumot (chat, jonli bildirishnoma, jonli narxlar) uchun ishlating; oddiy, kam o'zgaradigan ma'lumot uchun, oddiy `GET` endpoint (kerak bo'lsa, mijoz tomonidan davriy so'rov — polling) yetarli.

## Mashq/topshiriq

**(Oson)** `POST /xabar-yuborish` endpoint'ini yozing, u `BackgroundTasks` orqali, so'rov tugagandan keyin, konsolga `"Xabar fonda yuborildi"` chop etuvchi vazifani qo'shsin.

**(O'rtacha)** Oddiy `/ws/eho` (echo) WebSocket endpoint yarating — mijozdan kelgan har bir matnni, oldiga `"Eho: "` qo'shib, orqaga qaytarsin, `WebSocketDisconnect`ni to'g'ri tutib oling.

**(Qiyin)** Amaliy misoldagi `UlanishlarMenejeri`ni kengaytirib, unga `xona_boyicha_yuborish(xona_nomi: str, xabar: str)` metodini qo'shing — bu, faqat muayyan "xona"ga (masalan, `"sport"`, `"texnologiya"`) obuna bo'lgan mijozlarga xabar yuborsin (har bir WebSocket ulanishi, `dict[WebSocket, str]` orqali, o'zining xona nomi bilan saqlansin). Bu, nima uchun oddiy "barchaga yuborish"dan ko'ra murakkabroq, lekin real chat ilovalarida (masalan, Telegram guruhlari) zarur ekanini tushuntirib bering.

## Qisqacha xulosa

`BackgroundTasks` — mijozga javobni **darhol** qaytarib, keyin (email yuborish, log yozish kabi) qo'shimcha, qisqa muddatli vazifalarni fonda bajarish imkonini beradi — bu, foydalanuvchi tajribasini sezilarli yaxshilaydi, lekin uzoq yoki muhim vazifalar uchun maxsus navbat tizimlari (Celery kabi) kerak bo'ladi. **WebSocket** — oddiy so'rov-javob HTTP modelidan farqli, doimiy, ikki tomonlama aloqa kanalini ochib, chat va jonli bildirishnoma kabi real vaqtli xususiyatlarni tabiiy amalga oshirish imkonini beradi; `WebSocketDisconnect`ni to'g'ri tutib olish va ulanishlarni boshqarish (masalan, "ulanishlar menejeri" orqali) — ishonchli WebSocket tizimining asosiy talabi. Keyingi darsda, yozilgan FastAPI kodini avtomatik testlar bilan qanday tekshirishni o'rganamiz.
