# Branch tushunchasi va u bilan ishlash

## Bu darsda nimalarni o'rganasiz

- Branch (novda) nima ekanini va nima uchun kerakligini tushunasiz
- Yangi branch yaratish, unga o'tish va boshqarish buyruqlarini o'rganasiz
- `git switch` va `git checkout` farqini bilasiz
- Branch'larni oqilona nomlash konvensiyalarini o'rganasiz

## Nazariy qism

### Branch nima va nima uchun kerak

**Branch (novda)** — loyihaning mustaqil rivojlanish yo'nalishi. Uni "parallel olam" deb tasavvur qilish mumkin: asosiy kod (`main`) tegilmasdan turib, alohida branch'da yangi funksiya ustida ishlash, xato tuzatish yoki eksperiment qilish mumkin.

Branch'siz ishlash muammosi: agar bir nechta dasturchi (yoki hatto bitta dasturchi bir nechta vazifa ustida) bevosita `main`da ishlasa — tugallanmagan, sinovdan o'tmagan kod doimo asosiy kodga aralashib turadi, bu esa production'ni beqaror qiladi.

```
main:     A---B---C---F---G
                \         /
yangi-funksiya:   D-------E
```

Bu diagrammada: `main`dan `D` nuqtasida yangi branch ochilgan, unda `D` va `E` commit'lari qilingan, so'ng `G`da `main`ga qaytadan **birlashtirilgan** (merge — keyingi darsda ko'ramiz).

### Branch — aslida nima

Texnik jihatdan, Git branch'i — bu shunchaki **muayyan commit'ga ishora qiluvchi harakatlanuvchi ko'rsatkich (pointer)**. Bu — Git'ning boshqa VCS tizimlaridan (masalan, SVN) farqli, juda yengil va tez ishlaydigan branch mexanizmini ta'minlaydi (yangi branch yaratish — millisekundlar ichida, fayllarni nusxalashni talab qilmaydi).

### Asosiy branch buyruqlari

```bash
# Barcha branch'larni ko'rish (joriy branch * bilan belgilanadi)
git branch

# Yangi branch yaratish (lekin unga o'tmasdan)
git branch yangi-funksiya

# Branch'ga o'tish (zamonaviy usul, Git 2.23+)
git switch yangi-funksiya

# Yaratish + o'tish birdaniga
git switch -c yangi-funksiya

# Branch'ni o'chirish
git branch -d yangi-funksiya

# Majburiy o'chirish (birlashtirilmagan bo'lsa ham)
git branch -D yangi-funksiya

# Branch nomini o'zgartirish
git branch -m eski-nom yangi-nom
```

### `git switch` vs `git checkout`

Tarixiy jihatdan, branch'lar bilan ishlash uchun `git checkout` ishlatilar edi. Ammo `checkout` — juda ko'p turli vazifalarni bajaradi (branch almashtirish, fayllarni tiklash, commit'ga o'tish), bu esa uni chalkash qiladi. Git 2.23 versiyasidan boshlab, ushbu vazifalar ikkiga ajratildi:

| Buyruq | Vazifa |
|---|---|
| `git switch <branch>` | Faqat branch almashtirish uchun (zamonaviy, tavsiya etiladi) |
| `git restore <fayl>` | Faqat faylni oldingi holatga qaytarish uchun |
| `git checkout <narsa>` | Eski, universal buyruq (hozir ham ishlaydi, lekin ko'p ma'noli) |

```bash
# Zamonaviy (tavsiya etiladi)
git switch main

# Eski, lekin hali ham keng qo'llaniladigan usul
git checkout main
```

Ko'plab qo'llanmalar va eski loyihalarda hali ham `git checkout -b <branch>` (yaratish + o'tish) ko'rinishini uchratish mumkin — bu `git switch -c <branch>`ga funksional ekvivalent.

### Branch nomlash konvensiyalari

Amaliyotda keng tarqalgan naming konvensiyalar:

| Prefiks | Vazifasi | Misol |
|---|---|---|
| `feature/` | Yangi funksiya | `feature/foydalanuvchi-royxatdan-otish` |
| `fix/` yoki `bugfix/` | Xato tuzatish | `fix/login-xatosi` |
| `hotfix/` | Shoshilinch production tuzatish | `hotfix/server-ishlamayapti` |
| `refactor/` | Kodni qayta tashkil etish (funksionallik o'zgarmaydi) | `refactor/database-qatlami` |
| `docs/` | Hujjatlash o'zgarishlari | `docs/readme-yangilash` |

Bu konvensiyalar — jamoada kim nima ustida ishlayotganini branch nomidan bilib olish imkonini beradi (4-bobda "Git Flow" workflow'ida batafsil ko'riladi).

### Joriy branch'ni tekshirish

```bash
git branch --show-current
```

## Amaliy misol

To'liq ish jarayoni — yangi funksiya ustida alohida branch'da ishlash:

```bash
mkdir kalkulyator && cd kalkulyator && git init
echo "def qoshish(a, b): return a + b" > kalkulyator.py
git add kalkulyator.py
git commit -m "Boshlang'ich qo'shish funksiyasi"

# Hozir qaysi branch'damiz?
git branch
# * main

# Yangi funksiya uchun branch yaratamiz va o'tamiz
git switch -c feature/ayirish-funksiyasi

git branch
#   main
# * feature/ayirish-funksiyasi

# Yangi branch'da o'zgartirish kiritamiz
echo "def ayirish(a, b): return a - b" >> kalkulyator.py
git add kalkulyator.py
git commit -m "Ayirish funksiyasini qo'shish"

git log --oneline
# e4f5g6h (HEAD -> feature/ayirish-funksiyasi) Ayirish funksiyasini qo'shish
# a1b2c3d (main) Boshlang'ich qo'shish funksiyasi

# main'ga qaytamiz - kalkulyator.py qayta "eski" holatga qaytadi!
git switch main
cat kalkulyator.py
# def qoshish(a, b): return a + b
# (ayirish funksiyasi yo'q - u faqat feature branch'da mavjud)

# feature branch'ga qaytib, u yerda davom etamiz
git switch feature/ayirish-funksiyasi
cat kalkulyator.py
# def qoshish(a, b): return a + b
# def ayirish(a, b): return a - b
```

Bu misol — branch'lar bir-biridan **to'liq mustaqil** ekanini, va branch almashtirilganda fayllar avtomatik ravishda o'sha branch'ning holatiga o'zgarishini ko'rsatadi.

## Keng tarqalgan xatolar

**Xato 1:** to'g'ridan-to'g'ri `main` branch'ida yangi funksiyalar ustida ishlash, alohida branch ochmasdan.
❌ Bu — tugallanmagan yoki xato kod doimo asosiy kodga aralashib turishiga, va boshqa dasturchilar bilan ishlashda konfliktlar (4-bobda ko'riladi) yuzaga kelishiga sabab bo'ladi.
✅ To'g'ri: har bir yangi funksiya, xato tuzatish yoki eksperiment uchun **alohida branch** oching (`git switch -c feature/...`), va faqat tayyor bo'lgach, `main`ga birlashtiring.

**Xato 2:** branch almashtirishdan oldin joriy o'zgarishlarni commit qilmasdan (yoki stash qilmasdan) `git switch` qilishga urinish.
❌ Agar joriy branch'da commit qilinmagan o'zgarishlar mavjud bo'lsa va ular yangi branch'dagi bir xil fayllarga taalluqli bo'lsa, Git branch almashtirishni rad etishi mumkin ("error: Your local changes... would be overwritten").
✅ To'g'ri: branch almashtirishdan oldin o'zgarishlarni yo commit qiling, yo `git stash` bilan vaqtincha "yashirib qo'ying" (5-bobda batafsil ko'riladi).

**Xato 3:** ko'p sonli branch'larni tugagandan keyin o'chirmasdan qoldirish, natijada `git branch` ro'yxati o'nlab keraksiz branch'lar bilan to'lib ketishi.
❌ Bu — loyihada "qaysi branch hali dolzarb, qaysi eskirgan" degan chalkashlikka olib keladi.
✅ To'g'ri: funksiya `main`ga birlashtirilgach, feature branch'ni darhol o'chiring (`git branch -d feature/...`) — Git bu buyruqni, agar branch hali birlashtirilmagan bo'lsa, avtomatik rad etadi (xavfsizlik chorasi sifatida).

## Mashq/topshiriq

**(Oson)** Yangi loyiha yarating, `git branch` bilan joriy branch'ni ko'ring, so'ng `feature/test` nomli yangi branch yarating va unga o'ting (`git switch -c`).

**(O'rtacha)** `feature/test` branch'ida yangi fayl yarating va commit qiling. So'ng `main`ga qayting va o'sha faylning **mavjud emasligini** tasdiqlang. Nima uchun shunday bo'lishini tushuntiring.

**(Qiyin)** Uchta branch yarating: `feature/a`, `feature/b`, `feature/c`, har birida turlicha faylga o'zgartirish kiritib commit qiling. `git log --oneline --graph --all` buyrug'i orqali barcha branch'larning tarixini bir vaqtda vizual ko'ring va ularning `main`dan qanday "tarmoqlanganini" tasvirlab bering.

<details>
<summary>Javoblarni ko'rish</summary>

1. `git init`, `git branch` (natija: `* main`), `git switch -c feature/test`.
2. `touch yangi.txt && git add yangi.txt && git commit -m "test"`, `git switch main`, `ls` — `yangi.txt` ko'rinmaydi, chunki bu commit faqat `feature/test` branch'ining tarixida mavjud; `main` branch'i o'zining commit tarixiga ega bo'lib, `feature/test`dagi o'zgarishlardan bexabar (ular hali birlashtirilmagan).
3. `git switch -c feature/a && touch a.txt && git add a.txt && git commit -m "a" && git switch main`, xuddi shunday `feature/b` va `feature/c` uchun; `git log --oneline --graph --all` — `main`dan uchta alohida "shoxcha" chiqib, har biri o'z commit'iga ega ekanini vizual chiziqlar bilan ko'rsatadi (hali birlashtirilmagani uchun ular bir-biriga qo'shilmaydi).

</details>

## Qisqacha xulosa

Branch — loyihaning mustaqil rivojlanish yo'nalishi bo'lib, texnik jihatdan muayyan commit'ga ishora qiluvchi yengil ko'rsatkich hisoblanadi; `git switch -c <nom>` orqali yangi branch yaratib, unga o'tish mumkin, `git branch` esa mavjud branch'larni ko'rsatadi. Har bir yangi funksiya yoki xato tuzatish uchun alohida branch ochish — jamoaviy va yakka ishlashda ham asosiy amaliyot hisoblanadi, chunki bu asosiy (`main`) kodni doimo barqaror holatda saqlashga yordam beradi; keyingi darsda bu branch'larni qanday qilib qayta `main`ga birlashtirish (merge) o'rganiladi.
