# Repository, commit, asosiy buyruqlar (init, add, commit, status, log)

## Bu darsda nimalarni o'rganasiz

- `git init` orqali yangi repozitoriya yarata olasiz
- `git add` va `git commit` orqali o'zgarishlarni saqlay olasiz
- `git status` va `git log` orqali repozitoriya holatini tekshira olasiz
- Yaxshi commit izohi (commit message) qanday yozilishini bilasiz

## Nazariy qism

### Repository (repozitoriya) — Git tomonidan kuzatiladigan loyiha

**Repository** (qisqacha "repo") — Git tomonidan versiya nazorati qilinadigan papka. Har qanday oddiy papkani `git init` orqali repozitoriyaga aylantirish mumkin:

```bash
mkdir mening-birinchi-loyiham
cd mening-birinchi-loyiham
git init
```

Natija:

```
Initialized empty Git repository in /home/foydalanuvchi/mening-birinchi-loyiham/.git/
```

`git init` — joriy papka ichida **yashirin `.git`** papkasini yaratadi — aynan shu papkada butun loyiha tarixi (commit'lar, branch'lar, sozlamalar) saqlanadi. `.git` papkasini o'chirish — repozitoriya tarixini **butunlay** yo'qotish demakdir (oddiy fayllar esa saqlanib qoladi, faqat ularning Git tarixi yo'qoladi).

```bash
ls -la
# drwxr-xr-x  .git    <-- shu yerda butun tarix saqlanadi
```

### `git status` — "hozir nima bo'lyapti" savoliga javob

`git status` — Git bilan ishlashda **eng ko'p** ishlatiladigan buyruq bo'lib, joriy holatni ko'rsatadi:

```bash
echo "print('Salom, Git!')" > main.py
git status
```

Natija:

```
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	main.py

nothing added to commit but untracked files present (use "git add" to see)
```

`Untracked files` — Git bu faylni **hali kuzatmayapti** (u haqida hech narsa bilmaydi, faqat uni ko'radi) — bu 0.1-darsdagi "Working Directory" hududining aynan o'zi.

### `git add` — faylni Staging Area'ga qo'shish

```bash
git add main.py
git status
```

Natija:

```
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   main.py
```

Endi `main.py` — **Staging Area**da ("Changes to be committed"), ya'ni keyingi commit'ga kirishga **tayyorlangan**. Bir nechta faylni bir vaqtda qo'shish:

```bash
git add fayl1.py fayl2.py           # aniq fayllarni
git add .                              # JORIY PAPKADAGI barcha o'zgargan/yangi fayllarni
git add *.py                            # faqat .py kengaytmali fayllarni
```

### `git commit` — o'zgarishni doimiy saqlash

```bash
git commit -m "Birinchi commit: main.py yaratildi"
```

Natija:

```
[main (root-commit) a1b2c3d] Birinchi commit: main.py yaratildi
 1 file changed, 1 insertion(+)
 create mode 100644 main.py
```

`-m "..."` — commit izohini (message) to'g'ridan-to'g'ri buyruq qatorida yozish (0.2-darsda ko'rgan matn muharrirni chaqirmasdan). `a1b2c3d` — bu commit'ning **noyob identifikatori** (hash, SHA-1 asosida hisoblanadi) — bu son har bir commit uchun butunlay noyob va o'zgarmasdir.

### To'liq ish tsikli — bir necha marta commit qilish

```bash
# 1-o'zgarish
echo "def salomlash(): print('Salom!')" >> main.py
git add main.py
git commit -m "salomlash funksiyasi qo'shildi"

# 2-o'zgarish
echo "salomlash()" >> main.py
git add main.py
git commit -m "salomlash() chaqiruvi qo'shildi"
```

Har bir `add` + `commit` juftligi — loyiha tarixida **bitta nuqta** (checkpoint) yaratadi, unga keyinchalik qaytish mumkin (5-bobda `git reset`/`git revert` orqali ko'ramiz).

### `git log` — commit tarixini ko'rish

```bash
git log
```

Natija:

```
commit b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1 (HEAD -> main)
Author: Shamsiddin Shamsiyev <shamsiyevshamsiddin19@gmail.com>
Date:   Wed Aug 19 10:30:00 2026 +0500

    salomlash() chaqiruvi qo'shildi

commit a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0
Author: Shamsiddin Shamsiyev <shamsiyevshamsiddin19@gmail.com>
Date:   Wed Aug 19 10:25:00 2026 +0500

    salomlash funksiyasi qo'shildi
```

Foydali `git log` variantlari:

```bash
git log --oneline              # har bir commit BITTA qatorda, qisqa hash bilan
git log --oneline --graph        # + branch'lar vizual chiziq bilan (2-bobda foydali bo'ladi)
git log -3                        # faqat OXIRGI 3 ta commit
git log --author="Shamsiddin"      # faqat ma'lum muallif commit'lari
git log --since="2 days ago"        # ma'lum vaqtdan buyon
```

### `HEAD` — "siz hozir qayerdasiz" ko'rsatkichi

`HEAD` — Git'ning maxsus ko'rsatkichi (pointer) bo'lib, siz hozir **qaysi commit'da** turganingizni bildiradi (odatda — eng oxirgi commit, joriy branch'ning "uchi"). Bu tushuncha 2-bobdagi branch va 5-bobdagi `reset` mavzularida markaziy o'rin tutadi.

### Yaxshi commit izohi qanday yoziladi

Commit izohlari — kelajakda (siz yoki hamkasblaringiz uchun) loyiha tarixini o'qishda hal qiluvchi ahamiyatga ega:

| ❌ Yomon izoh | ✅ Yaxshi izoh |
|---|---|
| `"fix"` | `"Login formasidagi email validatsiyasi xatosini tuzatish"` |
| `"update"` | `"README fayliga o'rnatish yo'riqnomasi qo'shildi"` |
| `"asdasd"` | `"PostgreSQL ulanish sozlamalarini .env ga ko'chirish"` |
| `"final version"` | `"Buyurtma modeliga status maydoni qo'shildi"` |

**Umumiy qoidalar:**
- Fe'l bilan boshlang (nima **qilindi**): "qo'shildi", "tuzatildi", "o'chirildi", "yangilandi".
- Aniq va qisqa bo'ling — bitta commit, bitta mantiqiy o'zgarish haqida.
- "nima" o'zgarganini yozing (kod diff'ining o'zi buni ko'rsatadi), lekin ba'zan **"nega"** ham foydali bo'ladi.

## Amaliy misol

To'liq, boshidan oxirigacha bo'lgan ish tsikli — kichik Python skripti bilan:

```bash
# 1. Repozitoriya yaratish
mkdir kalkulyator-loyiha
cd kalkulyator-loyiha
git init

# 2. Birinchi fayl
cat > kalkulyator.py << 'EOF'
def qosh(a, b):
    return a + b
EOF

git status                       # "Untracked files: kalkulyator.py"
git add kalkulyator.py
git status                        # "Changes to be committed: new file: kalkulyator.py"
git commit -m "qosh funksiyasi qo'shildi"

# 3. Ikkinchi o'zgarish
cat >> kalkulyator.py << 'EOF'

def ayir(a, b):
    return a - b
EOF

git status                         # "Changes not staged for commit: modified: kalkulyator.py"
git add kalkulyator.py
git commit -m "ayir funksiyasi qo'shildi"

# 4. Uchinchi o'zgarish — README qo'shish
echo "# Kalkulyator loyihasi" > README.md
git add README.md
git commit -m "README.md yaratildi"

# 5. Butun tarixni ko'rish
git log --oneline
# c3d4e5f README.md yaratildi
# b2c3d4e ayir funksiyasi qo'shildi
# a1b2c3d qosh funksiyasi qo'shildi
```

Bu — uchta alohida, mantiqiy commit — har biri **bitta** aniq o'zgarishni ifodalaydi, bu kelajakda "qachon `ayir` funksiyasi qo'shilgan edi?" kabi savollarga `git log` orqali darhol javob topish imkonini beradi.

## Keng tarqalgan xatolar

**Xato 1:** `git add`ni unutib, to'g'ridan-to'g'ri `git commit` qilishga urinish.
❌ `git commit -m "o'zgarish"` (avval `git add` qilinmagan) — agar hech qanday fayl staging'da bo'lmasa, Git `nothing to commit, working tree clean` yoki `no changes added to commit` xatosini beradi.
✅ To'g'ri: har doim avval `git add <fayl>` (yoki `git add .`), so'ng `git commit -m "..."` — bu ikki bosqichli jarayonni unutmang.

**Xato 2:** juda ko'p, bog'liq bo'lmagan o'zgarishlarni **bitta** commit'ga jamlash.
❌ Bitta commit ichida "login formasi tuzatildi + yangi sahifa qo'shildi + CSS o'zgartirildi + README yangilandi" — bu tarixni o'qishni va kerak bo'lganda faqat bitta o'zgarishni bekor qilishni qiyinlashtiradi.
✅ To'g'ri: har bir commit **bitta, mantiqiy** o'zgarishni ifodalasin — bu Python kursining funksiyalar haqidagi bobida ko'rgan "bitta funksiya — bitta vazifa" tamoyilining commit'lar darajasidagi analogi.

**Xato 3:** `.git` papkasini tasodifan o'chirib, butun tarixni yo'qotish.
❌ `rm -rf .git` (yoki uni tashqi backup'siz butunlay o'chirish) — bu barcha commit tarixini **qaytarib bo'lmas** tarzda yo'qotadi (oddiy fayllar qoladi, lekin ularning tarixi yo'qoladi).
✅ To'g'ri: `.git` papkasiga hech qachon qo'lda tegmang; agar repozitoriyani "asl holiga qaytarish" kerak bo'lsa, Git'ning o'z buyruqlaridan (`git reset`, 5-bobda) foydalaning, GitHub'ga muntazam `push` qilib turish esa (3-bobda ko'ramiz) qo'shimcha "backup" vazifasini ham bajaradi.

## Mashq/topshiriq

**(Oson)** Yangi papka yarating, `git init` bilan repozitoriya boshlang, bitta `.txt` fayl yaratib, uni `git add` va `git commit -m "..."` orqali saqlang, so'ng `git log` bilan tasdiqlang.

**(O'rtacha)** Bitta faylga uchta alohida o'zgarish kiritib, har birini alohida, mantiqiy izohlar bilan commit qiling, so'ng `git log --oneline` orqali barcha uchta commit'ni bitta qatorda ko'ring.

**(Qiyin)** Ikkita fayl (`a.py`, `b.py`) yarating, ikkalasini ham o'zgartiring, lekin `git add a.py` orqali faqat **bittasini** staging'ga qo'shing va commit qiling; so'ng `git status` orqali `b.py` hamon "not staged" holatida ekanini tasdiqlang va bu nima uchun foydali xususiyat ekanini (aniq tanlab commit qilish imkoniyati) tushuntirib bering.

1. `mkdir test && cd test && git init`, `echo "Salom" > fayl.txt`, `git add fayl.txt`, `git commit -m "fayl.txt yaratildi"`, `git log`.
2. Masalan: `echo "1" > sonlar.txt && git add sonlar.txt && git commit -m "Birinchi son qo'shildi"`, so'ng `echo "2" >> sonlar.txt && git add sonlar.txt && git commit -m "Ikkinchi son qo'shildi"`, va yana bir marta — `git log --oneline` uchta qatorni ko'rsatadi.
3. `echo "a" > a.py; echo "b" > b.py; git add a.py; git commit -m "a.py qo'shildi"`, so'ng `git status` — `b.py` hamon `Untracked files` ostida ko'rinadi, chunki u hech qachon `git add`ga qo'shilmagan; bu foydali, chunki dasturchi bir vaqtda bir nechta faylni o'zgartirsa ham, faqat **tayyor, tugallangan** o'zgarishlarni tanlab commit qilish imkoniyatiga ega bo'ladi, tugallanmagan ishni esa keyingi commit'gacha "kutdirib turishi" mumkin.

## Qisqacha xulosa

`git init` — papkani Git repozitoriyasiga aylantiradi (`.git` yashirin papkasi orqali), `git status` — joriy holatni (qaysi fayllar kuzatilmayapti, o'zgartirilgan yoki staging'da ekanini) ko'rsatadi, `git add` — fayllarni Staging Area'ga (keyingi commit'ga kiritish uchun) qo'shadi, `git commit -m "..."` esa ularni **doimiy, noyob identifikatorli** (hash) tarixiy nuqta sifatida saqlaydi; `git log` — butun commit tarixini ko'rsatadi, yaxshi yozilgan commit izohlari esa loyiha tarixini kelajakda o'qish va tushunishni sezilarli osonlashtiradi — bu to'rtta buyruq (`add`, `commit`, `status`, `log`) Git bilan ishlashning kundalik, eng asosiy ish tsiklini tashkil qiladi.
