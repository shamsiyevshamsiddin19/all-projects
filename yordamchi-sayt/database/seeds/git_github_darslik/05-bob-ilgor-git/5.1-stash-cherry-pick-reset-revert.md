# Stash, cherry-pick va reset vs revert

## Bu darsda nimalarni o'rganasiz

- `git stash` orqali o'zgarishlarni vaqtincha "yashirishni" o'rganasiz
- `git cherry-pick` bilan muayyan commit'ni boshqa branch'ga ko'chirishni bilasiz
- `git reset`ning uch rejimini (`--soft`, `--mixed`, `--hard`) tushunasiz
- `git reset` va `git revert` orasidagi muhim farqni va qачон qaysi birini ishlatishni bilasiz

## Nazariy qism

### `git stash` — o'zgarishlarni vaqtincha "yashirish"

Tez-tez uchraydigan vaziyat: siz bir narsa ustida ishlab turibsiz (hali commit qilishga tayyor emas), lekin shoshilinch boshqa branch'ga o'tishingiz kerak (masalan, shoshilinch xato tuzatish uchun). `git stash` — joriy commit qilinmagan o'zgarishlarni **vaqtincha saqlab qo'yadi** va working directory'ni toza holatga qaytaradi.

```bash
# O'zgarishlarni "yashirish"
git stash

# Yashirilganlar ro'yxatini ko'rish
git stash list
# stash@{0}: WIP on main: a1b2c3d Boshlang'ich commit

# Qaytarib olish (va stash'dan o'chirish)
git stash pop

# Qaytarib olish (lekin stash'da nusxasini saqlab qolish)
git stash apply

# Nomlab saqlash (bir nechta stash bilan ishlashda foydali)
git stash push -m "login formasi ustida ishlash"

# Muayyan stash'ni qo'llash
git stash apply stash@{1}

# Barcha stash'larni o'chirish
git stash clear
```

| Buyruq | Vazifasi |
|---|---|
| `git stash` | O'zgarishlarni saqlab, tozalaydi |
| `git stash pop` | Oxirgi stash'ni qaytaradi va o'chiradi |
| `git stash apply` | Qaytaradi, lekin stash ro'yxatida saqlab qoladi |
| `git stash list` | Barcha saqlangan stash'larni ko'rsatadi |
| `git stash drop` | Muayyan stash'ni o'chiradi |

### `git cherry-pick` — bitta commit'ni tanlab olish

`git cherry-pick` — boshqa branch'dagi **bitta muayyan commit'ni**, joriy branch'ga (butun branch'ni merge qilmasdan) qo'shish imkonini beradi. Foydali holat: boshqa branch'da tasodifan foydali tuzatish qilingan, va sizga faqat o'sha bitta o'zgarish kerak, boshqa hech narsa emas.

```bash
git switch main
git cherry-pick a1b2c3d
```

Bu — `a1b2c3d` commit'ida qilingan o'zgarishlarni, joriy branch'ga **yangi commit** sifatida qo'shadi (yangi hash bilan).

```bash
# Bir nechta commit'ni ketma-ket
git cherry-pick a1b2c3d e4f5g6h

# Konflikt yuzaga kelsa (rebase'ga o'xshash)
git cherry-pick --continue
git cherry-pick --abort
```

### `git reset` — uch rejim

`git reset` — HEAD ko'rsatkichini (va ixtiyoriy ravishda, staging area/working directory'ni) **orqaga qaytarish** uchun ishlatiladi. Uning uch rejimi bor:

| Rejim | HEAD | Staging Area | Working Directory | Qачон ishlatiladi |
|---|---|---|---|---|
| `--soft` | O'zgaradi | O'zgarmaydi (saqlanadi) | O'zgarmaydi (saqlanadi) | Commit'ni "bekor qilib", o'zgarishlarni staged holatda qayta commit qilish uchun |
| `--mixed` (standart) | O'zgaradi | Tozalanadi | O'zgarmaydi (saqlanadi) | Commit va staging'ni bekor qilib, fayllarni qayta ko'rib chiqish uchun |
| `--hard` | O'zgaradi | Tozalanadi | **Tozalanadi (o'chadi!)** | Hamma narsani, shu jumladan fayl o'zgarishlarini butunlay yo'q qilish uchun |

```bash
# Oxirgi commit'ni bekor qilish, lekin o'zgarishlarni staged holatda saqlash
git reset --soft HEAD~1

# Oxirgi commit'ni bekor qilish, o'zgarishlarni working directory'da saqlash
git reset --mixed HEAD~1
# (yoki shunchaki: git reset HEAD~1)

# Oxirgi commit'ni VA barcha o'zgarishlarni butunlay yo'q qilish
git reset --hard HEAD~1
```

> ⚠️ **Jiddiy ogohlantirish:** `git reset --hard` — commit qilinmagan barcha o'zgarishlarni **qaytarib bo'lmaydigan tarzda o'chiradi**. Bu buyruqni ishlatishdan oldin, `git status` bilan nima yo'qolishini albatta tekshiring.

### `git revert` — xavfsiz "bekor qilish"

`git revert` — `reset`dan tubdan farq qiladi: u tarixni **o'zgartirmaydi**, aksincha, muayyan commit'ning ta'sirini **bekor qiluvchi yangi commit** yaratadi.

```bash
git revert a1b2c3d
```

```
Oldin:  A---B---C  (C - noto'g'ri commit)
Keyin:  A---B---C---D  (D - C'ni bekor qiluvchi yangi commit)
```

### `reset` vs `revert` — qачон qaysi birini ishlatish

| Vaziyat | Tavsiya |
|---|---|
| Shaxsiy, hali **push qilinmagan** commit'ni bekor qilish | `git reset` (tarix hali faqat sizda, o'zgartirish xavfsiz) |
| **Allaqachon push qilingan**, boshqalar bilan umumiy commit'ni bekor qilish | `git revert` (tarixni saqlaydi, boshqalarning nusxasi bilan konflikt qilmaydi) |
| "Bu commit tarixda umuman bo'lmasin" | `git reset` (faqat shaxsiy branch'da) |
| "Bu commit sodir bo'lgan, lekin uning ta'sirini bekor qilaman" (audit uchun muhim) | `git revert` |

> ⚠️ **Oltin qoida (rebase darsidagi qoidaga o'xshash):** `git reset --hard` yoki tarixni o'zgartiruvchi boshqa buyruqlarni, **allaqachon boshqalar bilan bo'lishilgan (push qilingan) commit'larga** hech qachon qo'llamang. Bunday holatlarda har doim `git revert` ishlatiladi.

## Amaliy misol

Uchta vositani birga qo'llash — amaliy stsenariy:

```bash
mkdir ilgor-git-mashqi && cd ilgor-git-mashqi && git init
echo "v1" > fayl.txt
git add fayl.txt
git commit -m "Boshlang'ich versiya"

# STASH misoli - ishni to'xtatib, boshqa branch'ga o'tish
echo "tugallanmagan ish" >> fayl.txt
git stash push -m "tugallanmagan xususiyat"
git status
# working directory toza

git switch -c shoshilinch/xato-tuzatish
echo "tuzatildi" >> fayl.txt
git add fayl.txt
git commit -m "Shoshilinch xatoni tuzatish"

git switch main
git stash pop
cat fayl.txt
# v1
# tugallanmagan ish   (qaytib keldi)

# CHERRY-PICK misoli - shoshilinch tuzatishni asosiy ishga ko'chirish
git log shoshilinch/xato-tuzatish --oneline
# f7g8h9i Shoshilinch xatoni tuzatish

git cherry-pick f7g8h9i
# Endi main branch'da ham bu tuzatish mavjud

# RESET misoli - oxirgi commit'ni bekor qilish (hali push qilinmagan)
git add fayl.txt
git commit -m "Test commit"
git reset --soft HEAD~1
git status
# o'zgarishlar hali staged holatda, qaytadan commit qilish mumkin

# REVERT misoli - allaqachon "push qilingan" commit'ni xavfsiz bekor qilish
git log --oneline
git revert f7g8h9i
# Yangi commit yaratiladi, f7g8h9i ning ta'sirini bekor qiladi,
# lekin f7g8h9i tarixda saqlanib qoladi
```

## Keng tarqalgan xatolar

**Xato 1:** `git reset --hard`ni, commit qilinmagan **muhim** o'zgarishlar borligini tekshirmasdan ishlatish.
❌ Bu — qaytarib bo'lmaydigan tarzda soatlab qilingan ishni yo'qotishga olib kelishi mumkin.
✅ To'g'ri: `--hard` ishlatishdan oldin har doim `git status` va `git diff` bilan nima yo'qolishini tekshiring; agar unchalik ishonchingiz komil bo'lmasa, `--soft` yoki `--mixed`dan boshlang (ular fayllarni saqlab qoladi).

**Xato 2:** allaqachon GitHub'ga push qilingan, boshqa dasturchilar `pull` qilib olgan commit'ni `git reset --hard` + majburiy push (`push --force`) bilan "yo'qotishga" urinish.
❌ Bu — boshqa dasturchilarning lokal tarixi bilan ziddiyatga olib keladi, ular keyingi `pull`da chalkash xatolarga duch keladi.
✅ To'g'ri: umumiy (push qilingan) commit'ni bekor qilish kerak bo'lsa, har doim `git revert` ishlating — bu tarixni saqlaydi va hech kimning nusxasini buzmaydi.

**Xato 3:** `git stash pop`ni bir necha marta ketma-ket ishlatib, qaysi stash qaysi ishga tegishli ekanini adashtirib yuborish.
❌ Ayniqsa bir nechta stash to'plangan bo'lsa, `pop` har doim **eng oxirgisini** qaytaradi, bu chalkashlikka olib kelishi mumkin.
✅ To'g'ri: bir nechta narsani stash qilayotganda, har doim tavsiflovchi nom bilan saqlang (`git stash push -m "..."`), va `git stash list` bilan avval nima borligini tekshirib, keyin kerakli stash'ni `git stash apply stash@{N}` orqali aniq tanlang.

## Mashq/topshiriq

**(Oson)** Faylga o'zgartirish kiriting (commit qilmasdan), `git stash` bilan yashiring, `git status` orqali toza holatni tasdiqlang, so'ng `git stash pop` bilan qaytarib oling.

**(O'rtacha)** Ikkita branch yarating. Birida commit qiling, uning hash'ini `git log --oneline` orqali toping, so'ng `git cherry-pick` orqali o'sha commit'ni ikkinchi branch'ga ko'chiring.

**(Qiyin)** Uchta ketma-ket commit qiling. `git reset --soft HEAD~2` bilan oxirgi ikkitasini "bekor qiling" (staged holatda saqlab), `git status` bilan natijani tekshiring. Keyin, xayolan "bu commit allaqachon GitHub'ga push qilingan" deb faraz qilib, o'sha commit'ni `git revert` orqali qanday bekor qilgan bo'lardingiz — ikkala usulning natijadagi asosiy farqini (`git log`da qanday ko'rinishini) tushuntirib bering.

<details>
<summary>Javoblarni ko'rish</summary>

1. `echo "test" >> fayl.txt && git stash && git status` (clean) `&& git stash pop && cat fayl.txt` (o'zgarish qaytadi).
2. `git switch -c branch-a && echo "a" > a.txt && git add a.txt && git commit -m "a"`, hash'ni `git log --oneline` orqali olish, `git switch -c branch-b main`, `git cherry-pick <hash>` — endi `branch-b`da ham `a.txt` mavjud bo'ladi, yangi commit hash bilan.
3. `git reset --soft HEAD~2` — oxirgi ikkita commit "yo'qoladi", lekin ularning o'zgarishlari **staged** holatda saqlanib qoladi (`git status`da "Changes to be committed" sifatida ko'rinadi), keyin ularni bitta yangi commit qilish mumkin. `git revert` esa — commit'ni tarixdan **olib tashlamaydi**, aksincha uning ustiga, uni bekor qiluvchi **yangi commit** qo'shadi; natijada `git log`da `reset`dan keyin faqat qolgan commit'lar ko'rinadi (tarix "qisqargandek"), `revert`dan keyin esa barcha eski commit'lar **va** ularni bekor qiluvchi yangi commit birga ko'rinadi (tarix "uzayadi", lekin hech narsa yo'qolmaydi).

</details>

## Qisqacha xulosa

`git stash` — commit qilinmagan o'zgarishlarni vaqtincha "yashirib", keyinroq qaytarib olish imkonini beradi (branch almashtirishdan oldin foydali); `git cherry-pick` — boshqa branch'dagi bitta muayyan commit'ni, butun branch'ni merge qilmasdan, joriy branch'ga qo'shadi; `git reset` (`--soft`/`--mixed`/`--hard`) — HEAD'ni orqaga qaytaradi, lekin faqat **shaxsiy, hali push qilinmagan** commit'larda xavfsiz, chunki u tarixni o'zgartiradi; `git revert` esa tarixni **saqlab**, muayyan commit'ning ta'sirini bekor qiluvchi yangi commit yaratadi — shuning uchun **allaqachon boshqalar bilan bo'lishilgan** commit'larni bekor qilishning yagona xavfsiz yo'li hisoblanadi.
