# Remote repository: push, pull, clone va fetch

## Bu darsda nimalarni o'rganasiz

- Remote repository tushunchasini va `origin` nomini tushunasiz
- Mavjud loyihani GitHub'ga qanday ulashni (`git remote add`, `git push`) bilasiz
- GitHub'dagi loyihani kompyuteringizga qanday yuklab olishni (`git clone`) o'rganasiz
- `git pull` va `git fetch` farqini tushunasiz

## Nazariy qism

### Remote nima

**Remote** — sizning lokal (kompyuteringizdagi) repository'ingiz bilan bog'langan, **masofadagi** (odatda GitHub'dagi) repository manzili. Bir repository bir nechta remote'ga ega bo'lishi mumkin, lekin eng keng tarqalgan holat — bitta remote, va u odatda `origin` deb nomlanadi (bu shunchaki konvensiya, majburiy nom emas).

```bash
# Mavjud remote'larni ko'rish
git remote -v
```

### Ikki xil boshlanish stsenariysi

| Stsenariy | Yondashuv |
|---|---|
| Lokalda loyiha allaqachon bor, uni GitHub'ga yuklamoqchisiz | `git remote add` + `git push` |
| GitHub'da loyiha bor, uni kompyuterga olmoqchisiz | `git clone` |

### 1-stsenariy: mavjud lokal loyihani GitHub'ga ulash

Avval, GitHub veb-saytida **bo'sh** repository yaratiladi (README, .gitignore qo'shmasdan — aks holda tarix konflikga uchraydi):

**New repository** tugmasi → nom kiritish → **Create repository**.

So'ng, lokal terminalda:

```bash
# Remote manzilini qo'shish (SSH orqali, oldingi darsda sozlangan)
git remote add origin git@github.com:foydalanuvchi-nomi/loyiha-nomi.git

# Qo'shilganini tekshirish
git remote -v
# origin  git@github.com:foydalanuvchi-nomi/loyiha-nomi.git (fetch)
# origin  git@github.com:foydalanuvchi-nomi/loyiha-nomi.git (push)

# Birinchi push - -u bayrog'i bilan
git push -u origin main
```

`-u` (yoki `--set-upstream`) bayrog'i — lokal `main` branch'ini, remote'dagi `origin/main` bilan **bog'laydi**. Bu — bir martalik sozlash: shundan keyin, oddiy `git push` (qo'shimcha parametrlarsiz) avtomatik ishlaydi.

### 2-stsenariy: GitHub'dagi loyihani klonlash

```bash
git clone git@github.com:foydalanuvchi-nomi/loyiha-nomi.git
```

`git clone` — remote repository'ning **to'liq nusxasini** (barcha tarix, branch'lar bilan birga) yangi papkaga yuklab oladi, va avtomatik ravishda uni `origin` deb nomlaydi (`git remote add` qilish shart emas).

```bash
# Muqobil - GitHub CLI orqali (avtomatik autentifikatsiya bilan)
gh repo clone foydalanuvchi-nomi/loyiha-nomi
```

### `git push` — o'zgarishlarni yuklash

```bash
git push origin main
```

Bu buyruq — lokal `main` branch'idagi yangi commit'larni, `origin` remote'ining `main` branch'iga yuboradi. Agar `-u` bilan avval bog'lab qo'yilgan bo'lsa, shunchaki:

```bash
git push
```

### `git pull` — o'zgarishlarni olish

```bash
git pull origin main
```

Bu buyruq — aslida ikki qadamni birlashtiradi:
1. `git fetch` — remote'dagi yangi commit'larni lokalga yuklab oladi (lekin birlashtirmaydi)
2. `git merge` (yoki sozlamaga qarab `rebase`) — yuklab olingan o'zgarishlarni joriy branch'ga birlashtiradi

### `git fetch` — faqat yuklab olish, birlashtirmasdan

```bash
git fetch origin
```

`git fetch` — remote'dagi o'zgarishlar haqida **ma'lumot oladi**, lekin ularni sizning joriy ishlayotgan fayllaringizga **avtomatik qo'shmaydi**. Bu — remote'da nima o'zgarganini xavfsiz tarzda, o'z ishingizga ta'sir qilmasdan ko'rish imkonini beradi.

```bash
# fetch qilingandan keyin, farqni ko'rish mumkin
git log origin/main --oneline
git diff main origin/main

# Faqat shundan keyin, xohlasangiz, birlashtiring
git merge origin/main
```

### `pull` vs `fetch` — qачон nimani ishlatish

| Vaziyat | Tavsiya |
|---|---|
| Tez, ishonchli tarzda eng so'nggi o'zgarishlarni olish | `git pull` |
| Avval nima o'zgarganini ko'rib, keyin qaror qabul qilish | `git fetch` + `git diff`/`git log` |
| Jamoaviy loyihada, o'z o'zgarishlaringiz bilan konflikt ehtimoli borligida | `git fetch` (ehtiyotkorlik bilan) |

### Remote branch'lar tushunchasi

`git fetch`/`clone`dan so'ng, Git — remote'dagi branch'larni **kuzatuvchi (tracking) branch'lar** sifatida ko'rsatadi (masalan, `origin/main`, `origin/feature-x`). Bularni ko'rish:

```bash
git branch -r        # faqat remote branch'lar
git branch -a        # lokal + remote, barchasi
```

### Bir necha remote — `upstream` misoli

Fork qilingan loyihalarda (keyingi darsda ko'ramiz), odatda ikkita remote bo'ladi:

```bash
git remote add upstream git@github.com:asl-muallif/loyiha.git
git remote -v
# origin    (sizning fork'ingiz)
# upstream  (asl loyiha)
```

## Amaliy misol

To'liq ish jarayoni — lokal loyihani GitHub'ga yuklash va boshqa "joydan" klonlash simulyatsiyasi:

```bash
# 1. Lokal loyiha (allaqachon commit'larga ega deb faraz qilamiz)
mkdir mening-loyiham && cd mening-loyiham
git init
echo "# Mening loyiham" > README.md
git add README.md
git commit -m "Boshlang'ich commit"

# 2. GitHub'da "mening-loyiham" nomli BO'SH repository yaratilgan deb faraz qilamiz

# 3. Remote qo'shish va yuklash
git remote add origin git@github.com:shamsiddin/mening-loyiham.git
git push -u origin main

# 4. Boshqa joyda (masalan, boshqa kompyuterda) klonlash
cd /tmp
git clone git@github.com:shamsiddin/mening-loyiham.git
cd mening-loyiham
ls
# README.md

# 5. O'zgarish kiritib, qaytadan yuklash
echo "Yangi qator" >> README.md
git add README.md
git commit -m "README'ga qo'shimcha"
git push

# 6. Asl papkaga qaytib, o'zgarishlarni olish
cd ../mening-loyiham
git pull
cat README.md
# Mening loyiham
# Yangi qator
```

## Keng tarqalgan xatolar

**Xato 1:** GitHub'da repository yaratishda README yoki `.gitignore`ni tanlab, so'ng lokal loyihani `push` qilishga urinish.
❌ Bu — remote'da allaqachon commit mavjudligi sababli, "fetch first" yoki tarix mos kelmasligi xatosini keltirib chiqaradi.
✅ To'g'ri: agar lokal loyihani birinchi marta yuklayotgan bo'lsangiz, GitHub'da repository'ni **butunlay bo'sh** (hech qanday fayl qo'shmasdan) yarating; aks holda, `git pull origin main --allow-unrelated-histories` bilan ikkala tarixni majburiy birlashtirish kerak bo'ladi.

**Xato 2:** `git pull`ni tez-tez, nima o'zgarganini tekshirmasdan, hatto o'zingizning commit qilinmagan o'zgarishlaringiz bor paytda ishlatish.
❌ Bu — kutilmagan konfliktlarga yoki noaniq merge commit'larga olib kelishi mumkin.
✅ To'g'ri: `git pull`dan oldin, `git status` bilan joriy holatni tekshiring; agar commit qilinmagan o'zgarishlar bo'lsa, avval ularni commit qiling (yoki `git stash` qiling — 5-bobda ko'riladi).

**Xato 3:** `git remote add origin ...` buyrug'ini, remote **allaqachon mavjud** bo'lgan repository'da qayta ishlatishga urinish.
❌ Bu — "remote origin already exists" xatosini beradi.
✅ To'g'ri: agar remote manzilini o'zgartirish kerak bo'lsa, `git remote set-url origin <yangi-manzil>` ishlatiladi; mavjud remote'larni ko'rish uchun har doim avval `git remote -v` bilan tekshirib ko'ring.

## Mashq/topshiriq

**(Oson)** GitHub'da bo'sh repository yarating, lokal papkada oddiy loyiha yaratib, uni `git remote add` va `git push -u origin main` orqali GitHub'ga yuklang.

**(O'rtacha)** O'sha repository'ni boshqa (masalan, `/tmp` ichidagi) papkaga `git clone` orqali klonlang. Klonlangan nusxada o'zgarish kiritib, `git push` qiling, so'ng asl papkada `git pull` orqali o'zgarishni oling.

**(Qiyin)** `git fetch origin` (pull emas) buyrug'ini ishga tushiring, so'ng `git log main..origin/main --oneline` orqali remote'da bor-u, lokalda hali yo'q commit'larni ko'ring. Shundan keyingina `git merge origin/main` bilan birlashtiring. Bu ikki bosqichli yondashuvning `git pull`dan nima afzalligi borligini tushuntiring.

<summary>Javoblarni ko'rish</summary>

1. GitHub'da "New repository" (bo'sh, README'siz) → lokal `git init`, commit, `git remote add origin <manzil>`, `git push -u origin main`.
2. `cd /tmp && git clone <manzil>`, o'sha yerda fayl o'zgartirib, `git add`, `git commit`, `git push`; asl papkaga qaytib `git pull` — yangilanish paydo bo'ladi.
3. `git fetch origin` — faqat remote ma'lumotlarini yuklab oladi, joriy fayllarni o'zgartirmaydi; `git log main..origin/main` — `origin/main`da bor-u `main`da yo'q commit'larni ko'rsatadi (nima kelayotganini oldindan ko'rish); bu yondashuv — `git pull`ga qaraganda xavfsizroq, chunki avval **nima o'zgarishi kerakligini ko'rib**, keyin ongli ravishda `merge` qaror qilinadi, o'zgarishlar "ko'r-ko'rona" avtomatik joriy ishga aralashib ketmaydi.

## Qisqacha xulosa

Remote — lokal repository bilan bog'langan masofadagi (odatda GitHub'dagi) manzil bo'lib, odatda `origin` deb nomlanadi; mavjud lokal loyihani GitHub'ga ulash uchun `git remote add` + `git push -u origin main`, GitHub'dagi loyihani olish uchun esa `git clone` ishlatiladi. `git pull` — `fetch` + `merge`ni birlashtirgan qulay, lekin "ko'r-ko'rona" buyruq, `git fetch` esa — remote o'zgarishlarini avval xavfsiz ko'rib chiqish, so'ng ongli ravishda birlashtirish imkonini beradi — jamoaviy loyihalarda ikkinchi yondashuv ko'pincha ehtiyotkorroq tanlov hisoblanadi.
