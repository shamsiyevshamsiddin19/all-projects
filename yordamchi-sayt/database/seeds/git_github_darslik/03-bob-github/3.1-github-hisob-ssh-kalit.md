# GitHub hisob yaratish va SSH kalitini sozlash

## Bu darsda nimalarni o'rganasiz

- GitHub'da hisob yaratasiz va uning asosiy imkoniyatlari bilan tanishasiz
- SSH kalit juftligini Ubuntu'da yaratishni o'rganasiz
- SSH kalitni GitHub akkauntga qo'shishni bilasiz
- Personal Access Token (PAT) nima ekanini va qachon kerak bo'lishini tushunasiz

## Nazariy qism

### GitHub nima (takror va kengaytirilgan)

Kirish bobida aytilganidek, **GitHub** — Git repozitoriylarini bulutda saqlash va jamoaviy ishlash uchun platforma. GitHub'ning asosiy imkoniyatlari:

| Imkoniyat | Vazifasi |
|---|---|
| Remote repository | Loyihangizning bulutdagi nusxasi (zaxira + boshqalar bilan bo'lishish) |
| Pull Request (PR) | Kod o'zgarishlarini ko'rib chiqish va birlashtirish jarayoni |
| Issues | Xato/vazifalarni kuzatish tizimi |
| Actions | CI/CD avtomatlashtirish (Docker darsligining 6.3-darsida ko'rilgan) |
| GitHub Pages | Statik saytlarni bepul joylashtirish |

Hisob yaratish — [github.com](https://github.com) saytida, email, foydalanuvchi nomi va parol orqali amalga oshiriladi (bu qadam brauzerda bajariladi, terminal buyruqlari talab qilmaydi).

### Nega parol orqali `git push` endi ishlamaydi

2021-yildan boshlab, GitHub — HTTPS orqali Git operatsiyalarida (`git push`, `git pull`) oddiy **parol bilan autentifikatsiyani butunlay o'chirib qo'ydi** (xavfsizlik sababli). Buning o'rniga, ikkita usuldan biri ishlatiladi:

| Usul | Qachon qulay |
|---|---|
| **SSH kalit** | Shaxsiy kompyuterda doimiy ishlash uchun (tavsiya etiladi) |
| **Personal Access Token (PAT)** | HTTPS orqali, yoki vaqtinchalik/skript avtomatlashtirish uchun |

### SSH kalit — qanday ishlaydi

SSH kalit juftligi — ikkita fayldan iborat: **maxfiy kalit** (`private key`, hech kimga berilmaydi, faqat kompyuteringizda qoladi) va **ochiq kalit** (`public key`, GitHub'ga yuklanadi). Ular bir-biriga matematik jihatdan bog'liq: GitHub sizga ochiq kalit orqali "savol" yuboradi, faqat mos maxfiy kalitga ega kompyuter unga to'g'ri "javob" bera oladi — parolni har safar kiritmasdan xavfsiz autentifikatsiya shu tarzda ta'minlanadi.

### SSH kalitini yaratish (Ubuntu)

```bash
ssh-keygen -t ed25519 -C "shamsiyevshamsiddin19@gmail.com"
```

| Bayroq | Ma'nosi |
|---|---|
| `-t ed25519` | Kalit turi — zamonaviy, tezkor va xavfsiz algoritm (eski `rsa`ga qaraganda tavsiya etiladi) |
| `-C "..."` | Izoh (odatda email) — kalitni keyinchalik tanib olish uchun |

Buyruq ishga tushgach, savollar beriladi:

```
Enter file in which to save the key (/home/foydalanuvchi/.ssh/id_ed25519): [Enter bosing]
Enter passphrase (empty for no passphrase): [ixtiyoriy parol, yoki bo'sh qoldirish uchun Enter]
```

> 📌 **Passphrase (kalit uchun parol) haqida:** Bu — SSH kalitning o'ziga qo'yiladigan qo'shimcha parol (GitHub paroli emas). Uni qo'shish xavfsizlikni oshiradi (agar kompyuter o'g'irlansa, kalit ishlatib bo'lmaydi), lekin har safar so'rashi mumkin. Boshlang'ich darajada bo'sh qoldirish ham qabul qilinadi.

### SSH agentga kalitni qo'shish

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

Bu — SSH kalitni "xotira"ga yuklaydi, har safar passphrase so'ralishining oldini oladi (agar passphrase qo'yilgan bo'lsa).

### Ochiq kalitni nusxalash va GitHub'ga qo'shish

```bash
cat ~/.ssh/id_ed25519.pub
```

Bu buyruq chiqargan **butun qatorni** (`ssh-ed25519 AAAA... email@example.com`) nusxalab olasiz, so'ng:

1. GitHub'da: **Settings → SSH and GPG keys → New SSH key**
2. "Title" maydoniga (masalan, "Ish kompyuterim") nom kiritiladi
3. "Key" maydoniga nusxalangan ochiq kalit joylashtiriladi
4. **Add SSH key** tugmasi bosiladi

### Ulanishni tekshirish

```bash
ssh -T git@github.com
```

Muvaffaqiyatli bo'lsa, quyidagicha xabar chiqadi:

```
Hi <foydalanuvchi-nomi>! You've successfully authenticated, but GitHub does not provide shell access.
```

### Personal Access Token (PAT) — muqobil usul

Agar SSH sozlash imkoni bo'lmasa (masalan, vaqtinchalik muhitda), HTTPS orqali ishlash uchun **Personal Access Token** ishlatiladi — bu, mohiyatan, parol o'rnini bosuvchi maxsus token.

GitHub — hozirda ikki turdagi tokenni taqdim etadi:

| Tur | Tavsif |
|---|---|
| **Fine-grained token** | Zamonaviy, **tavsiya etiladigan** tur — muayyan repository'larga, muayyan huquqlarga cheklab beriladi (xavfsizroq) |
| **Classic token** | Eski uslub, butun akkaunt bo'yicha kengroq huquqlarga ega |

Token yaratish: **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.

HTTPS orqali `git push` qilinganda, parol o'rniga shu token kiritiladi:

```
Username: foydalanuvchi-nomi
Password: <shu yerga PAT kiritiladi, oddiy parol emas>
```

> 📌 **SSH vs PAT tanlovi:** shaxsiy ish kompyuterida doimiy ishlash uchun — SSH tavsiya etiladi (bir marta sozlanadi, keyin parol/token so'ralmaydi). Vaqtinchalik muhit yoki CI/CD skriptlar uchun — token qulayroq.

### GitHub CLI (`gh`) — muqobil, zamonaviy vosita

GitHub — brauzersiz, terminal orqali GitHub bilan ishlash uchun rasmiy `gh` buyruq qatori vositasini taqdim etadi. Uni Ubuntu'ga o'rnatish:

```bash
sudo apt update && sudo apt install curl -y
curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg | sudo dd of=/usr/share/keyrings/githubcli-archive-keyring.gpg
sudo chmod go+r /usr/share/keyrings/githubcli-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null
sudo apt update
sudo apt install gh -y
```

O'rnatilgandan so'ng, autentifikatsiya bir buyruq bilan (brauzer orqali interaktiv, SSH kalitni qo'lda sozlashni talab qilmaydi):

```bash
gh auth login
```

`gh` — keyingi darslarda repository klonlash, Pull Request yaratish kabi vazifalarni ham soddalashtiradi.

## Amaliy misol

To'liq SSH sozlash ketma-ketligi — noldan:

```bash
# 1. Kalit yaratish
ssh-keygen -t ed25519 -C "shamsiyevshamsiddin19@gmail.com"
# Enter, Enter (yoki passphrase kiritish)

# 2. SSH agentni ishga tushirish va kalitni qo'shish
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# 3. Ochiq kalitni ko'rish va nusxalash
cat ~/.ssh/id_ed25519.pub
# (chiqqan qatorni nusxalab, GitHub Settings > SSH and GPG keys > New SSH key ga qo'shamiz)

# 4. Ulanishni tekshirish
ssh -T git@github.com
# Hi Shamsiddin! You've successfully authenticated...
```

Shu bilan, kompyuter GitHub bilan xavfsiz, parolsiz ulanishga tayyor — keyingi darsda birinchi repository'ni GitHub'ga yuklaymiz.

## Keng tarqalgan xatolar

**Xato 1:** ochiq kalit (`.pub`) o'rniga, **maxfiy kalitni** (`id_ed25519`, kengaytmasiz) GitHub'ga yuklashga urinish.
❌ Bu — jiddiy xavfsizlik xatosi: maxfiy kalit hech qachon hech kimga (hatto GitHub'ga ham) berilmasligi kerak; agar bu tasodifan sodir bo'lsa, kalitni darhol bekor qilib, yangisini yaratish kerak.
✅ To'g'ri: har doim faqat `.pub` kengaytmali faylni (`cat ~/.ssh/id_ed25519.pub`) nusxalab, GitHub'ga qo'shing.

**Xato 2:** HTTPS orqali `git push` qilishda, so'ralgan "Password" maydoniga oddiy GitHub parolini kiritish.
❌ 2021-yildan buyon bu — ishlamaydi, "support for password authentication was removed" xatosi bilan rad etiladi.
✅ To'g'ri: "Password" maydoniga — oldindan yaratilgan **Personal Access Token** kiritilishi kerak (yoki, yanada qulayroq, SSH orqali ulanish sozlanishi kerak).

**Xato 3:** bitta SSH kalitni bir nechta xizmat (GitHub, GitLab, ish serveri) uchun ishlatish va ularni chalkashtirib yuborish, yoki eski, zaif `rsa` (kichik uzunlikdagi) kalitlardan foydalanishni davom ettirish.
❌ Bu — xavfsizlik va boshqaruv nuqtai nazaridan noqulay.
✅ To'g'ri: har bir xizmat/kompyuter uchun alohida, zamonaviy `ed25519` turidagi kalit yaratish (masalan, `-f ~/.ssh/id_ed25519_github` bilan nomlab), va ularni `~/.ssh/config` faylida boshqarish tavsiya etiladi.

## Mashq/topshiriq

**(Oson)** GitHub'da hisob yarating (agar hali yo'q bo'lsa) va profil sozlamalarini (ism, avatar) to'ldiring.

**(O'rtacha)** Ubuntu'da `ssh-keygen -t ed25519` orqali yangi SSH kalit yarating, uni GitHub akkauntga qo'shing va `ssh -T git@github.com` orqali ulanishni tasdiqlang.

**(Qiyin)** GitHub CLI (`gh`)ni Ubuntu'ga o'rnating va `gh auth login` orqali autentifikatsiyadan o'ting. So'ng `gh auth status` buyrug'i bilan qaysi usul (SSH yoki HTTPS token) orqali autentifikatsiya qilinganini tekshiring va ikkalasining farqini tushuntiring.

## Qisqacha xulosa

GitHub bilan xavfsiz ishlash uchun parol autentifikatsiyasi endi qo'llab-quvvatlanmaydi — buning o'rniga SSH kalit (`ssh-keygen -t ed25519` orqali yaratilib, ochiq qismi GitHub'ga qo'shiladi) yoki Personal Access Token (fine-grained turi tavsiya etiladi) ishlatiladi; SSH — doimiy shaxsiy ishlash uchun qulayroq (bir marta sozlanadi), token esa vaqtinchalik yoki avtomatlashtirilgan holatlar uchun mos keladi. GitHub CLI (`gh`) — bularning barchasini soddalashtiradigan, brauzer orqali bir buyruqli autentifikatsiya (`gh auth login`) taqdim etuvchi zamonaviy vosita hisoblanadi.
