# Iteratorlar va generatorlar

## Bu darsda nimalarni o'rganasiz

- Iterator va iterable tushunchalari orasidagi farqni tushuntira olasiz
- `yield` yordamida o'z generator funksiyangizni yoza olasiz
- Generatorlarning xotira tejash afzalligini tushunasiz
- `yield from` va generator expression'larni qo'llay olasiz

## Nazariy qism

### Iterable va Iterator — asosiy farq

**Iterable** — `for` sikli bilan aylanish mumkin bo'lgan har qanday obyekt (`list`, `str`, `dict`, `set`). **Iterator** — bu iterable'ning "harakatlantiruvchisi": u har safar `next()` chaqirilganda **keyingi** elementni qaytaradi, elementlar tugaganda `StopIteration` xatosini ko'taradi.

```python
royxat = [1, 2, 3]

iterator = iter(royxat)     # list'dan iterator olish
print(next(iterator))         # 1
print(next(iterator))         # 2
print(next(iterator))         # 3
print(next(iterator))         # StopIteration xatosi!
```

Aslida, `for element in royxat:` yozganingizda, Python "sahna ortida" aynan shu jarayonni avtomatik bajaradi — `iter()` chaqiradi, so'ng `StopIteration` kelguncha `next()`ni takrorlaydi.

### Generator funksiya — `yield` bilan

**Generator** — iteratorning eng oddiy va qulay yaratish usuli. Oddiy funksiyada `return` bitta marta ishlaydi va funksiya tugaydi; `yield` esa qiymatni **"berib turadi"**, lekin funksiya holatini **saqlab qoladi** va keyingi `next()` chaqirilganda o'sha joydan davom etadi:

```python
def sonlar_generatori():
    print("Boshlandi")
    yield 1
    print("Birinchidan keyin")
    yield 2
    print("Ikkinchidan keyin")
    yield 3
    print("Tugadi")


gen = sonlar_generatori()    # funksiya HALI ishlamaydi — faqat generator obyekt yaratiladi
print(next(gen))    # Boshlandi \n 1
print(next(gen))    # Birinchidan keyin \n 2
print(next(gen))    # Ikkinchidan keyin \n 3
```

`for` sikli bilan ham ishlatish mumkin (`StopIteration`ni avtomatik boshqaradi):

```python
def uchgacha_sanash():
    yield 1
    yield 2
    yield 3

for son in uchgacha_sanash():
    print(son)     # 1, 2, 3
```

### Nega generatorlar — xotira tejash

```python
def royxat_yarat(n):
    natija = []
    for i in range(n):
        natija.append(i ** 2)
    return natija    # BUTUN ro'yxat darhol xotirada yaratiladi

def generator_yarat(n):
    for i in range(n):
        yield i ** 2     # har bir qiymat FAQAT kerak bo'lganda hisoblanadi

# 10 million elementli ro'yxat — GB'larcha xotira band qilishi mumkin
katta_royxat = royxat_yarat(10_000_000)     # darhol butun ro'yxatni xotiraga yuklaydi

# generator esa deyarli hech qanday qo'shimcha xotira band qilmaydi
katta_generator = generator_yarat(10_000_000)   # darhol hech narsa hisoblanmaydi!

for qiymat in katta_generator:
    if qiymat > 100:
        break    # faqat kerak bo'lgan qismi hisoblandi, qolgani umuman ishlamadi
```

Bu — generatorlarning eng katta afzalligi: ular elementlarni **"dangasa" (lazy)** tarzda, faqat so'ralganda hosil qiladi, shuning uchun juda katta (yoki hatto cheksiz) ketma-ketliklar bilan ishlashda xotirani tejaydi.

### Generator expression — comprehension'ning generator versiyasi

2.4-darsda qisqacha ko'rgan edik:

```python
kvadratlar_royxat = [x ** 2 for x in range(1000000)]     # darhol butun ro'yxat
kvadratlar_generator = (x ** 2 for x in range(1000000))    # generator — darhol hisoblanmaydi

print(sum(kvadratlar_generator))    # faqat shu yerda, birma-bir hisoblab, yig'indini topadi
```

Kvadrat qavs (`[]`) — list comprehension, oddiy qavs (`()`) — generator expression. Agar natijani faqat **bir marta**, ketma-ket ishlatish kerak bo'lsa (masalan, `sum()`, `max()`ga uzatish), generator expression xotirani tejaydigan, ko'proq samarali tanlov.

> ⚠️ **Generator faqat BIR MARTA aylanadi.** 
```python
gen = (x for x in range(5))
print(list(gen))    # [0, 1, 2, 3, 4]
print(list(gen))    # [] — bo'sh! Generator "tugagan", uni qayta ishlatib bo'lmaydi
```
Agar bir nechta marta aylanish kerak bo'lsa — list yoki `tuple` ishlating, yoki generatorni har safar qaytadan yarating (funksiyani qayta chaqiring).

### `yield from` — generatorni boshqa generatordan "davom ettirish"

```python
def kichik_generator():
    yield 1
    yield 2

def katta_generator():
    yield from kichik_generator()    # kichik_generator()ning barcha qiymatlarini "uzatadi"
    yield 3
    yield 4

print(list(katta_generator()))    # [1, 2, 3, 4]
```

`yield from` — ichma-ich generatorlarni (masalan, rekursiv daraxt aylanishda) yozishni ancha soddalashtiradi, `for element in kichik_generator(): yield element` yozishning qisqartmasi.

### Cheksiz generator — real hayotiy misol

```python
def cheksiz_sanoq(boshlanish=0):
    son = boshlanish
    while True:          # cheksiz sikl — lekin generator bo'lgani uchun xavfsiz!
        yield son
        son += 1


sanoq = cheksiz_sanoq(10)
for _ in range(5):
    print(next(sanoq))    # 10, 11, 12, 13, 14
# generator "to'xtatilgan" holatda qoladi, keyingi safar davom etishi mumkin
```

Bu — oddiy `while True: royxat.append(...)` bilan **hech qachon** amalga oshirib bo'lmaydigan narsa (chunki ro'yxat cheksiz o'sib, xotira tugab qoladi), lekin generator bilan mutlaqo xavfsiz, chunki har bir qiymat faqat so'ralganda hisoblanadi.

## Amaliy misol

Katta faylni qator-qator, xotirani tejab o'qish (real loyihalarda juda ko'p uchraydigan naqsh):

```python
# log_tahlil.py

def log_qatorlarini_oqish(fayl_nomi):
    """Fayldagi har bir qatorni birma-bir 'beradi' — butun faylni xotiraga yuklamasdan."""
    with open(fayl_nomi, "r", encoding="utf-8") as fayl:
        for qator in fayl:
            yield qator.strip()


def xato_qatorlarini_filtrlash(qatorlar):
    """Faqat 'ERROR' so'zi bor qatorlarni 'beradi'."""
    for qator in qatorlar:
        if "ERROR" in qator:
            yield qator


# Bu yerda hech qanday katta ro'yxat xotiraga yuklanmaydi —
# hatto fayl GB'larcha katta bo'lsa ham, dastur ishlayveradi:
barcha_qatorlar = log_qatorlarini_oqish("server.log")
xato_qatorlar = xato_qatorlarini_filtrlash(barcha_qatorlar)

xatolar_soni = 0
for xato in xato_qatorlar:
    print(xato)
    xatolar_soni += 1

print(f"\nJami xatolar: {xatolar_soni}")
```

Diqqat qiling: `log_qatorlarini_oqish()` va `xato_qatorlarini_filtrlash()` — ikkalasi ham generator, ular **zanjir** ko'rinishida ishlaydi (bittasining natijasi ikkinchisiga kirish sifatida beriladi), va hech qaysi bosqichda butun fayl yoki butun filtrlangan ro'yxat xotiraga to'liq yuklanmaydi — bu "pipeline" (quvur) uslubi katta ma'lumotlar bilan ishlashda standart hisoblanadi.

## Keng tarqalgan xatolar

**Xato 1:** generatorni ikki marta ishlatishga urinish.
❌ 
```python
gen = (x for x in range(5))
jami = sum(gen)      # 10
maksimum = max(gen)   # ValueError: max() arg is an empty sequence — gen allaqachon "tugagan"!
```
✅ To'g'ri: agar bir nechta marta kerak bo'lsa, natijani `list()`ga aylantiring: `royxat = list(gen); jami = sum(royxat); maksimum = max(royxat)`, yoki generatorni har safar qaytadan yarating.

**Xato 2:** `return`ni generator ichida qiymat qaytarish uchun ishlatishga urinish.
❌ 
```python
def gen():
    yield 1
    return 42    # bu qiymat oddiy usulda OLINMAYDI, iteratsiyada ko'rinmaydi
    yield 2      # bu qatorga hech qachon yetib borilmaydi
```
✅ To'g'ri: generator ichida `return` (qiymatsiz yoki bilan) — generatorni **to'xtatish** uchun ishlatiladi, `yield` o'rnini bosмайди. Agar generatordan oddiy qiymat qaytarish kerak bo'lsa, oddiy funksiya (`yield`siz) ishlating.

**Xato 3:** kichik, oddiy ro'yxatlar uchun ham har doim generator ishlatishga harakat qilish.
❌ 5-10 ta elementli oddiy ro'yxat uchun ham generator yozish — bu ortiqcha murakkablik, chunki xotira tejashning amaliy foydasi yo'q, lekin kod tushunarliligi pasayadi (generator faqat bir marta ishlatilishi mumkinligi kabi "sirli" xatti-harakatlar tufayli).
✅ To'g'ri: generatorlarni asosan **katta** yoki **cheksiz** ma'lumotlar, yoki "lazy evaluation" (kerak bo'lganda hisoblash) haqiqatan foyda keltiradigan holatlarda ishlating; kichik, ma'lum hajmdagi ma'lumotlar uchun oddiy `list` ko'pincha yetarli va tushunarliroq.

## Mashq/topshiriq

**(Oson)** `juft_sonlar_generatori(chegara)` generator funksiyasini yozing — `0` dan `chegara`gacha bo'lgan barcha juft sonlarni `yield` qilib bersin.

**(O'rtacha)** `fibonachchi_generator(n)` generator funksiyasini yozing — birinchi `n` ta Fibonachchi sonini (3.2-darsda rekursiv yozgan edik, endi generator bilan, sikl asosida, ancha samaraliroq) `yield` qilib bersin.

**(Qiyin)** `sahifalash(royxat, sahifa_hajmi)` generator funksiyasini yozing — berilgan ro'yxatni `sahifa_hajmi`ta elementdan iborat "sahifalar" (kichik ro'yxatlar) ko'rinishida birma-bir `yield` qilib bersin (masalan, `[1,2,3,4,5,6,7]` va `sahifa_hajmi=3` — `[1,2,3]`, `[4,5,6]`, `[7]`ni birma-bir beradi). Bu — real API'larda ma'lumotlarni "sahifalash" (pagination) uchun ishlatiladigan naqsh.

## Qisqacha xulosa

Iterator — `next()` orqali birma-bir qiymat beruvchi obyekt, generator (`yield` bilan yozilgan funksiya) esa — iteratorni yaratishning eng oddiy, "dangasa" (lazy) usuli bo'lib, katta yoki cheksiz ma'lumotlar bilan ishlashda xotirani sezilarli tejaydi; generator faqat **bir marta** aylanishi mumkinligini va `yield from` orqali generatorlarni zanjirlash mumkinligini yodda tutish — bu "pipeline" uslubidagi ma'lumot qayta ishlashning (fayllarni qator-qator o'qish, katta API javoblarini qayta ishlash) asosiy vositasi.
