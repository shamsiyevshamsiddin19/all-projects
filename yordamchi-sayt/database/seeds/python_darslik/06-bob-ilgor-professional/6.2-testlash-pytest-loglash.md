# Testlash (pytest) va loglash

## Bu darsda nimalarni o'rganasiz

- `pytest` yordamida avtomatik testlar yoza va ishga tushira olasiz
- Fixture'lar va parametrlangan testlarni qo'llay olasiz
- `assert` orqali kutilgan natijalarni tekshira olasiz
- `logging` modulini `print()` o'rniga professional loglash uchun ishlata olasiz

## Nazariy qism

### Nega avtomatik testlar kerak

Kod yozgach, uni qo'lda ishga tushirib "ishlayaptimi" deb tekshirish — kichik loyihalarda yetarli, lekin loyiha kattalashgach bu **sekin** va **ishonchsiz** bo'lib qoladi (har safar hamma narsani qo'lda qayta tekshirish kerak). **Avtomatik testlar** — kodning to'g'ri ishlashini bir necha soniyada, avtomatik va takrorlanuvchan tarzda tekshirish imkonini beradi.

### `pytest` — o'rnatish va birinchi test

```bash
pip install pytest    # (venv faol bo'lganda)
```

`kalkulyator.py`:

```python
def qosh(a, b):
    return a + b

def bol(a, b):
    if b == 0:
        raise ValueError("Nolga bo'lish mumkin emas")
    return a / b
```

`test_kalkulyator.py` — test fayllari **har doim** `test_` prefiksi bilan boshlanishi kerak (pytest'ning avtomatik topish qoidasi):

```python
from kalkulyator import qosh, bol
import pytest


def test_qosh():
    assert qosh(2, 3) == 5
    assert qosh(-1, 1) == 0
    assert qosh(0, 0) == 0


def test_bol():
    assert bol(10, 2) == 5
    assert bol(7, 2) == 3.5


def test_bol_nolga():
    with pytest.raises(ValueError):    # bu blok ValueError kutadi
        bol(10, 0)
```

Testlarni ishga tushirish:

```bash
pytest                    # joriy papkadagi barcha test_*.py fayllarni topib, ishga tushiradi
pytest -v                  # batafsil (verbose) natija
pytest test_kalkulyator.py  # faqat bitta faylni tekshirish
```

Natija:

```
test_kalkulyator.py::test_qosh PASSED
test_kalkulyator.py::test_bol PASSED
test_kalkulyator.py::test_bol_nolga PASSED

3 passed in 0.02s
```

### `assert` — testning yuragi

`assert ifoda` — agar `ifoda` `False` bo'lsa, `AssertionError` ko'taradi va test **muvaffaqiyatsiz (FAILED)** deb belgilanadi:

```python
def test_royxat_tartibi():
    royxat = sorted([3, 1, 2])
    assert royxat == [1, 2, 3]          # tenglikni tekshirish
    assert len(royxat) == 3               # uzunlikni tekshirish
    assert 2 in royxat                     # qatnashishni tekshirish
    assert royxat[0] < royxat[-1]           # taqqoslashni tekshirish
```

### Fixture — testlar uchun umumiy tayyorgarlik

Ko'p testlar bir xil "boshlang'ich holat"ga muhtoj bo'ladi (masalan, bir xil obyekt yaratish). **Fixture** — buni takrorlanishsiz, avtomatik ta'minlaydi:

```python
import pytest


class Savat:
    def __init__(self):
        self.mahsulotlar = {}

    def qosh(self, nom, narx):
        self.mahsulotlar[nom] = narx

    def jami(self):
        return sum(self.mahsulotlar.values())


@pytest.fixture
def bosh_savat():
    """Har bir test uchun YANGI, bo'sh Savat obyektini beradi."""
    return Savat()


def test_bosh_savat_jami_nol(bosh_savat):     # fixture nomi argument sifatida "so'raladi"
    assert bosh_savat.jami() == 0


def test_savatga_qoshish(bosh_savat):
    bosh_savat.qosh("Noutbuk", 8500000)
    assert bosh_savat.jami() == 8500000


def test_savatga_bir_nechta_qoshish(bosh_savat):
    bosh_savat.qosh("Noutbuk", 8500000)
    bosh_savat.qosh("Sichqoncha", 150000)
    assert bosh_savat.jami() == 8650000
```

Diqqat qiling: `bosh_savat` funksiyasi har bir test uchun **qaytadan** chaqiriladi — shuning uchun testlar bir-biriga ta'sir qilmaydi (har biri o'zining "toza" `Savat` obyekti bilan boshlaydi).

### Parametrlangan testlar — bitta test, ko'p holat

```python
import pytest
from kalkulyator import qosh


@pytest.mark.parametrize("a, b, kutilgan", [
    (2, 3, 5),
    (-1, 1, 0),
    (0, 0, 0),
    (100, 200, 300),
    (-5, -5, -10),
])
def test_qosh_turli_holatlar(a, b, kutilgan):
    assert qosh(a, b) == kutilgan
```

`@pytest.mark.parametrize` — bitta test funksiyasini **bir nechta** ma'lumot to'plami bilan avtomatik qayta-qayta ishga tushiradi (yuqoridagi misolda — 5 marta, har biri alohida natija bilan), bu kod takrorlanishining oldini oladi.

### `logging` — `print()`ning professional o'rnini bosuvchisi

Kichik skriptlarda `print()` yetarli, lekin real loyihalarda **`logging`** moduli ishlatiladi — u xabarlarni darajalarga (level) ajratadi, vaqt belgisi qo'yadi va faylga yozishni avtomatlashtiradi:

```python
import logging

logging.basicConfig(
    level=logging.INFO,        # shu darajadan yuqori xabarlar ko'rsatiladi
    format="%(asctime)s - %(levelname)s - %(message)s"
)

logging.debug("Bu DEBUG xabari — odatda ko'rinmaydi (level=INFO dan past)")
logging.info("Dastur ishga tushdi")
logging.warning("Diqqat: balans kam qoldi")
logging.error("Xato: fayl topilmadi")
logging.critical("Jiddiy xato: baza bilan aloqa uzildi")
```

Natija (`level=logging.INFO` bilan `DEBUG` ko'rinmaydi):

```
2026-08-18 10:30:15,123 - INFO - Dastur ishga tushdi
2026-08-18 10:30:15,124 - WARNING - Diqqat: balans kam qoldi
2026-08-18 10:30:15,125 - ERROR - Xato: fayl topilmadi
2026-08-18 10:30:15,126 - CRITICAL - Jiddiy xato: baza bilan aloqa uzildi
```

### Log darajalari — qachon qaysi birini ishlatish

| Daraja | Qachon ishlatiladi |
|---|---|
| `DEBUG` | Faqat dasturchi uchun, batafsil texnik ma'lumot (development paytida) |
| `INFO` | Oddiy, kutilgan hodisalar ("foydalanuvchi tizimga kirdi") |
| `WARNING` | Muammo emas, lekin diqqatga loyiq ("kesh eskirgan") |
| `ERROR` | Muammo yuz berdi, lekin dastur davom eta oladi |
| `CRITICAL` | Jiddiy muammo, dastur ishlashi xavf ostida |

### Logni faylga yozish

```python
import logging

logging.basicConfig(
    level=logging.INFO,
    filename="dastur.log",     # konsol o'rniga faylga yoziladi
    filemode="a",                 # "a" — qo'shish, "w" — har safar tozalab yozish
    format="%(asctime)s - %(levelname)s - %(message)s"
)

logging.info("Bu xabar dastur.log fayliga yoziladi")
```

## Amaliy misol

To'liq misol — test qilinadigan modul va uning testlari, `logging` bilan birga:

```python
# banka.py
import logging

logging.basicConfig(level=logging.INFO, format="%(asctime)s - %(levelname)s - %(message)s")
logger = logging.getLogger(__name__)


class BankHisobi:
    def __init__(self, egasi, balans=0):
        self.egasi = egasi
        self.balans = balans

    def toldirish(self, summa):
        if summa <= 0:
            raise ValueError("Summa musbat bo'lishi kerak")
        self.balans += summa
        logger.info(f"{self.egasi} hisobi {summa} so'mga to'ldirildi")
        return self.balans

    def yechish(self, summa):
        if summa > self.balans:
            logger.warning(f"{self.egasi} yetarsiz mablag' bilan yechishga urindi: {summa}")
            raise ValueError("Yetarli mablag' yo'q")
        self.balans -= summa
        logger.info(f"{self.egasi} hisobidan {summa} so'm yechildi")
        return self.balans
```

```python
# tests/test_banka.py
import pytest
from banka import BankHisobi


@pytest.fixture
def hisob():
    return BankHisobi("Ali", balans=100000)


def test_toldirish(hisob):
    yangi_balans = hisob.toldirish(50000)
    assert yangi_balans == 150000


def test_yechish(hisob):
    yangi_balans = hisob.yechish(30000)
    assert yangi_balans == 70000


def test_yetarsiz_mablag(hisob):
    with pytest.raises(ValueError):
        hisob.yechish(200000)


@pytest.mark.parametrize("summa", [-100, 0])
def test_notogri_toldirish_summasi(hisob, summa):
    with pytest.raises(ValueError):
        hisob.toldirish(summa)
```

## Keng tarqalgan xatolar

**Xato 1:** test fayl/funksiya nomlarini `test_` prefiksisiz yozish.
❌ `funksiyalarim_test.py` yoki `def kalkulyator_tekshiruv():` — pytest bularni **avtomatik topmaydi**, chunki standart qoida — fayl `test_*.py`/`*_test.py`, funksiya `test_*` bilan boshlanishi kerak.
✅ To'g'ri: har doim `test_fayl_nomi.py` va `def test_funksiya_nomi():` konvensiyasiga amal qiling.

**Xato 2:** bitta testda juda ko'p, bog'liq bo'lmagan narsalarni tekshirish.
❌ 
```python
def test_hammasi():
    assert qosh(2, 3) == 5
    assert bol(10, 2) == 5
    assert kutubxona.kitob_qosh(...) 
    # 20 qator davomida turli funksiyalarni tekshirish
```
Agar birinchi `assert` muvaffaqiyatsiz bo'lsa, qolganlari umuman ishga tushmaydi, va test nomi qaysi aniq narsa buzilganini ko'rsatmaydi.
✅ To'g'ri: har bir test funksiyasi **bitta aniq narsani** tekshirsin (`test_qosh_musbat_sonlar`, `test_qosh_manfiy_sonlar` — alohida-alohida).

**Xato 3:** production kodda hamon `print()` bilan debug qilish, `logging`ga o'tmaslik.
❌ Real loyihada `print(f"Xato: {xato}")` — bu konsolga chiqadi, lekin serverda kim uni ko'radi? Qachon yuz berdi? Qanday darajadagi muammo?
✅ To'g'ri: `logging.error(f"Xato: {xato}")` ishlating — bu vaqt belgisi, daraja va (sozlansa) faylga saqlashni avtomatik ta'minlaydi, bu production muhitida muammolarni kuzatish uchun zarur.

## Qisqacha xulosa

`pytest` — Python'da eng ko'p ishlatiladigan testlash freymvorki bo'lib, `assert` orqali kutilgan natijalarni tekshiradi, fixture'lar takroriy tayyorgarlikni umumlashtiradi, `@pytest.mark.parametrize` esa bitta testni ko'p holat bilan avtomatik ishga tushiradi; `logging` moduli — `print()`ning professional o'rnini bosib, xabarlarni darajalarga (`INFO`, `WARNING`, `ERROR`) ajratadi va production muhitida muammolarni kuzatishni osonlashtiradi — testlash va loglash birgalikda, kodning ishonchliligini va uzoq muddatli qo'llab-quvvatlanishini ta'minlovchi ikkita asosiy professional amaliyot hisoblanadi.
