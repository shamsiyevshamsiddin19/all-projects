# Virtual muhit va paket boshqaruvi (pip, uv)

## Bu darsda nimalarni o'rganasiz

- `pip` yordamida tashqi kutubxonalarni o'rnatish va boshqarishni bilasiz
- `requirements.txt` fayli nima uchun kerakligini tushunasiz
- **`uv`** — 2025-2026 yillarda tez ommalashgan zamonaviy paket menejeridan foydalana olasiz
- Loyihani boshqa kompyuterda qayta tiklash (reproduce) jarayonini tushuntira olasiz

## Nazariy qism

### `pip` — Python'ning standart paket menejeri

`pip` — Python paketlarini PyPI (Python Package Index) dan yuklab olish va o'rnatish vositasi. `0.1`-darsda ko'rganimizdek, Ubuntu'da u `python3-pip` paketi orqali o'rnatiladi.

```bash
# venv faollashtirilgan holatda:
pip install requests           # bitta kutubxona o'rnatish
pip install requests==2.31.0    # aniq versiyani o'rnatish
pip install requests django      # bir nechtasini birga
pip install --upgrade requests   # mavjudini yangilash
pip uninstall requests            # o'rnatilganni o'chirish
pip list                           # o'rnatilgan barcha paketlarni ko'rish
pip show requests                  # bitta paket haqida batafsil ma'lumot
```

### `requirements.txt` — loyiha bog'liqliklarini saqlash

Har bir jiddiy Python loyihasi o'zining kerakli kutubxonalari ro'yxatini saqlaydi, shunda boshqa kompyuterda (yoki serverda) ularni bir buyruq bilan o'rnatish mumkin bo'ladi:

```bash
pip freeze > requirements.txt    # hozirgi o'rnatilgan paketlarni faylga yozish
```

`requirements.txt` fayli namunasi:

```
requests==2.31.0
django==5.0.1
python-dotenv==1.0.0
```

Boshqa kompyuterda (yoki jamoadosh) loyihani "tiklash":

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt    # -r fayldagi barcha paketlarni o'rnatadi
```

### `uv` — zamonaviy, tez paket va loyiha menejeri

**`uv`** — Rust tilida yozilgan, `pip`+`venv`+`pip-tools` vazifalarini birlashtirgan, sezilarli darajada tezroq ishlaydigan zamonaviy vosita bo'lib, 2024-2025 yillarda Python jamoasida keng tarqaldi. Ubuntu'da o'rnatish:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

O'rnatishni tekshirish:

```bash
uv --version
```

`uv`ning asosiy buyruqlari:

```bash
uv init mening_loyiham      # yangi loyiha yaratish (pyproject.toml bilan)
cd mening_loyiham

uv add requests               # kutubxona qo'shish (avtomatik venv yaratadi va boshqaradi)
uv add django==5.0.1           # aniq versiya bilan

uv run main.py                  # venv'ni faollashtirmasdan, to'g'ridan-to'g'ri ishga tushirish
uv sync                          # pyproject.toml/uv.lock asosida barcha bog'liqliklarni o'rnatish

uv remove requests                # kutubxonani olib tashlash
```

### `uv` va an'anaviy `pip`+`venv` — taqqoslash

| Xususiyat | `pip` + `venv` | `uv` |
|---|---|---|
| Tezlik | Standart | 10-100 marta tezroq (Rust'da yozilgan) |
| Venv boshqaruvi | Qo'lda (`python3 -m venv`) | Avtomatik |
| Bog'liqliklar fayli | `requirements.txt` (qo'lda yangilanadi) | `pyproject.toml` + `uv.lock` (avtomatik) |
| O'rnatilganlik | Python bilan birga keladi | Alohida o'rnatish kerak |
| Jamoadagi barqarorlik | O'rtacha (versiyalar mos kelmasligi mumkin) | Yuqori (`uv.lock` aniq versiyalarni qotiradi) |

> 📌 **Bu kursda qaysi birini ishlatamiz:** ushbu kursning barcha keyingi darslarida (ayniqsa 4-6-boblarda) asosiy, hamma joyda ishlaydigan **`pip` + `venv`** ko'rsatiladi, chunki bu — har qanday Python o'rnatilgan tizimda ishlaydigan universal usul. Ammo `uv` — 2026-yilda tobora ko'proq loyihada standart bo'lib borayotgani uchun, uni bilish va o'z shaxsiy loyihalaringizda ishlatish tavsiya etiladi — ikkalasi ham bir xil natijaga (kutubxonalar to'g'ri o'rnatilgan, izolyatsiya qilingan muhit) olib keladi.

### `pyproject.toml` — zamonaviy loyiha konfiguratsiyasi

`uv init` yaratadigan asosiy fayl:

```toml
[project]
name = "mening-loyiham"
version = "0.1.0"
description = "Mening birinchi loyiham"
requires-python = ">=3.12"
dependencies = [
    "requests>=2.31.0",
]
```

Bu fayl — nafaqat bog'liqliklarni, balki loyiha nomi, versiyasi va Python talab qilinadigan versiyasini ham bitta joyda saqlaydi (bu — `setup.py`/`requirements.txt` kombinatsiyasining zamonaviy, birlashtirilgan o'rnini bosuvchi standart, PEP 621 asosida).

## Amaliy misol

To'liq loyiha boshlash jarayoni — ikkala usul bilan:

**1-usul: an'anaviy `pip` + `venv`**

```bash
mkdir ob-havo-dasturi
cd ob-havo-dasturi
python3 -m venv venv
source venv/bin/activate
pip install requests python-dotenv
pip freeze > requirements.txt
```

`main.py`:

```python
import requests

javob = requests.get("https://api.github.com")
print(javob.status_code)    # 200
```

**2-usul: `uv` bilan**

```bash
uv init ob-havo-dasturi
cd ob-havo-dasturi
uv add requests python-dotenv
uv run main.py
```

Ikkala usulda ham natija bir xil — `requests` kutubxonasi izolyatsiya qilingan muhitda o'rnatiladi va loyiha ishga tushadi, farqi — `uv` buyruqlari kamroq va tezroq.

## Keng tarqalgan xatolar

**Xato 1:** `pip install`ni venv faollashtirmasdan bajarish.
❌ Venv faollashtirilmagan holda `pip install django` — Django kompyuterning global Python muhitiga o'rnatiladi (0.1-darsda ko'rgan muammo).
✅ To'g'ri: har doim avval `source venv/bin/activate`, terminalda `(venv)` yozuvini ko'rgach, keyin `pip install` qiling. `uv` bilan bu muammo avtomatik oldini olinadi, chunki `uv add`/`uv run` o'zi venv'ni boshqaradi.

**Xato 2:** `requirements.txt`ni loyihaga qo'shishni (Git'ga commit qilishni) unutish.
❌ Loyiha boshqa kompyuterga ko'chirilganda, `requirements.txt` fayli topilmay, qaysi kutubxonalar kerakligi noma'lum bo'lib qoladi.
✅ To'g'ri: `requirements.txt` (yoki `pyproject.toml`/`uv.lock`) har doim loyihaning bir qismi sifatida saqlanishi va Git'ga qo'shilishi kerak — faqat `venv/` papkasining o'zi Git'ga qo'shilmasligi kerak (`.gitignore` orqali).

**Xato 3:** versiya raqamlarini butunlay e'tiborsiz qoldirish.
❌ `requirements.txt`da faqat `django` (versiyasiz) yozilsa, boshqa kompyuterda `pip install -r requirements.txt` **eng yangi** Django versiyasini o'rnatishi mumkin, bu esa loyihada kutilmagan xatolarga olib kelishi mumkin (agar loyiha eski versiyaga mo'ljallangan bo'lsa).
✅ To'g'ri: `pip freeze > requirements.txt` orqali aniq versiyalarni qotiring (`django==5.0.1`), yoki `uv`ning `uv.lock` fayliga tayaning — u avtomatik aniq versiyalarni saqlaydi.

## Mashq/topshiriq

**(Oson)** Yangi papka yarating, `venv` bilan virtual muhit tuzing, `requests` kutubxonasini o'rnating va `pip freeze > requirements.txt` orqali faylga yozib, uning tarkibini ko'ring.

**(O'rtacha)** `uv`ni Ubuntu'ga o'rnating (agar hali o'rnatilmagan bo'lsa) va `uv init` orqali yangi loyiha yarating, unga `requests` qo'shing va `uv run` orqali oddiy `import requests; print("ishladi")` kodini ishga tushiring.

**(Qiyin)** Ikkita alohida papkada ikkita loyiha yarating: birida `requests==2.28.0`, ikkinchisida `requests==2.31.0` o'rnating (`pip install requests==versiya`). Har birida `import requests; print(requests.__version__)` ishga tushirib, ular bir-biriga ta'sir qilmasligini isbotlang va nega bu mumkin ekanini (venv izolyatsiyasi) tushuntirib bering.

1. `python3 -m venv venv && source venv/bin/activate && pip install requests && pip freeze > requirements.txt` — fayl ichida `requests==<versiya>` va uning bog'liqliklari (`certifi`, `urllib3` va h.k.) ko'rinadi.
2. `curl -LsSf https://astral.sh/uv/install.sh | sh`, so'ng `uv init test_loyiha && cd test_loyiha && uv add requests`, `main.py`ga kod yozib `uv run main.py`.
3. Ikkala papkada alohida `venv` yaratib, mos versiyalarni o'rnatgach, har birida `requests.__version__` mos ravishda `2.28.0` va `2.31.0` chiqadi — chunki har bir `venv` o'zining alohida `site-packages` papkasiga ega, ular bir-biridan butunlay izolyatsiya qilingan (0.1-darsda ko'rgan tushuncha).

## Qisqacha xulosa

`pip` — Python'ning standart paket menejeri bo'lib, `requirements.txt` orqali loyiha bog'liqliklarini saqlaydi va boshqa muhitda qayta tiklash imkonini beradi; **`uv`** — 2025-2026 yillarda ommalashgan, sezilarli tezroq, venv boshqaruvini avtomatlashtiruvchi zamonaviy alternativa bo'lib, `pyproject.toml`/`uv.lock` orqali yanada barqaror bog'liqlik boshqaruvini ta'minlaydi; ikkalasini ham bilish — zamonaviy Python dasturchisi uchun muhim, chunki turli loyihalar turli vositalardan foydalanishi mumkin.
