# Meros (inheritance) va super()

## Bu darsda nimalarni o'rganasiz

- Klasslar orasida meros (inheritance) o'rnata olasiz
- `super()` funksiyasining vazifasini va qachon kerakligini tushuntira olasiz
- Metodlarni **override** (qayta aniqlash) qila olasiz
- Ko'p darajali va ko'p ota-klassli merosni tushunasiz

## Nazariy qism

### Meros nima uchun kerak

**Meros** (inheritance) — bir klass (bola/child) boshqa klassning (ota/parent) atribut va metodlarini "meros qilib olishi". Bu — umumiy kod takrorlanishining oldini oladi:

```python
class Hayvon:
    def __init__(self, ism):
        self.ism = ism

    def yer(self):
        print(f"{self.ism} ovqatlanmoqda")

    def uxlaydi(self):
        print(f"{self.ism} uxlamoqda")


class It(Hayvon):     # It — Hayvon'dan meros oladi
    def hurish(self):
        print(f"{self.ism}: Vov-vov!")


class Mushuk(Hayvon):  # Mushuk ham Hayvon'dan meros oladi
    def miyovlash(self):
        print(f"{self.ism}: Miyov!")


it1 = It("Aka")
it1.yer()          # Hayvon'dan meros olingan metod — Aka ovqatlanmoqda
it1.hurish()        # It'ning o'z metodi — Aka: Vov-vov!

mushuk1 = Mushuk("Pushti")
mushuk1.uxlaydi()    # Hayvon'dan meros olingan — Pushti uxlamoqda
mushuk1.miyovlash()  # Mushuk: Miyov!
```

`It(Hayvon)` — qavs ichidagi `Hayvon` — `It` klassi `Hayvon`dan meros olishini bildiradi. `It` va `Mushuk` — `Hayvon`ning barcha metodlarini (`yer`, `uxlaydi`) **avtomatik** oladi, va o'zlarining qo'shimcha metodlarini ham qo'shishi mumkin.

### `super()` — ota klassga murojaat qilish

```python
class Hayvon:
    def __init__(self, ism, yosh):
        self.ism = ism
        self.yosh = yosh

    def malumot(self):
        return f"{self.ism}, {self.yosh} yoshda"


class It(Hayvon):
    def __init__(self, ism, yosh, zoti):
        super().__init__(ism, yosh)   # Hayvon.__init__ ni chaqiradi — ism va yoshni o'rnatadi
        self.zoti = zoti                # It'ga xos qo'shimcha atribut

    def malumot(self):
        asosiy = super().malumot()     # Hayvon'ning malumot() natijasini oladi
        return f"{asosiy}, zoti: {self.zoti}"


it1 = It("Aka", 3, "Nemis cho'poni")
print(it1.malumot())    # Aka, 3 yoshda, zoti: Nemis cho'poni
```

`super()` — ota klassning metodiga murojaat qilish imkonini beradi, bu ayniqsa `__init__`ni **qayta yozish** (override) o'rniga **kengaytirish** kerak bo'lganda muhim — ota klassning kodi takrorlanmaydi.

> ⚠️ **`super().__init__()`ni unutmang.** Agar bola klass o'z `__init__`ini yozsa-yu, `super().__init__()`ni chaqirmasa, ota klassning `__init__`i **umuman ishlamaydi** — ota klass o'rnatgan atributlar (masalan, `self.ism`) mavjud bo'lmay qoladi.

### Metodni override qilish (qayta aniqlash)

```python
class Hayvon:
    def ovoz_chiqar(self):
        print("Hayvon ovoz chiqarmoqda...")


class It(Hayvon):
    def ovoz_chiqar(self):     # ota klassdagi metod QAYTA ANIQLANDI (override)
        print("Vov-vov!")


class Mushuk(Hayvon):
    def ovoz_chiqar(self):
        print("Miyov!")


hayvonlar = [Hayvon(), It(), Mushuk()]
for hayvon in hayvonlar:
    hayvon.ovoz_chiqar()
# Hayvon ovoz chiqarmoqda...
# Vov-vov!
# Miyov!
```

Bu — **polimorfizm**ning oddiy namunasi (4.3-darsda batafsil ko'riladi): bir xil metod nomi (`ovoz_chiqar`) turli klasslarda turlicha ishlaydi.

### Ko'p darajali meros (multilevel inheritance)

```python
class Transport:
    def __init__(self, marka):
        self.marka = marka

    def harakatlan(self):
        print(f"{self.marka} harakatlanmoqda")


class Mashina(Transport):
    def signal_ber(self):
        print("Bip-bip!")


class SportMashina(Mashina):    # SportMashina -> Mashina -> Transport
    def tez_yur(self):
        print(f"{self.marka} juda tez ketmoqda!")


ferrari = SportMashina("Ferrari")
ferrari.harakatlan()    # Transport'dan (2 daraja yuqoridan)
ferrari.signal_ber()     # Mashina'dan (1 daraja yuqoridan)
ferrari.tez_yur()         # o'zining metodi
```

### `isinstance()` va `issubclass()` — meros munosabatlarini tekshirish

```python
print(isinstance(ferrari, SportMashina))   # True
print(isinstance(ferrari, Mashina))          # True — SportMashina Mashina'dan meros oladi
print(isinstance(ferrari, Transport))         # True — ko'p darajali meros orqali ham
print(isinstance(ferrari, str))                # False

print(issubclass(SportMashina, Transport))    # True — klasslar orasidagi munosabat
print(issubclass(Mashina, SportMashina))       # False — teskarisi to'g'ri emas
```

### Ko'p ota-klassli meros (multiple inheritance) — qisqacha

Python — bir vaqtning o'zida bir nechta klassdan meros olishga (`class Bola(Ota1, Ota2):`) ruxsat beradi:

```python
class Uchuvchi:
    def uch(self):
        print("Uchmoqda")


class Suzuvchi:
    def suz(self):
        print("Suzmoqda")


class Ordak(Uchuvchi, Suzuvchi):    # ikkala klassdan ham meros oladi
    pass


ordak = Ordak()
ordak.uch()    # Uchmoqda
ordak.suz()     # Suzmoqda
```

> 📌 **Amaliy maslahat:** ko'p ota-klassli meros kuchli, lekin murakkab tuzilmalarda MRO (Method Resolution Order — metod qidirish tartibi) chalkash bo'lib qolishi mumkin. Amaliyotda ko'pincha oddiyroq alternativalar (masalan, "composition" — bir klass ichida boshqa klass obyektini atribut sifatida saqlash) afzalroq hisoblanadi. Bu kursda asosan **oddiy, bitta ota-klassli** meros ishlatiladi.

## Amaliy misol

Xodimlar tizimi — meros orqali:

```python
# xodimlar.py

class Xodim:
    def __init__(self, ism, oylik_maosh):
        self.ism = ism
        self.oylik_maosh = oylik_maosh

    def maosh_hisobla(self):
        return self.oylik_maosh

    def __str__(self):
        return f"{self.ism}: {self.maosh_hisobla():,.0f} so'm"


class Menejer(Xodim):
    def __init__(self, ism, oylik_maosh, bonus_foizi):
        super().__init__(ism, oylik_maosh)
        self.bonus_foizi = bonus_foizi

    def maosh_hisobla(self):     # override — bonus qo'shib hisoblaydi
        asosiy = super().maosh_hisobla()
        bonus = asosiy * self.bonus_foizi / 100
        return asosiy + bonus


class Stajyor(Xodim):
    def __init__(self, ism, oylik_maosh):
        super().__init__(ism, oylik_maosh)

    def maosh_hisobla(self):     # override — stajyorlar maoshining 70% ini oladi (sinov muddati)
        return super().maosh_hisobla() * 0.7


xodimlar = [
    Xodim("Ali", 5000000),
    Menejer("Vali", 8000000, bonus_foizi=15),
    Stajyor("Guli", 3000000),
]

for xodim in xodimlar:
    print(xodim)     # __str__ har biri uchun mos maosh_hisobla()ni chaqiradi

jami = sum(xodim.maosh_hisobla() for xodim in xodimlar)
print(f"\nJami oylik xarajat: {jami:,.0f} so'm")
```

Bu misol — polimorfizmning kuchini ko'rsatadi: `for xodim in xodimlar:` sikli har bir xodim turi uchun **to'g'ri** `maosh_hisobla()` metodini avtomatik chaqiradi, garchi tashqi ko'rinishda bir xil kod yozilgan bo'lsa ham.

## Keng tarqalgan xatolar

**Xato 1:** `super().__init__()`ni chaqirishni unutish.
❌ 
```python
class Menejer(Xodim):
    def __init__(self, ism, oylik_maosh, bonus_foizi):
        self.bonus_foizi = bonus_foizi   # super().__init__() yo'q!
```
Bu holda `menejer1.ism` yoki `menejer1.oylik_maosh` — `AttributeError` beradi, chunki `Xodim.__init__` hech qachon chaqirilmagan.
✅ To'g'ri: har doim bola klassning `__init__`i boshida (yoki kerakli joyida) `super().__init__(...)`ni chaqiring.

**Xato 2:** ota klassning metodini butunlay "unutib", ortiqcha meros zanjiri qurish.
❌ Har bir kichik farq uchun yangi klass yaratish (masalan, `KattaIt`, `KichikIt`, `OrtaIt`) — bu meros zanjirini keraksiz murakkablashtiradi.
✅ To'g'ri: agar farq shunchaki bir atribut qiymati bo'lsa (masalan, o'lcham), buni alohida klass emas, oddiy `__init__` argumenti sifatida bering — meros faqat xatti-harakat (metodlar) haqiqatan farq qilganda ishlatilsin.

**Xato 3:** `isinstance()` o'rniga `type() == `dan foydalanish (meros zanjirini hisobga olmaslik).
❌ `if type(hayvon) == Hayvon:` — bu `It` yoki `Mushuk` obyektlarini **hisobga olmaydi**, faqat aniq `Hayvon` klassining o'zini tekshiradi.
✅ To'g'ri: meros zanjirini hisobga olgan holda tekshirish uchun `isinstance(hayvon, Hayvon)` ishlating — bu `It`, `Mushuk` va boshqa barcha avlod klasslar uchun ham `True` qaytaradi.

## Mashq/topshiriq

**(Oson)** `Shakl` klassini yarating (`nomi` atributi bilan), so'ng `Doira(Shakl)` klassini yarating (`radius` bilan) — `super()` orqali `nomi="Doira"`ni ota klassga uzating.

**(O'rtacha)** `Kitob` klassini (`nom`, `muallif`) va undan meros oluvchi `ElektronKitob(Kitob)` klassini (`fayl_hajmi_mb` qo'shimcha atributi bilan) yarating; `ElektronKitob`da `__str__`ni override qilib, oddiy `Kitob.__str__`ga (agar u mavjud bo'lsa, `super()` orqali) fayl hajmini ham qo'shib chiqaring.

**(Qiyin)** `To'lovUsuli` ota klassini yarating — `summa_hisobla(self, asl_summa)` metodi bilan (standart holda hech qanday chegirma qo'shmaydi, `asl_summa`ni qaytaradi). Undan uchta klass hosil qiling: `NaqdTolov` (5% chegirma), `KartaTolov` (2% qo'shimcha komissiya), `KreditTolov` (10% qo'shimcha foiz) — har biri `summa_hisobla`ni override qilsin. Ro'yxatdagi turli to'lov usullari uchun umumiy summani hisoblang.

## Qisqacha xulosa

Meros (`class Bola(Ota):`) — umumiy atribut va metodlarni ota klassdan bola klasslarga o'tkazish, kod takrorlanishining oldini olish imkonini beradi; `super()` — ota klassning metodlariga (ayniqsa `__init__`ga) murojaat qilish uchun ishlatiladi, override esa — bola klassda ota klassning metodini o'ziga xos tarzda qayta yozish; `isinstance()`/`issubclass()` — meros munosabatlarini tekshiradi — bu vositalar birgalikda katta, tuzilmalashgan dasturlarni yaratishning asosini tashkil qiladi.
