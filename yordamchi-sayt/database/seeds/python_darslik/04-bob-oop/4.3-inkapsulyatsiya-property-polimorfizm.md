# Inkapsulyatsiya, property va polimorfizm

## Bu darsda nimalarni o'rganasiz

- Inkapsulyatsiya (data hiding) tushunchasini va Python'dagi konvensiyalarini tushunasiz
- `@property` dekoratori orqali "hisoblangan atribut" yarata olasiz
- Setter va getter'larni Python uslubida to'g'ri yoza olasiz
- Polimorfizm nima ekanini va uning amaliy afzalligini tushuntira olasiz

## Nazariy qism

### Inkapsulyatsiya — Python'da qanday amalga oshiriladi

**Inkapsulyatsiya** — obyektning ichki holatini tashqi, nazoratsiz o'zgartirishlardan himoya qilish. Ko'p tillarda (Java, C++) bu `private`/`public` kalit so'zlari orqali qat'iy amalga oshiriladi. Python'da esa **konvensiyaga asoslangan** yondashuv ishlatiladi:

| Belgi | Ma'nosi | Misol |
|---|---|---|
| `nom` | Ochiq (public) — erkin ishlatilishi mumkin | `self.ism` |
| `_nom` | "Ichki" (protected) — konvensiya bo'yicha tashqaridan ishlatilmasin | `self._balans` |
| `__nom` | "Kuchli ichki" (name mangling orqali) — tasodifan qayta yozilishdan himoyalanadi | `self.__parol` |

```python
class BankHisobi:
    def __init__(self, egasi, balans):
        self.egasi = egasi          # public
        self._balans = balans        # "ichki" — to'g'ridan-to'g'ri o'zgartirilmasin degan signal
        self.__pin_kod = "0000"      # "kuchli ichki" — name mangling qo'llaniladi

hisob = BankHisobi("Ali", 100000)
print(hisob._balans)          # ishlaydi, lekin konvensiyaga zid (ogohlantirish, xato emas)
print(hisob.__pin_kod)         # AttributeError! chunki aslida __pin_kod -> _BankHisobi__pin_kod ga aylantiriladi
print(hisob._BankHisobi__pin_kod)   # bu ishlaydi (name mangling qanday ishlashini ko'rsatish uchun)
```

> 📌 **Muhim tushuncha:** Python'da haqiqiy "private" mavjud emas — `__` bilan boshlash faqat tasodifiy nom to'qnashuvlarining oldini oladi (name mangling), qat'iy himoya emas. Python falsafasi: *"We are all consenting adults here"* — dasturchilar bir-biriga ishonadi, shuning uchun qat'iy cheklashdan ko'ra, **aniq konvensiya** (bitta `_`) yetarli hisoblanadi.

### `@property` — metodni atribut kabi ko'rsatish

```python
class Toifa:
    def __init__(self, narx):
        self._narx = narx

    @property
    def narx(self):          # bu METOD, lekin OBYEKT.narx ko'rinishida chaqiriladi (qavssiz!)
        return self._narx

    @narx.setter
    def narx(self, yangi_narx):
        if yangi_narx < 0:
            raise ValueError("Narx manfiy bo'lishi mumkin emas!")
        self._narx = yangi_narx


mahsulot = Toifa(50000)
print(mahsulot.narx)      # 50000 — metod chaqirilmoqda, lekin oddiy atribut kabi ko'rinadi (qavssiz)

mahsulot.narx = 60000      # setter ishlaydi — tekshiruvdan o'tadi
print(mahsulot.narx)       # 60000

mahsulot.narx = -100        # ValueError: Narx manfiy bo'lishi mumkin emas!
```

`@property` — Python'ning eng qulay xususiyatlaridan biri: u tashqi kod uchun **oddiy atributga o'xshab ko'rinadigan**, lekin ichida validatsiya yoki hisoblash mantig'i bo'lgan "aqlli atribut" yaratish imkonini beradi. Tashqi kod `mahsulot.narx = 60000` yozadi (metod chaqirayotganini bilmasdan ham), lekin aslida `@narx.setter` bilan belgilangan tekshiruv ishlab ketadi.

### Faqat o'qish uchun (read-only) property — hisoblangan qiymat

```python
class Toʻrtburchak:
    def __init__(self, uzunlik, kenglik):
        self.uzunlik = uzunlik
        self.kenglik = kenglik

    @property
    def yuza(self):            # setter YO'Q — faqat o'qish uchun
        return self.uzunlik * self.kenglik

    @property
    def perimetr(self):
        return 2 * (self.uzunlik + self.kenglik)


toshbaqa = Toʻrtburchak(5, 3)
print(toshbaqa.yuza)         # 15 — har safar avtomatik qayta hisoblanadi
toshbaqa.uzunlik = 10
print(toshbaqa.yuza)         # 30 — o'zgargan uzunlikka mos yangilangan

toshbaqa.yuza = 100           # AttributeError: can't set attribute (setter yo'q!)
```

Bu — `yuza` va `perimetr`ni har safar qo'lda hisoblab, alohida metod (`hisobla_yuza()`) chaqirish o'rniga, ularni **doimo yangilangan, faqat o'qiladigan atribut** sifatida taqdim etadi.

### Polimorfizm — "bir xil interfeys, turli natija"

**Polimorfizm** (ko'p shakllilik) — bir xil metod nomi turli klasslarda turlicha ishlashi (4.2-darsda `ovoz_chiqar()` misolida ko'rgan edik). Buning amaliy kuchi — bir xil kodning turli obyekt turlari bilan ishlashi mumkinligida:

```python
class Toʻrtburchak:
    def __init__(self, uzunlik, kenglik):
        self.uzunlik, self.kenglik = uzunlik, kenglik

    def yuza(self):
        return self.uzunlik * self.kenglik


class Doira:
    def __init__(self, radius):
        self.radius = radius

    def yuza(self):
        return 3.14159 * self.radius ** 2


class Uchburchak:
    def __init__(self, asos, balandlik):
        self.asos, self.balandlik = asos, balandlik

    def yuza(self):
        return 0.5 * self.asos * self.balandlik


shakllar = [Toʻrtburchak(4, 5), Doira(3), Uchburchak(6, 4)]

# Bu sikl shakllarning ANIQ turini bilishi shart EMAS — har biri o'zining yuza() metodiga ega
jami_yuza = 0
for shakl in shakllar:
    yuza = shakl.yuza()      # polimorfizm — har bir obyekt o'ziga mos yuza() ni chaqiradi
    print(f"{type(shakl).__name__}: {yuza:.2f}")
    jami_yuza += yuza

print(f"Jami yuza: {jami_yuza:.2f}")
```

Bu — polimorfizmning asosiy afzalligi: agar ertaga yangi shakl (`Kvadrat`) qo'shilsa, yuqoridagi sikl kodini **umuman o'zgartirish shart emas** — faqat yangi klass o'zining `yuza()` metodi bilan yozilsa, u avtomatik ishlab ketadi.

### "Duck typing" — Python'ning erkin polimorfizmi

```python
class Ordak:
    def gapir(self):
        return "Kva-kva!"

class Odam:
    def gapir(self):
        return "Salom!"

def kimdir_gapirsin(obyekt):
    print(obyekt.gapir())    # obyektning ANIQ turi muhim emas, faqat gapir() metodi bo'lsa yetarli

kimdir_gapirsin(Ordak())    # Kva-kva!
kimdir_gapirsin(Odam())      # Salom!
```

Bu — **"duck typing"** deb ataladi (*"agar u o'rdakdek yursa va o'rdakdek gapirsa, u o'rdak hisoblanadi"*): Python meros yoki aniq turni talab qilmaydi, faqat kerakli metod mavjud bo'lishi kifoya. Bu Java yoki C#dagi qat'iy interfeys tekshiruviga qaraganda ancha moslashuvchan (lekin ehtiyotsizlik bilan xatolarni kechroq aniqlashi ham mumkin — shuning uchun 5-bobda type hints'ni o'rganamiz, bu muammoni yumshatadi).

## Amaliy misol

Haroratni Selsiy/Farengeyt orasida avtomatik o'giruvchi klass:

```python
# harorat.py

class Harorat:
    def __init__(self, selsiy=0):
        self._selsiy = selsiy

    @property
    def selsiy(self):
        return self._selsiy

    @selsiy.setter
    def selsiy(self, qiymat):
        if qiymat < -273.15:
            raise ValueError("Harorat mutlaq noldan past bo'lishi mumkin emas!")
        self._selsiy = qiymat

    @property
    def farengeyt(self):
        return self._selsiy * 9 / 5 + 32

    @farengeyt.setter
    def farengeyt(self, qiymat):
        self.selsiy = (qiymat - 32) * 5 / 9    # selsiy setter orqali, validatsiya ham ishlaydi


harorat = Harorat(25)
print(f"{harorat.selsiy}°C = {harorat.farengeyt}°F")   # 25°C = 77.0°F

harorat.farengeyt = 100
print(f"{harorat.selsiy:.1f}°C")                          # 37.8°C

harorat.selsiy = -300     # ValueError: Harorat mutlaq noldan past bo'lishi mumkin emas!
```

Diqqat qiling: `farengeyt.setter` ichida `self.selsiy = ...` (property orqali) chaqirilmoqda, `self._selsiy` emas — bu orqali Selsiyning **validatsiyasi** Farengeyt orqali o'rnatilganda ham ishlab ketadi.

## Keng tarqalgan xatolar

**Xato 1:** `@property`ni qavs bilan chaqirishga urinish.
❌ `print(mahsulot.narx())` — `TypeError: 'int' object is not callable`, chunki `@property` bilan belgilangan metod **atribut kabi**, qavssiz chaqiriladi.
✅ To'g'ri: `print(mahsulot.narx)` — hech qanday qavssiz.

**Xato 2:** setter ichida `self._narx` o'rniga `self.narx`ni ishlatib, cheksiz rekursiyaga tushib qolish.
❌ 
```python
@narx.setter
def narx(self, yangi_narx):
    self.narx = yangi_narx    # bu setter'ning O'ZINI qayta chaqiradi — RecursionError!
```
✅ To'g'ri: setter ichida har doim **ichki** o'zgaruvchiga (`self._narx`) murojaat qiling, `self.narx`ga emas.

**Xato 3:** har bir atribut uchun keraksiz `@property` yozish (over-engineering).
❌ Hech qanday validatsiya yoki hisoblash kerak bo'lmagan oddiy atributlar uchun ham `@property` + setter yozish — bu ortiqcha, foydasiz murakkablik qo'shadi.
✅ To'g'ri: `@property`ni faqat haqiqatan **validatsiya**, **hisoblangan qiymat** yoki **atribut o'zgarishini kuzatish** kerak bo'lganda ishlating; oddiy ma'lumot uchun oddiy `self.narx = narx` yetarli.

## Mashq/topshiriq

**(Oson)** `Kub` klassini yarating — `qirra` atributi bilan, va `@property` orqali `hajm` (qirra**3) va `yuza` (6 * qirra**2) hisoblangan atributlarini qo'shing.

**(O'rtacha)** `Foydalanuvchi` klassini yarating — `_email` ichki atributi va `email` property'si bilan, setter ichida email formatini tekshiring (kamida `"@"` belgisi borligini `if "@" not in qiymat: raise ValueError(...)` orqali).

**(Qiyin)** `Chegirma` va `Bonus` nomli ikkita klass yarating, ikkalasida ham `narx_hisobla(self, asl_narx)` metodi bo'lsin (`Chegirma` — 10% kamaytiradi, `Bonus` — narxga 5000 so'm bonus ball qo'shadi, hisoblashda ayiradi). So'ng duck typing yordamida, ro'yxatdagi har xil "kampaniya" obyektlari (ikkalasidan aralash) uchun umumiy yakuniy narxni hisoblovchi funksiya yozing — bu funksiya obyektlarning aniq turini tekshirmasligi kerak.

## Qisqacha xulosa

Python'da inkapsulyatsiya konvensiyaga asoslangan (`_ichki`, `__kuchli_ichki`), qat'iy majburlash o'rniga dasturchilar o'rtasidagi "kelishuv"ga tayanadi; `@property` — metodni oddiy atribut kabi ko'rsatib, validatsiya va hisoblangan qiymatlarni shaffof tarzda joylashtirish imkonini beradi; polimorfizm (va Python'ga xos "duck typing") esa turli klasslar bir xil metod nomiga ega bo'lsa, ularni bitta umumiy kod bilan (aniq turini bilmasdan) ishlatish imkonini beradi — bu uchtasi birgalikda katta, kengaytiriladigan dasturiy tizimlar qurishning asosini tashkil qiladi.
