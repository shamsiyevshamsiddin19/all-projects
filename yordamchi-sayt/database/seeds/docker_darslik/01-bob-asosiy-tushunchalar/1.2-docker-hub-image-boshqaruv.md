# Docker Hub, image qidirish va yuklab olish (pull/push)

## Bu darsda nimalarni o'rganasiz

- Docker Hub nima ekanini va undan qanday foydalanishni bilasiz
- `docker pull`, `docker images`, `docker rmi` buyruqlarini qo'llay olasiz
- Image tag (versiya belgisi) tushunchasini va uning ahamiyatini tushunasiz
- O'z image'ingizni Docker Hub'ga qanday yuklashni (push) tushunasiz

## Nazariy qism

### Docker Hub — image'lar uchun "GitHub"

**Docker Hub** (`hub.docker.com`) — Docker'ning rasmiy, ommaviy **registry**si (0.1-darsda ko'rgan tushuncha) bo'lib, millionlab tayyor image'larni saqlaydi. Bu — dasturchilar uchun GitHub kodga qanday xizmat qilsa, image'larga xuddi shunday xizmat qiladi: siz o'z image'ingizni yuklashingiz (push), boshqalarning image'larini yuklab olishingiz (pull) mumkin.

### Rasmiy va nomukammal (community) image'lar

Docker Hub'da ikki turdagi image'lar mavjud:

| Tur | Tavsif | Misol |
|---|---|---|
| **Rasmiy image'lar (Official Images)** | Docker yoki dastur ishlab chiquvchisi tomonidan rasmiy qo'llab-quvvatlanadigan, tekshirilgan image'lar | `python`, `nginx`, `postgres`, `node` |
| **Community image'lar** | Foydalanuvchilar tomonidan yaratilgan, `foydalanuvchi_nomi/image_nomi` formatida | `bitnami/django`, `someuser/mening-loyiham` |

> ⚠️ **Xavfsizlik bo'yicha maslahat:** production loyihalarda imkon qadar **rasmiy image'larni** ishlating (ular xavfsizlik nuqtai nazaridan muntazam yangilanadi va tekshiriladi). Community image'larni ishlatishdan oldin ularning manba kodini (agar mavjud bo'lsa) va yuklab olishlar sonini tekshirish tavsiya etiladi.

### `docker pull` — image'ni yuklab olish

```bash
docker pull python:3.13
docker pull postgres:16
docker pull nginx:latest
```

`docker pull <image>:<tag>` — image'ni **ishga tushirmasdan**, faqat mahalliy diskka yuklab oladi (0.1-darsda ko'rganimizdek, `docker run` avtomatik `pull`ni ham bajaradi, agar image mahalliy bo'lmasa).

### Tag (versiya belgisi) — nega muhim

**Tag** — image'ning aniq versiyasini bildiradi, `image_nomi:tag` formatida yoziladi:

```bash
docker pull python:3.13          # aniq versiya
docker pull python:3.13-slim      # "slim" — kichraytirilgan, kamroq qo'shimcha dasturlar bilan
docker pull python:latest          # eng so'nggi versiya (tag ko'rsatilmasa, "latest" standart hisoblanadi)
```

| Tag turi | Misol | Tavsif |
|---|---|---|
| Aniq versiya | `python:3.13` | Ma'lum, o'zgarmas versiya — **production uchun tavsiya etiladi** |
| `slim` | `python:3.13-slim` | Kichraytirilgan, faqat zarur qismlar bilan — image hajmini kamaytiradi |
| `alpine` | `python:3.13-alpine` | Alpine Linux asosida — eng kichik hajmli, lekin ba'zi kutubxonalar bilan moslik muammosi bo'lishi mumkin |
| `latest` | `python:latest` | Eng so'nggi versiya — **production'da tavsiya etilmaydi**, chunki versiya kutilmaganda o'zgarib qolishi mumkin |

> ⚠️ **`latest` tag'idan production'da saqlaning.** Agar `Dockerfile`ingizda yoki `docker-compose.yaml`ingizda tag ko'rsatilmasa, Docker avtomatik `latest`ni ishlatadi. Muammo: `latest` — vaqt o'tishi bilan **boshqa versiyaga** ishora qilishi mumkin (masalan, bugun `python:latest` — Python 3.13 bo'lsa, ertaga u Python 3.14'ga yangilanishi mumkin), bu esa loyihangizni kutilmagan tarzda buzishi mumkin. Har doim **aniq versiya** ko'rsating: `python:3.13-slim`.

### Mahalliy image'lar ro'yxatini ko'rish — `docker images`

```bash
docker images
```

Natija:

```
REPOSITORY   TAG        IMAGE ID       CREATED        SIZE
python       3.13-slim  a1b2c3d4e5f6   2 weeks ago    130MB
nginx        latest     f6e5d4c3b2a1   3 weeks ago    187MB
postgres     16         1a2b3c4d5e6f   1 month ago     432MB
```

### Image'ni o'chirish — `docker rmi`

```bash
docker rmi python:3.13-slim
```

> ⚠️ **Diqqat:** agar image asosida yaratilgan konteyner (hatto to'xtatilgan bo'lsa ham) hali mavjud bo'lsa, `docker rmi` xato beradi (`image is being used by stopped container`). Avval bog'liq konteynerlarni (`docker rm`) o'chirish kerak, yoki `docker rmi -f` bilan majburlash mumkin (ehtiyotkorlik bilan).

### Image qidirish

```bash
docker search postgres
```

Bu buyruq terminaldan to'g'ridan-to'g'ri Docker Hub'da qidiradi, lekin amalda ko'pchilik dasturchi brauzer orqali `hub.docker.com` saytida qidirishni afzal ko'radi — u yerda tavsiflar, yulduzchalar (stars) va rasmiy belgisi (`Docker Official Image`) ko'proq ma'lumot beradi.

### O'z image'ingizni Docker Hub'ga yuklash — `docker push`

Bu jarayon — o'z qurgan image'ingizni (2-bobda Dockerfile orqali qurishni ko'ramiz) boshqalar bilan ulashish yoki serverga joylashtirish uchun ishlatiladi:

```bash
# 1. Docker Hub'ga hisobingiz orqali kirish
docker login

# 2. Image'ni Docker Hub formatiga mos qilib "belgilash" (tag qo'yish)
docker tag mening_loyiham foydalanuvchi_nomi/mening_loyiham:1.0

# 3. Docker Hub'ga yuklash
docker push foydalanuvchi_nomi/mening_loyiham:1.0
```

`docker tag` — mavjud image'ga **qo'shimcha nom** beradi (asl image o'zgarmaydi, faqat unga ikkinchi "yorliq" qo'shiladi) — bu Docker Hub'ning talab qiladigan `foydalanuvchi_nomi/image_nomi:tag` formatiga moslashtirish uchun zarur.

### Image'lardan bo'shagan joyni tozalash

```bash
docker image prune          # ISHLATILMAYOTGAN (hech qanday konteyner bilan bog'lanmagan) image'larni o'chiradi
docker image prune -a        # BARCHA ishlatilmayotgan image'larni o'chiradi (hozir hech qanday konteyner ishlatmayotgan)
docker system df              # Docker qancha disk joyini egallaganini ko'rsatadi (image, konteyner, volume bo'yicha)
```

## Amaliy misol

Turli Python versiyalarini solishtirish — hajm va tag farqi:

```bash
# Turli tag'lardagi Python image'larini yuklab olish
docker pull python:3.13
docker pull python:3.13-slim
docker pull python:3.13-alpine

# Hajmlarini solishtirish
docker images python

# Namuna natija:
# REPOSITORY   TAG            SIZE
# python       3.13           1.02GB
# python       3.13-slim       130MB
# python       3.13-alpine      52MB
```

Bu — nega tag tanlovi muhim ekanini aniq ko'rsatadi: `python:3.13` (to'liq versiya) — barcha qo'shimcha kutubxonalar bilan ~1GB, `python:3.13-slim` — faqat zarur qismlar bilan ~130MB, `python:3.13-alpine` esa eng kichik (~52MB), lekin Alpine Linux'ning o'ziga xos xususiyatlari (masalan, `apt` o'rniga `apk`, ba'zi C kutubxonalari bilan moslik muammolari) bo'lishi mumkin.

```bash
# Kichik test konteyneri — turli tag bilan ishga tushirish va versiyani tekshirish
docker run --rm python:3.13-slim python3 --version
docker run --rm python:3.13-alpine python3 --version

# Ishlatilmayotgan image'larni tozalash
docker image prune -a
```

## Keng tarqalgan xatolar

**Xato 1:** `latest` tag'iga tayanib, "versiya" haqida noaniq tasavvurga ega bo'lish.
❌ `docker pull postgres` (tag ko'rsatilmagan, standart `latest`) — bu bugun PostgreSQL 17 bo'lishi mumkin, lekin bir necha oydan keyin `latest` boshqa versiyaga ishora qilib, loyihangizdagi ma'lumotlar bazasi kutilmagan tarzda yangi (yoki mos kelmaydigan) versiyaga o'tib qolishi mumkin.
✅ To'g'ri: har doim aniq versiya bilan ishlating: `docker pull postgres:16`.

**Xato 2:** image o'chirilishidan oldin unga bog'liq konteynerlarni tekshirmaslik.
❌ `docker rmi python:3.13` — agar `python:3.13` asosida yaratilgan (hatto to'xtatilgan) konteyner mavjud bo'lsa, xato chiqadi.
✅ To'g'ri: avval `docker ps -a` bilan bog'liq konteynerlarni toping va o'chiring, yoki image'ni saqlab qolishga qaror qiling.

**Xato 3:** `docker tag`ni "nusxalash" deb o'ylab, asl image'ni o'zgartirilgan deb hisoblash.
❌ `docker tag mening_loyiham foydalanuvchi/mening_loyiham:1.0` — ba'zilar buni "yangi image yaratildi" deb tushunadi.
✅ To'g'ri: `docker tag` **yangi image yaratmaydi** — u faqat mavjud image'ga qo'shimcha nom (havola) qo'shadi; `docker images` buyrug'ida ikkala nom ham bir xil `IMAGE ID`ga ega ekanini ko'rish mumkin, chunki bu — bitta va o'sha image, faqat ikki xil nom bilan.

## Mashq/topshiriq

**(Oson)** `nginx:1.27` va `nginx:alpine` image'larini yuklab oling (`docker pull`), so'ng `docker images` orqali ularning hajmlarini solishtiring.

**(O'rtacha)** `postgres:16` image'ini yuklab oling, `docker run --rm postgres:16 postgres --version` orqali PostgreSQL versiyasini tekshiring, so'ng `docker system df` orqali Docker qancha disk joyi egallaganini ko'ring.

**(Qiyin)** Mahalliy `alpine:latest` image'ini `docker pull` qiling, so'ng uni `mening-foydalanuvchim/mening-alpine:v1` deb `docker tag` orqali qayta belgilang, `docker images` orqali ikkala nom **bir xil** `IMAGE ID`ga ega ekanini tasdiqlang, va nega bu shunday ekanini tushuntirib bering (Docker Hub hisobingiz bo'lmasa, `docker push`ni bajarish shart emas — faqat `tag` bosqichini bajaring).

2. `docker pull postgres:16`, `docker run --rm postgres:16 postgres --version` → `postgres (PostgreSQL) 16.x` kabi natija; `docker system df` — `Images`, `Containers`, `Local Volumes` bo'yicha jami hajmni jadval ko'rinishida ko'rsatadi.
3. `docker pull alpine:latest`, `docker tag alpine:latest mening-foydalanuvchim/mening-alpine:v1`, `docker images` — ikkala qator (`alpine:latest` va `mening-foydalanuvchim/mening-alpine:v1`) bir xil `IMAGE ID` ustunига ega, chunki `docker tag` yangi image yaratmaydi, faqat mavjud image'ga (bitta va o'sha diskdagi fayllar to'plamiga) ikkinchi "yorliq"/havola qo'shadi — bu Git'dagi ikkita branch bir xil commit'ga ishora qilishiga o'xshaydi.

## Qisqacha xulosa

Docker Hub — image'lar uchun markaziy, ommaviy registry bo'lib, `docker pull` orqali tayyor image'larni yuklab olish, `docker images`/`docker rmi` orqali mahalliy image'larni boshqarish mumkin; **tag** — image versiyasini aniq belgilaydi (`python:3.13-slim` kabi), va production loyihalarda `latest` tag'idan qochib, har doim aniq versiya ko'rsatish tavsiya etiladi; `docker tag` va `docker push` esa — o'z qurgan image'ingizni (keyingi bobda ko'radigan Dockerfile orqali) Docker Hub'ga yuklab, boshqa kompyuter yoki serverlarda ishlatish imkonini beradi.
