# Docker networking asoslari

## Bu darsda nimalarni o'rganasiz

- Docker'ning standart tarmoq turlarini (bridge, host, none) tushuntira olasiz
- O'z maxsus tarmog'ingizni yaratib, konteynerlarni bir-biri bilan bog'lay olasiz
- Konteynerlar nomlari orqali bir-biri bilan qanday "gaplashishini" (DNS) tushunasiz
- Ikkita konteyner (masalan, Python ilova va PostgreSQL) orasida tarmoq aloqasini o'rnata olasiz

## Nazariy qism

### Nega tarmoq (networking) tushunchasi kerak

Real loyihalar deyarli hech qachon **bitta** konteynerdan iborat bo'lmaydi — odatda bir nechta xizmat (masalan, Django ilova + PostgreSQL baza + Redis kesh) alohida-alohida konteynerlarda ishlaydi, va ular **bir-biri bilan gaplashishi** kerak. Docker buni **tarmoqlar** (networks) orqali boshqaradi.

### Docker'ning standart tarmoq turlari

```bash
docker network ls
```

Natija:

```
NETWORK ID     NAME      DRIVER    SCOPE
a1b2c3d4e5f6   bridge    bridge    local
b2c3d4e5f6a7   host       host      local
c3d4e5f6a7b8   none        null      local
```

| Tur | Tavsif |
|---|---|
| **bridge** | Standart tarmoq — har bir konteyner o'z izolyatsiya qilingan IP manziliga ega, host orqali tashqi dunyoga chiqadi |
| **host** | Konteyner host'ning tarmog'ini **to'g'ridan-to'g'ri** ishlatadi (izolyatsiya yo'q, maksimal tezlik, lekin kamroq xavfsiz) |
| **none** | Hech qanday tarmoq yo'q — konteyner butunlay izolyatsiya qilingan |

Standart holda, `docker run` orqali ishga tushirilgan har qanday konteyner avtomatik **standart bridge** tarmog'iga ulanadi.

### Muammo — standart bridge tarmog'ida konteynerlar nomi orqali topilmaydi

```bash
docker run -d --name konteyner_a nginx
docker run -d --name konteyner_b python:3.13-slim tail -f /dev/null

docker exec konteyner_b ping konteyner_a
# ping: konteyner_a: Name or service not known    <-- ISHLAMAYDI!
```

**Standart bridge tarmog'ida konteynerlar bir-birini nom orqali topa olmaydi** (faqat IP manzil orqali, u ham har safar konteyner qayta yaratilganda o'zgarishi mumkin) — bu amaliy ishlatish uchun noqulay.

### Yechim — o'z maxsus tarmog'ingizni yaratish

```bash
docker network create mening_tarmogim

docker run -d --name konteyner_a --network mening_tarmogim nginx
docker run -d --name konteyner_b --network mening_tarmogim python:3.13-slim tail -f /dev/null

docker exec konteyner_b ping konteyner_a
# PING konteyner_a (172.20.0.2): 56 data bytes
# 64 bytes from 172.20.0.2: icmp_seq=0 ttl=64 time=0.123 ms    <-- ISHLAYDI!
```

**Maxsus (user-defined) tarmoqda Docker avtomatik ichki DNS taqdim etadi** — konteynerlar bir-birini o'z **nomi** orqali topa oladi, IP manzilni bilish yoki eslab qolish shart emas. Bu — Docker networking'ning eng muhim va amaliy foydali xususiyati.

### Tarmoq buyruqlari

```bash
docker network create mening_tarmogim         # yangi tarmoq yaratish
docker network ls                                 # barcha tarmoqlar ro'yxati
docker network inspect mening_tarmogim            # tarmoq haqida batafsil ma'lumot (qaysi konteynerlar ulangan)
docker network connect mening_tarmogim konteyner_c   # mavjud konteynerni tarmoqqa QO'SHISH
docker network disconnect mening_tarmogim konteyner_c  # tarmoqdan uzish
docker network rm mening_tarmogim                    # tarmoqni o'chirish (faqat hech qanday konteyner ulanmagan bo'lsa)
```

### Amaliy misol — Python ilova + PostgreSQL, tarmoq orqali bog'langan

```bash
# 1. Maxsus tarmoq yaratamiz
docker network create loyiha_tarmogi

# 2. PostgreSQL'ni shu tarmoqqa ulaymiz
docker run -d --name loyiha_db \
  --network loyiha_tarmogi \
  -e POSTGRES_PASSWORD=parol123 \
  -e POSTGRES_DB=mening_bazam \
  postgres:16

# 3. Python konteynerini HAM shu tarmoqqa ulaymiz
docker run -it --rm \
  --network loyiha_tarmogi \
  python:3.13-slim bash
```

Python konteyneri ichida:

```bash
pip install psycopg2-binary
python3
```

```python
import psycopg2

# Diqqat: host sifatida "localhost" EMAS, "loyiha_db" (konteyner NOMI) ishlatiladi!
ulanish = psycopg2.connect(
    host="loyiha_db",
    dbname="mening_bazam",
    user="postgres",
    password="parol123"
)
print("Ulanish muvaffaqiyatli!")
```

Bu — Docker networking'ning eng muhim amaliy xulosasi: konteynerlar orasida ulanishda **host** sifatida `localhost` emas, balki **boshqa konteynerning nomi** ishlatiladi, chunki har bir konteyner o'zining alohida, izolyatsiya qilingan tarmoq muhitiga ega (`localhost` konteyner ichida faqat **o'zini** anglatadi).

### Port mapping vs ichki tarmoq — muhim farq

```bash
docker run -d --name loyiha_db --network loyiha_tarmogi -e POSTGRES_PASSWORD=parol postgres:16
# -p (port mapping) YO'Q!
```

Diqqat qiling: bu misolda `-p` bayrog'i **ishlatilmagan**. Nega? Chunki `loyiha_db` konteyneriga faqat **boshqa konteynerlar** (o'sha tarmoq ichidan) murojaat qiladi — tashqi dunyo (host kompyuter yoki internet) unga to'g'ridan-to'g'ri kirish huquqiga ega bo'lishi **shart emas**, aksincha, xavfsizlik nuqtai nazaridan bu yaxshiroq (ma'lumotlar bazasi faqat ichki tarmoqdan ko'rinadi, tashqaridan emas).

`-p` faqat **host kompyuterdan** (yoki tashqi dunyodan) konteynerga kirish kerak bo'lgan xizmatlar uchun ishlatiladi (masalan, veb-server — foydalanuvchilar brauzer orqali murojaat qilishi kerak).

| Kirish turi | Kerakmi | Misol |
|---|---|---|
| Konteynerdan konteynerga (bitta tarmoqda) | `--network` yetarli, `-p` shart emas | Django → PostgreSQL |
| Host'dan (yoki tashqi dunyodan) konteynerga | `-p host_port:konteyner_port` kerak | Brauzer → Nginx/Django |

## Amaliy misol

To'liq stsenariy — uchta konteyner: veb-ilova, ma'lumotlar bazasi va keshlash xizmati, bitta tarmoqda:

```bash
# 1. Tarmoq yaratish
docker network create mening_loyiham_net

# 2. PostgreSQL — faqat ICHKI foydalanish uchun (port mapping yo'q)
docker run -d --name db \
  --network mening_loyiham_net \
  -e POSTGRES_PASSWORD=xavfsiz_parol \
  -e POSTGRES_DB=loyiha_db \
  -v pg_data:/var/lib/postgresql/data \
  postgres:16

# 3. Redis — kesh xizmati, faqat ICHKI foydalanish uchun
docker run -d --name redis_cache \
  --network mening_loyiham_net \
  redis:7-alpine

# 4. Python ilova — TASHQI dunyoga ochiq (8000-port)
docker run -d --name veb_ilova \
  --network mening_loyiham_net \
  -p 8000:8000 \
  -e DATABASE_HOST=db \
  -e REDIS_HOST=redis_cache \
  python:3.13-slim \
  tail -f /dev/null

# 5. Tekshirish — veb_ilova konteyneridan boshqa ikkalasiga "ping" qilish
docker exec veb_ilova ping -c 2 db
docker exec veb_ilova ping -c 2 redis_cache

# 6. Tarmoq holatini tekshirish — barcha ulangan konteynerlarni ko'rish
docker network inspect mening_loyiham_net
```

Bu — 4-bobda ko'radigan Docker Compose'ning aslida "qo'lda" bajarilishi: Compose xuddi shu tarmoq yaratish, konteynerlarni ulash va portlarni bog'lash ishlarini **avtomatik**, bitta konfiguratsiya fayli orqali bajaradi.

## Keng tarqalgan xatolar

**Xato 1:** konteynerlar orasidagi ulanishda `localhost`ni ishlatish.
❌ Python ilova konteyneri ichida `psycopg2.connect(host="localhost", ...)` — bu **ishlamaydi**, chunki konteyner ichida `localhost` faqat **shu konteynerning o'zini** anglatadi, PostgreSQL boshqa, alohida konteynerda ishlayapti.
✅ To'g'ri: boshqa konteynerga murojaat qilish uchun **uning nomini** (`host="db"`) ishlating — bu faqat ikkalasi **bir xil** maxsus tarmoqda bo'lganda ishlaydi.

**Xato 2:** standart bridge tarmog'ida (maxsus tarmoq yaratmasdan) konteynerlar nomi orqali bog'lanishni kutish.
❌ `docker run --name db postgres` va `docker run --name app python` (ikkalasi ham `--network` ko'rsatilmagan, ya'ni standart bridge'da) — `app` konteyneridan `db` nomiga ping qilish ishlamaydi.
✅ To'g'ri: har doim `docker network create` orqali **o'z maxsus tarmog'ingizni** yarating va barcha bog'liq konteynerlarni unga ulang — bu DNS orqali nom bilan topishni ta'minlaydi.

**Xato 3:** ma'lumotlar bazasi kabi ichki xizmatlarni keraksiz `-p` bilan tashqariga ochib qo'yish.
❌ `docker run -p 5432:5432 postgres:16` — agar bu baza faqat boshqa konteynerlar tomonidan ishlatilishi kerak bo'lsa, uni tashqi dunyoga (internetga) ochish keraksiz xavfsizlik xatarini yaratadi.
✅ To'g'ri: agar bazaga faqat konteynerlar ichidan kirish kerak bo'lsa, `-p`ni umuman ishlatmang — faqat `--network` orqali ulang; `-p`ni faqat host'dan (masalan, o'zingiz `psql` bilan tashqaridan ulanish uchun) kirish zarur bo'lganda qo'shing.

## Mashq/topshiriq

**(Oson)** `test_tarmoq` nomli tarmoq yarating, ikkita `python:3.13-slim` konteynerini (`c1`, `c2` nomlari bilan, `tail -f /dev/null` bilan "ochiq" ushlab) shu tarmoqqa ulang, va `c1`dan `c2`ga `ping` orqali bog'lanishni tasdiqlang.

**(O'rtacha)** `docker network inspect test_tarmoq` buyrug'ini ishga tushiring va natijadan har bir konteynerning ichki IP manzilini toping, so'ng nima uchun nom orqali bog'lanish IP manzil orqali bog'lanishdan qulayroq ekanini tushuntiring.

**(Qiyin)** Yuqoridagi amaliy misoldagi uchta konteynerli (`db`, `redis_cache`, `veb_ilova`) tizimni qayta yarating, so'ng `redis_cache` konteynerini `docker network disconnect` orqali tarmoqdan uzing va `veb_ilova`dan unga ping urinib ko'ring — endi nima sodir bo'lishini kuzatib, sababini tushuntirib bering.

## Qisqacha xulosa

Docker konteynerlari standart holda **bridge** tarmog'ida ishga tushadi, lekin bir-birini nom orqali topa olmaydi — bu muammoni **maxsus (user-defined) tarmoq** yaratish orqali hal qilish mumkin, unda Docker avtomatik ichki DNS taqdim etib, konteynerlarga bir-birini **nomi** orqali (masalan, `host="db"`) topish imkonini beradi; `-p` (port mapping) faqat **tashqi dunyodan** (host yoki internet) konteynerga kirish kerak bo'lganda ishlatiladi, ichki (konteynerdan konteynerga) aloqa uchun esa shart emas — bu tushunchalar keyingi bobda ko'riladigan Docker Compose'ning "sahna ortida" qanday ishlashini tushunish uchun zarur poydevordir.
