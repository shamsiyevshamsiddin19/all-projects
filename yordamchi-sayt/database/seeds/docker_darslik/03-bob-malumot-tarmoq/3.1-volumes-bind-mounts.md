# Volumes va bind mounts

## Bu darsda nimalarni o'rganasiz

- Konteynerlarning "vaqtinchalik" (ephemeral) tabiatini va bu muammoni tushunasiz
- Docker **volume**larni yarata va boshqara olasiz
- **Bind mount**larni development jarayonida qo'llay olasiz
- Volume va bind mount orasidagi farqni va qachon qaysi birini tanlashni bilasiz

## Nazariy qism

### Muammo — konteyner ma'lumoti "vaqtinchalik"

1.1-darsda ko'rganimizdek, konteyner — image asosida yaratilgan **namuna**. Agar konteyner ichida biror ma'lumot yaratilsa (masalan, PostgreSQL konteynerida ma'lumotlar bazasiga yozuv qo'shilsa), va konteyner **o'chirilsa** (`docker rm`) — bu ma'lumot **butunlay yo'qoladi**, chunki u faqat konteynerning vaqtinchalik fayl tizimida saqlangan edi.

```bash
docker run -d --name test_db -e POSTGRES_PASSWORD=parol postgres:16
# ... bazaga ma'lumot qo'shildi ...
docker rm -f test_db
# barcha ma'lumot BUTUNLAY YO'QOLDI!
```

Bu — real loyihalarda **jiddiy muammo**: ma'lumotlar bazasi, yuklangan fayllar, log'lar kabi **doimiy saqlanishi kerak bo'lgan** ma'lumotlar konteyner hayoti bilan chegaralanmasligi kerak.

### Yechim — Volume va Bind mount

Docker bu muammoni ikkita mexanizm orqali hal qiladi:

| Mexanizm | Ma'lumot qayerda saqlanadi | Kim boshqaradi |
|---|---|---|
| **Volume** | Docker o'zi boshqaradigan maxsus joyda (`/var/lib/docker/volumes/`) | Docker |
| **Bind mount** | Host kompyuterning **istalgan** papkasida (siz ko'rsatgan aniq yo'lda) | Siz (to'liq nazorat) |

### Volume — Docker tomonidan boshqariladigan saqlash

```bash
# Volume yaratish
docker volume create mening_db_data

# Volume'ni konteynerga ulash
docker run -d --name postgres_db \
  -e POSTGRES_PASSWORD=parol \
  -v mening_db_data:/var/lib/postgresql/data \
  postgres:16
```

`-v mening_db_data:/var/lib/postgresql/data` — `mening_db_data` nomli volume'ni konteyner ichidagi `/var/lib/postgresql/data` papkasiga (PostgreSQL ma'lumotlarni shu yerga yozadi) ulaydi. Endi konteyner o'chirilsa ham, **ma'lumot volume'da saqlanib qoladi**:

```bash
docker rm -f postgres_db

# Yangi konteyner yaratib, XUDDI O'SHA volume'ni ulaymiz
docker run -d --name postgres_db_2 \
  -e POSTGRES_PASSWORD=parol \
  -v mening_db_data:/var/lib/postgresql/data \
  postgres:16
# Eski ma'lumotlar HAMON MAVJUD!
```

### Volume'larni boshqarish buyruqlari

```bash
docker volume ls              # barcha volume'lar ro'yxati
docker volume inspect mening_db_data     # batafsil ma'lumot (qayerda saqlanganini ko'rsatadi)
docker volume rm mening_db_data            # volume'ni o'chirish (FAQAT hech qanday konteyner ishlatmasa)
docker volume prune               # ISHLATILMAYOTGAN barcha volume'larni tozalash
```

> ⚠️ **`docker volume prune` juda ehtiyotkorlik bilan ishlatilishi kerak** — bu buyruq hech qanday konteyner tomonidan ishlatilmayotgan **barcha** volume'larni, ularning ichidagi **barcha** ma'lumot bilan birga o'chiradi, va bu amalni **qaytarib bo'lmaydi**.

### Bind mount — host papkasini to'g'ridan-to'g'ri ulash

**Bind mount** — Docker'ning ichki boshqaruvidan tashqarida, host kompyuterning **aniq bir papkasini** konteynerga "ko'zguband" qiladi:

```bash
docker run -d --name mening_app \
  -v /home/foydalanuvchi/loyiham/kod:/app \
  python:3.13-slim
```

Bu — host'dagi `/home/foydalanuvchi/loyiham/kod` papkasidagi **har qanday o'zgarish** konteyner ichida **darhol** ko'rinishini bildiradi (va aksincha) — bu ayniqsa **development** jarayonida juda foydali: kodni tahrirlaganingizda, konteynerni qayta qurmasdan (`docker build`) o'zgarishlarni darhol ko'rish mumkin.

### Bind mount — nisbiy yo'l bilan (qulay yozuv)

```bash
docker run -d --name mening_app -v "$(pwd)":/app python:3.13-slim
```

`$(pwd)` — joriy papka to'liq yo'lini avtomatik oladi, bu har safar to'liq yo'lni qo'lda yozishdan qutqaradi.

### Volume vs Bind mount — qachon qaysi birini tanlash

| Holat | Tavsiya |
|---|---|
| Ma'lumotlar bazasi ma'lumotlari (PostgreSQL, MySQL) | **Volume** — Docker boshqaradi, ko'chirish/backup qilish osonroq |
| Development paytida kodni "jonli" tahrirlash | **Bind mount** — host'dagi kodni to'g'ridan-to'g'ri ulaydi |
| Production'da ilova kodi | Odatda **kod image ichida** (`COPY` orqali) — bind mount emas, chunki image o'zgarmas (immutable) bo'lishi kerak |
| Konteynerlar orasida fayl ulashish | **Volume** — bir nechta konteyner bitta volume'ni ulashi mumkin |
| Konfiguratsiya fayllarini host'dan uzatish | **Bind mount** — aniq, ma'lum joydagi faylni ulash uchun qulay |

### Read-only mount — faqat o'qish uchun ulash

```bash
docker run -v /host/config:/app/config:ro python:3.13-slim
```

`:ro` (read-only) — konteyner shu papkani **faqat o'qishi**, unga yozib bo'lmasligini bildiradi. Bu — konfiguratsiya fayllari yoki maxfiy ma'lumotlarni ulaganda xavfsizlik uchun foydali (konteyner ichidagi dastur, hatto buzilgan yoki noto'g'ri sozlangan bo'lsa ham, host fayllarini o'zgartira olmaydi).

### Anonim volume — nom berilmagan volume

```bash
docker run -v /var/lib/postgresql/data postgres:16
```

Agar volume nomi ko'rsatilmasa (faqat konteyner ichidagi yo'l), Docker **tasodifiy nomli** ("anonim") volume yaratadi. Bu — ma'lumot saqlanishini ta'minlaydi, lekin unga keyinchalik aniq nom bilan murojaat qilish qiyinroq — shuning uchun **har doim aniq nomli volume** (`-v mening_db_data:/...`) ishlatish tavsiya etiladi.

## Amaliy misol

PostgreSQL ma'lumotlar bazasini volume bilan — ma'lumot yo'qolmasligini isbotlash:

```bash
# 1. Volume yaratish va PostgreSQL'ni ishga tushirish
docker volume create pg_data
docker run -d --name pg_test \
  -e POSTGRES_PASSWORD=parol123 \
  -v pg_data:/var/lib/postgresql/data \
  -p 5432:5432 \
  postgres:16

# 2. Bazaga jadval va ma'lumot qo'shamiz
docker exec -it pg_test psql -U postgres -c "CREATE TABLE talabalar (ism TEXT);"
docker exec -it pg_test psql -U postgres -c "INSERT INTO talabalar VALUES ('Ali');"
docker exec -it pg_test psql -U postgres -c "SELECT * FROM talabalar;"
# ism
# -----
# Ali

# 3. Konteynerni BUTUNLAY o'chiramiz
docker rm -f pg_test

# 4. YANGI konteyner yaratamiz, XUDDI O'SHA volume bilan
docker run -d --name pg_test_2 \
  -e POSTGRES_PASSWORD=parol123 \
  -v pg_data:/var/lib/postgresql/data \
  -p 5432:5432 \
  postgres:16

# 5. Ma'lumot HAMON mavjudligini tekshiramiz
docker exec -it pg_test_2 psql -U postgres -c "SELECT * FROM talabalar;"
# ism
# -----
# Ali          <-- MA'LUMOT SAQLANIB QOLDI!
```

Endi development uchun bind mount misoli — Python kodini "jonli" tahrirlash:

```bash
mkdir -p ~/dev-loyiha && cd ~/dev-loyiha
echo 'print("Versiya 1")' > main.py

docker run -d --name dev_konteyner \
  -v "$(pwd)":/app \
  -w /app \
  python:3.13-slim \
  tail -f /dev/null   # konteynerni "ochiq" ushlab turish uchun

docker exec dev_konteyner python3 main.py
# Versiya 1

# Kodni HOST'da o'zgartiramiz (Docker'siz, oddiy matn muharririda)
echo 'print("Versiya 2 - jonli o'\''zgartirildi!")' > main.py

docker exec dev_konteyner python3 main.py
# Versiya 2 - jonli o'zgartirildi!   <-- konteynerni qayta qurmasdan, o'zgarish DARHOL ko'rindi!
```

## Keng tarqalgan xatolar

**Xato 1:** volume ulanmasdan ma'lumotlar bazasi konteynerini ishga tushirib, keyin ma'lumot yo'qolganidan hayron bo'lish.
❌ `docker run -d postgres:16` (volume'siz) — konteyner o'chirilsa yoki qayta yaratilsa (masalan, `docker compose down`), barcha ma'lumot **butunlay yo'qoladi**.
✅ To'g'ri: ma'lumotlar bazasi kabi doimiy saqlanishi kerak bo'lgan har qanday xizmat uchun har doim **nomli volume** ulang.

**Xato 2:** production'da kod uchun ham bind mount ishlatish (development odatini production'ga olib o'tish).
❌ Production serverida `-v /server/kod:/app` orqali kodni ulash — bu image'ning "o'zgarmaslik" (immutability) tamoyilini buzadi, chunki kod endi image ichida emas, tashqi, nazoratsiz manbada.
✅ To'g'ri: production'da kod har doim `Dockerfile`dagi `COPY` orqali image ichiga **qurilishi** kerak — bind mount faqat **development** (kodni tez-tez o'zgartirib, natijani darhol ko'rish) uchun ishlatiladi.

**Xato 3:** bind mount yo'lini noto'g'ri (nisbiy, aniqlanmagan) yozib, kutilmagan xatolarga duch kelish.
❌ `docker run -v ./kod:/app ...` — ba'zi Docker versiyalarida yoki turli ishga tushirish papkalaridan chaqirilganda nisbiy yo'l noto'g'ri talqin qilinishi mumkin.
✅ To'g'ri: `$(pwd)` (joriy papkaning **to'liq** yo'lini avtomatik olish) yoki to'liq, aniq yo'l (`/home/foydalanuvchi/loyiha`) ishlatish tavsiya etiladi.

## Mashq/topshiriq

**(Oson)** `mening_volume` nomli volume yarating, uni `python:3.13-slim` konteyneriga `/data` sifatida ulang, konteyner ichida `/data/test.txt` fayl yarating (`docker exec ... bash -c "echo salom > /data/test.txt"`), konteynerni o'chirib, yangi konteynerda xuddi shu volume bilan faylning mavjudligini tekshiring.

**(O'rtacha)** Bind mount orqali host'dagi bo'sh papkani konteynerga ulang, konteyner ichida (`docker exec`) yangi fayl yarating, so'ng shu faylni **host** kompyuterda (Docker'dan tashqarida, oddiy `ls`/matn muharriri orqali) ko'rinishini tasdiqlang.

**(Qiyin)** Ikkita alohida konteynerni **bitta** volume'ga ulang (`-v umumiy_volume:/shared` ikkalasida ham), birinchi konteynerda faylga ma'lumot yozing, ikkinchi konteynerda shu faylni o'qing va nega bu ishlashini (Docker volume'lar bir nechta konteyner orasida ulashilishi mumkinligi) tushuntirib bering.

Bu ishlaydi, chunki Docker volume — konteynerlardan **mustaqil**, alohida saqlash birligi bo'lib, bir nechta konteyner uni bir vaqtda ulashi (mount qilishi) mumkin, xuddi umumiy tarmoq papkasiga o'xshab.

## Qisqacha xulosa

Konteynerlar tabiatan **vaqtinchalik** (ephemeral) — konteyner o'chirilganda, uning ichidagi ma'lumot ham yo'qoladi, shuning uchun doimiy saqlanishi kerak bo'lgan ma'lumotlar (ma'lumotlar bazasi, yuklangan fayllar) **volume**larda saqlanishi kerak; **Volume** — Docker tomonidan boshqariladigan, konteynerlar orasida ulashilishi mumkin bo'lgan saqlash birligi (odatda production ma'lumotlari uchun), **bind mount** esa host'ning aniq bir papkasini konteynerga to'g'ridan-to'g'ri ulaydi (odatda development jarayonida kodni "jonli" tahrirlash uchun) — bu ikkita mexanizm keyingi bobda ko'riladigan Docker Compose'da bir nechta xizmatni birlashtirishda muntazam ishlatiladi.
