# Dockerfile asoslari va direktivalari

## Bu darsda nimalarni o'rganasiz

- `Dockerfile` nima ekanini va uning asosiy direktivalarini bilasiz
- `FROM`, `WORKDIR`, `COPY`, `RUN`, `CMD` kabi buyruqlarni to'g'ri qo'llay olasiz
- O'z Python ilovangiz uchun image qura olasiz (`docker build`)
- `CMD` va `ENTRYPOINT` orasidagi farqni tushuntira olasiz

## Nazariy qism

### Dockerfile — image'ning "retsepti"

**Dockerfile** — matnli fayl bo'lib, image qanday qurilishi kerakligini bosqichma-bosqich tavsiflaydi. Bu — 0.1-darsda ko'rgan "retsept" metaforasining aynan o'zi: `Dockerfile` — retsept, `docker build` — pishirish jarayoni, natijaviy **image** — tayyor taom.

### Eng oddiy Dockerfile — Python skripti uchun

Loyiha strukturasi:

```
mening-loyiham/
├── Dockerfile
├── main.py
└── requirements.txt
```

`main.py`:

```python
print("Salom, Docker konteyneridan!")
```

`Dockerfile`:

```dockerfile
FROM python:3.13-slim

WORKDIR /app

COPY . .

CMD ["python3", "main.py"]
```

### Asosiy direktivalar — bosqichma-bosqich

**`FROM`** — bazaviy image'ni belgilaydi, har bir Dockerfile shu bilan **boshlanishi shart**:

```dockerfile
FROM python:3.13-slim
```

Bu — sizning image'ingiz Python 3.13 (kichraytirilgan versiya) allaqachon o'rnatilgan bazaviy image ustiga quriladi degani (1.2-darsda ko'rgan tag tanlovi bu yerda ham muhim).

**`WORKDIR`** — konteyner ichidagi "ishchi papka"ni belgilaydi (agar mavjud bo'lmasa, avtomatik yaratiladi):

```dockerfile
WORKDIR /app
```

Bu qatordan keyingi barcha buyruqlar (`COPY`, `RUN`, `CMD`) shu `/app` papkasi ichida bajariladi — bu Linux'da `cd /app` yozishga o'xshaydi, lekin butun Dockerfile davomida amal qiladi.

**`COPY`** — host kompyuterdagi fayllarni image ichiga nusxalaydi:

```dockerfile
COPY . .                          # joriy papkadagi HAMMA narsani /app ichiga nusxalash
COPY requirements.txt .            # faqat bitta faylni nusxalash
COPY src/ /app/src/                 # aniq papkani aniq joyga nusxalash
```

`COPY <manba> <maqsad>` — birinchi `.` (nuqta) — Dockerfile joylashgan papkadagi barcha fayllarni, ikkinchi `.` esa — `WORKDIR` bilan belgilangan joyga (`/app`) degani.

**`RUN`** — image **qurilish vaqtida** buyruq bajaradi (masalan, kutubxona o'rnatish):

```dockerfile
RUN pip install --no-cache-dir -r requirements.txt
```

`RUN` — Dockerfile'dagi eng ko'p ishlatiladigan direktivalardan biri, chunki u orqali `apt install`, `pip install`, fayllarni tayyorlash kabi barcha "qurilish vaqti" ishlari bajariladi.

**`CMD`** — konteyner **ishga tushirilganda** bajariladigan standart buyruq:

```dockerfile
CMD ["python3", "main.py"]
```

`CMD` — `RUN`dan farqli o'laroq, image qurilish vaqtida **emas**, faqat konteyner `docker run` orqali ishga tushirilganda bajariladi.

### `RUN` vs `CMD` — asosiy farq

| Direktiva | Qachon bajariladi | Nechta marta bo'lishi mumkin |
|---|---|---|
| `RUN` | Image **qurilishi** (`docker build`) vaqtida | Bir nechta marta (har biri yangi qatlam yaratadi) |
| `CMD` | Konteyner **ishga tushirilganda** (`docker run`) | Faqat **bittasi** amal qiladi (oxirgisi qolganlarini bekor qiladi) |

Bu farq — 0.1-darsdagi Image/Container tushunchasiga to'g'ridan-to'g'ri bog'liq: `RUN` — image (retsept)ni tayyorlash bosqichida, `CMD` — konteyner (tayyor taom, xizmat qilinganda) ishga tushirilganda.

### Image qurish — `docker build`

```bash
docker build -t mening-loyiham:1.0 .
```

| Qism | Ma'nosi |
|---|---|
| `-t mening-loyiham:1.0` | Image'ga nom va tag berish (1.2-darsda ko'rgan format) |
| `.` (oxirgi nuqta) | **Build context** — Dockerfile va unga bog'liq fayllar qayerda ekanini ko'rsatadi (joriy papka) |

Qurilgandan keyin, image'ni oddiy image kabi ishga tushirish mumkin:

```bash
docker run mening-loyiham:1.0
# Salom, Docker konteyneridan!
```

### `CMD` va `ENTRYPOINT` — farqi va birgalikda ishlatilishi

```dockerfile
ENTRYPOINT ["python3"]
CMD ["main.py"]
```

`ENTRYPOINT` — konteyner ishga tushganda **har doim** bajariladigan, "o'zgarmas" qismi; `CMD` esa — unga standart **argumentlar** beradi, lekin `docker run` paytida **almashtirilishi** mumkin:

```bash
docker run mening-image                    # python3 main.py bajaradi (CMD standart)
docker run mening-image boshqa_skript.py     # python3 boshqa_skript.py bajaradi (CMD almashtirildi!)
```

Agar faqat `CMD` (ENTRYPOINT'siz) ishlatilsa, `docker run mening-image boshqa_buyruq` — butun `CMD`ni **butunlay** almashtiradi. `ENTRYPOINT` + `CMD` kombinatsiyasi — "asosiy dastur o'zgarmasin, lekin unga uzatiladigan parametr o'zgarishi mumkin" degan holatlarda ishlatiladi.

### Muhim: `["..."]` (exec forma) vs oddiy matn (shell forma)

```dockerfile
CMD ["python3", "main.py"]     # ✅ EXEC FORMA — tavsiya etiladi
CMD python3 main.py               # ⚠️ SHELL FORMA — ishlaydi, lekin kamroq tavsiya etiladi
```

**Exec forma** (kvadrat qavs, har bir so'z alohida qo'shtirnoqda) — buyruqni to'g'ridan-to'g'ri, oraliq shell (`/bin/sh`) siz bajaradi, bu signallarni (masalan, `docker stop` yuboradigan `SIGTERM`) to'g'ri qabul qilishni ta'minlaydi. **Shell forma** — qulayroq ko'rinsada, ba'zi hollarda signal boshqaruvida muammolarga olib kelishi mumkin. Ushbu kursda har doim **exec forma** ishlatiladi.

### `.dockerignore` — keraksiz fayllarni build'dan chetlab o'tish

`.gitignore`ga o'xshab, `.dockerignore` fayli `COPY . .` orqali image ichiga **nusxalanmasligi kerak** bo'lgan fayllarni belgilaydi:

```
# .dockerignore
__pycache__/
*.pyc
.git/
.env
venv/
*.md
```

Bu — image hajmini kamaytiradi va (ayniqsa `.env` kabi maxfiy ma'lumotlar uchun) **xavfsizlik** nuqtai nazaridan muhim — maxfiy fayllar tasodifan image ichiga tushib qolmasligi kerak.

## Amaliy misol

To'liq, ishlaydigan Python ilovasi uchun Dockerfile:

```
salomlashuv-app/
├── Dockerfile
├── .dockerignore
├── requirements.txt
└── main.py
```

`requirements.txt`:

```
requests==2.31.0
```

`main.py`:

```python
import requests
import sys

def main():
    ism = sys.argv[1] if len(sys.argv) > 1 else "Dunyo"
    print(f"Salom, {ism}! Docker konteyneridan ishlayapman.")
    javob = requests.get("https://api.github.com")
    print(f"GitHub API holati: {javob.status_code}")

if __name__ == "__main__":
    main()
```

`.dockerignore`:

```
__pycache__/
*.pyc
.git/
```

`Dockerfile`:

```dockerfile
FROM python:3.13-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

ENTRYPOINT ["python3", "main.py"]
CMD ["Dunyo"]
```

Qurish va ishga tushirish:

```bash
docker build -t salomlashuv-app:1.0 .

docker run salomlashuv-app:1.0
# Salom, Dunyo! Docker konteyneridan ishlayapman.
# GitHub API holati: 200

docker run salomlashuv-app:1.0 Ali
# Salom, Ali! Docker konteyneridan ishlayapman.
# GitHub API holati: 200
```

Ikkinchi ishga tushirishda `CMD`ning standart qiymati (`"Dunyo"`) `docker run` orqali `"Ali"` bilan almashtirildi, lekin `ENTRYPOINT` (`python3 main.py`) o'zgarmadi — bu yuqorida ko'rgan `ENTRYPOINT`+`CMD` mexanizmining amaliy namunasi.

## Keng tarqalgan xatolar

**Xato 1:** `COPY . .`ni `requirements.txt` o'rnatishdan **oldin** yozish (build cache samarasiz ishlatiladi — 2.2-darsda batafsil ko'riladi, lekin bu yerda ham eslatib o'tamiz).
❌ 
```dockerfile
COPY . .
RUN pip install -r requirements.txt
```
Bu — texnik jihatdan ishlaydi, lekin har safar **istalgan** fayl o'zgarganda (hatto `requirements.txt` o'zgarmagan bo'lsa ham), `pip install` **qayta** bajariladi — bu buildni sekinlashtiradi.
✅ To'g'ri: yuqoridagi amaliy misolda ko'rganimizdek, avval faqat `requirements.txt`ni nusxalab, kutubxonalarni o'rnating, **keyin** qolgan kodni nusxalang.

**Xato 2:** `CMD`da bir nechta buyruqni "qo'shib" yozishga urinish.
❌ 
```dockerfile
CMD ["python3", "main.py"]
CMD ["python3", "boshqa.py"]
```
Ikkinchi `CMD` — birinchisini **butunlay bekor qiladi**, faqat oxirgisi amal qiladi (bu — Dockerfile'ning ataylab shunday ishlashi, xato emas, lekin ko'p boshlovchi buni tushunmasdan chalkashadi).
✅ To'g'ri: har bir Dockerfile'da faqat **bitta** `CMD` bo'lishi kerak — agar bir nechta buyruq bajarish kerak bo'lsa, ularni bitta skriptga (`start.sh`) yig'ib, o'sha skriptni `CMD`da chaqiring.

**Xato 3:** `.dockerignore` faylini yaratmasdan, katta yoki maxfiy fayllarni tasodifan image ichiga nusxalab qo'yish.
❌ `.git/` papkasi (ba'zan yuzlab MB) yoki `.env` fayli (maxfiy parollar bilan) `COPY . .` orqali image ichiga tushib qolishi — bu ham image hajmini keraksiz oshiradi, ham xavfsizlik xatarini tug'diradi (agar image kimgadir ulashilsa yoki Docker Hub'ga yuklansa).
✅ To'g'ri: har doim `.dockerignore` faylini yarating va unga `.git/`, `.env`, `__pycache__/`, `venv/` kabi fayllarni qo'shing.

## Mashq/topshiriq

**(Oson)** Oddiy `salom.py` (`print("Salom, Docker!")`) fayli uchun minimal Dockerfile yozing (`FROM`, `WORKDIR`, `COPY`, `CMD` bilan) va uni `docker build`/`docker run` orqali sinab ko'ring.

**(O'rtacha)** 0.1-darsdagi mashqda yozgan Python `argparse` asosidagi "Vazifa boshqaruvchi" CLI loyihasini (Python kursining 6.3-darsi) Dockerfile bilan konteynerlashtiring — `requirements.txt` (agar kerak bo'lsa) va `ENTRYPOINT`/`CMD` kombinatsiyasidan foydalanib, turli buyruqlar (`qosh`, `royxat`) bilan ishga tushirib ko'ring.

**(Qiyin)** Ikkita Dockerfile yozing: birida `COPY . .` keyin `RUN pip install`, ikkinchisida (yuqoridagi to'g'ri tartibda) avval `requirements.txt` nusxalanadi. Har ikkalasini quring, so'ng `requirements.txt`ga o'zgarishsiz `main.py`ga kichik o'zgartirish kiritib, ikkalasini **qayta** quring — qaysi birida qurilish tezroq bo'lganini kuzating va sababini tushuntiring (bu — 2.2-darsda chuqurroq o'rganiladigan build cache mavzusiga kirish).

## Qisqacha xulosa

`Dockerfile` — image qurilish "retseptini" belgilaydi: `FROM` bazaviy image'ni, `WORKDIR` ishchi papkani, `COPY` fayllarni image ichiga nusxalashni, `RUN` qurilish vaqtidagi buyruqlarni (masalan, `pip install`), `CMD`/`ENTRYPOINT` esa konteyner ishga tushganda bajariladigan buyruqni belgilaydi; `docker build -t nom:tag .` orqali Dockerfile asosida image quriladi; `.dockerignore` fayli keraksiz yoki maxfiy fayllarning image ichiga tushib qolishining oldini oladi — bu direktivalar butun qolgan kursning (multi-stage build, Docker Compose, production deploy) poydevorini tashkil qiladi.
