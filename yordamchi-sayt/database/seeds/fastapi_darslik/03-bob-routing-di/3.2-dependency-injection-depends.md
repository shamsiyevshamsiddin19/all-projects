# Dependency Injection (Depends) asoslari

## Bu darsda nimalarni o'rganasiz

- Dependency Injection (bog'liqlikni kiritish) tushunchasini va uning nima uchun kerakligini tushunasiz
- `Depends()` orqali umumiy mantiqni qayta ishlatishni o'rganasiz
- Klass-asosidagi (class-based) dependency'larni yaratishni bilasiz
- Dependency'larni zanjirlashtirish (bir dependency, boshqasiga bog'liq bo'lishi) imkoniyatini tushunasiz

## Nazariy qism

### Dependency Injection nima

**Dependency Injection (DI)** — funksiyaga kerakli narsalarni (masalan, ma'lumotlar bazasi ulanishi, joriy foydalanuvchi, sozlamalar) **tashqaridan, avtomatik ravishda "kiritish"** naqshi. FastAPI'da bu, `Depends()` funksiyasi orqali amalga oshiriladi.

### Muammo — DI'siz kod

Tasavvur qiling, bir nechta endpoint, bir xil "sahifalash parametrlarini tekshirish" mantig'iga ega:

```python
@app.get("/mahsulotlar")
def mahsulotlar(sahifa: int = 1, hajmi: int = 10):
    if sahifa < 1:
        raise HTTPException(400, "Sahifa 1 dan katta bo'lishi kerak")
    if hajmi > 100:
        raise HTTPException(400, "Hajmi 100 dan oshmasligi kerak")
    return {"sahifa": sahifa, "hajmi": hajmi}

@app.get("/foydalanuvchilar")
def foydalanuvchilar(sahifa: int = 1, hajmi: int = 10):
    if sahifa < 1:                                    # TAKRORLANGAN kod
        raise HTTPException(400, "Sahifa 1 dan katta bo'lishi kerak")
    if hajmi > 100:                                    # TAKRORLANGAN kod
        raise HTTPException(400, "Hajmi 100 dan oshmasligi kerak")
    return {"sahifa": sahifa, "hajmi": hajmi}
```

Bu — kod takrorlanishi (DRY — "Don't Repeat Yourself" tamoyiliga zid), va agar tekshiruv mantiqi o'zgarsa, uni **har bir** endpoint'da alohida yangilash kerak bo'ladi.

### Yechim — `Depends()`

```python
from typing import Annotated
from fastapi import Depends, FastAPI

app = FastAPI()

def sahifalash_parametrlari(sahifa: int = 1, hajmi: int = 10):
    if sahifa < 1:
        raise HTTPException(400, "Sahifa 1 dan katta bo'lishi kerak")
    if hajmi > 100:
        raise HTTPException(400, "Hajmi 100 dan oshmasligi kerak")
    return {"sahifa": sahifa, "hajmi": hajmi}

@app.get("/mahsulotlar")
def mahsulotlar(sahifalash: Annotated[dict, Depends(sahifalash_parametrlari)]):
    return {"turi": "mahsulotlar", **sahifalash}

@app.get("/foydalanuvchilar")
def foydalanuvchilar(sahifalash: Annotated[dict, Depends(sahifalash_parametrlari)]):
    return {"turi": "foydalanuvchilar", **sahifalash}
```

Endi tekshiruv mantiqi — **bitta joyda** (`sahifalash_parametrlari` funksiyasida) yashaydi, va istalgan endpoint uni `Depends(sahifalash_parametrlari)` orqali qayta ishlatishi mumkin.

### `Depends()` qanday ishlaydi — bosqichma-bosqich

1. So'rov kelganda, FastAPI — `Depends()` ichidagi funksiyani (`sahifalash_parametrlari`) **avval** chaqiradi
2. Bu funksiya, o'zining parametrlarini (`sahifa`, `hajmi`) — xuddi oddiy endpoint kabi — so'rovdan (query, path, va h.k.) avtomatik oladi
3. Funksiyaning natijasi — asosiy endpoint funksiyasiga, `Depends()` o'rniga **qo'yiladi**

Bu — dependency'lar **oddiy endpoint funksiyalari kabi**, xuddi shu qoidalar (path/query/body parametrlarini avtomatik olish) bilan yozilishini bildiradi.

### Umumiy DI qo'llanilishi — ma'lumotlar bazasi sessiyasi (4-bobga tayyorgarlik)

Eng keng tarqalgan DI qo'llanilishi — har bir so'rov uchun ma'lumotlar bazasi ulanishini (session) ochish va **avtomatik yopish**:

```python
def db_sessiyasini_olish():
    db = SessionLocal()
    try:
        yield db          # bu yerda "yield" - so'rov tugagach, keyingi kod ishga tushadi
    finally:
        db.close()

@app.get("/mahsulotlar")
def mahsulotlar(db: Annotated[Session, Depends(db_sessiyasini_olish)]):
    return db.query(Mahsulot).all()
```

> 📌 **`yield` bilan dependency — muhim naqsh:** agar dependency funksiyasi `return` o'rniga `yield` ishlatsa, `yield`dan **keyingi** kod — so'rov to'liq qayta ishlangandan (javob qaytarilgandan) **keyin** ishga tushadi. Bu — resurslarni (ma'lumotlar bazasi ulanishi, fayl handle) har doim to'g'ri yopilishini kafolatlash uchun ideal (bu, Python darsligining `with` operatori/context manager mavzusiga konseptual jihatdan o'xshaydi).

### Klass-asosidagi dependency'lar

Oddiy funksiyalar o'rniga, murakkabroq holatlar uchun **klass** ham dependency sifatida ishlatilishi mumkin:

```python
class UmumiyParametrlar:
    def __init__(self, sahifa: int = 1, hajmi: int = 10, saralash: str | None = None):
        self.sahifa = sahifa
        self.hajmi = hajmi
        self.saralash = saralash

@app.get("/mahsulotlar")
def mahsulotlar(parametrlar: Annotated[UmumiyParametrlar, Depends(UmumiyParametrlar)]):
    return {
        "sahifa": parametrlar.sahifa,
        "hajmi": parametrlar.hajmi,
        "saralash": parametrlar.saralash,
    }
```

FastAPI — klassning `__init__` metodini, xuddi oddiy funksiyaga o'xshab, so'rov parametrlarini avtomatik "kiritish" uchun ishlatadi.

### Dependency'larni zanjirlashtirish

Bir dependency, **boshqa dependency'ga** bog'liq bo'lishi mumkin — bu, real loyihalarda (masalan, "joriy foydalanuvchi" — "autentifikatsiya token"iga bog'liq) juda keng tarqalgan:

```python
def token_olish(token: str | None = None) -> str:
    if not token:
        raise HTTPException(401, "Token talab qilinadi")
    return token

def joriy_foydalanuvchi(token: Annotated[str, Depends(token_olish)]) -> dict:
    # (haqiqiy loyihada, token dekodlanib, foydalanuvchi bazadan olinadi)
    return {"foydalanuvchi_id": 1, "ism": "Shamsiddin"}

@app.get("/profil")
def profil(foydalanuvchi: Annotated[dict, Depends(joriy_foydalanuvchi)]):
    return foydalanuvchi
```

Bu yerda: `profil` — `joriy_foydalanuvchi`ga bog'liq, `joriy_foydalanuvchi` esa — `token_olish`ga bog'liq. FastAPI, bu **butun zanjirni avtomatik** chaqiradi va hal qiladi. Bu naqsh, 5-bobda autentifikatsiya tizimini qurishning asosini tashkil etadi.

### `Depends()`ni kesh (cache) qilish

Standart holda, agar bir dependency, bitta so'rov davomida bir nechta joyda ishlatilsa, FastAPI uni **faqat bir marta** chaqiradi va natijani keshlab, qayta ishlatadi (samaradorlik uchun).

### Global (butun router yoki ilova uchun) dependency'lar

Agar dependency, **router'dagi barcha** endpoint'lar uchun qo'llanilishi kerak bo'lsa (masalan, barcha admin endpoint'lari autentifikatsiya talab qilishi kerak):

```python
router = APIRouter(
    prefix="/admin",
    dependencies=[Depends(joriy_foydalanuvchi)],  # HAR BIR endpoint uchun avtomatik ishlaydi
)
```

## Amaliy misol

To'liq, real loyihada uchraydigan DI qo'llanilishi — sahifalash va soxta autentifikatsiya:

```python
from typing import Annotated
from fastapi import FastAPI, Depends, HTTPException, Header

app = FastAPI()

class Sahifalash:
    def __init__(self, sahifa: int = 1, hajmi: int = 10):
        if sahifa < 1:
            raise HTTPException(400, "sahifa >= 1 bo'lishi kerak")
        if not (1 <= hajmi <= 100):
            raise HTTPException(400, "hajmi 1 va 100 orasida bo'lishi kerak")
        self.sahifa = sahifa
        self.hajmi = hajmi
        self.chegara = (sahifa - 1) * hajmi

def api_kalitini_tekshirish(x_api_key: Annotated[str | None, Header()] = None) -> str:
    if x_api_key != "maxfiy-kalit-2026":
        raise HTTPException(401, "Yaroqsiz yoki mavjud bo'lmagan API kalit")
    return x_api_key

MAHSULOTLAR = [{"id": i, "nomi": f"Mahsulot {i}"} for i in range(1, 51)]

@app.get("/mahsulotlar")
def mahsulotlar_royxati(
    sahifalash: Annotated[Sahifalash, Depends(Sahifalash)],
    _api_kalit: Annotated[str, Depends(api_kalitini_tekshirish)],
):
    natija = MAHSULOTLAR[sahifalash.chegara : sahifalash.chegara + sahifalash.hajmi]
    return {"sahifa": sahifalash.sahifa, "jami": len(MAHSULOTLAR), "mahsulotlar": natija}
```

Sinash:

```bash
# API kalitsiz - 401 xatosi
curl http://127.0.0.1:8000/mahsulotlar

# To'g'ri API kalit bilan
curl http://127.0.0.1:8000/mahsulotlar?sahifa=2&hajmi=5 \
  -H "X-API-Key: maxfiy-kalit-2026"
```

## Keng tarqalgan xatolar

**Xato 1:** dependency funksiyasini, uni chaqirib (`Depends(funksiya())`), Python funksiyasi obyektini emas, balki uning **natijasini** `Depends()`ga uzatish.
❌ `Depends(sahifalash_parametrlari())` — bu funksiyani darhol, so'rov kelishidan oldin chaqiradi, bu esa FastAPI'ning kutgan xulq-atvoriga zid.
✅ To'g'ri: har doim funksiyaning **o'zini** (qavslarsiz) uzating: `Depends(sahifalash_parametrlari)` — FastAPI uni, so'rov kelganda, o'zi to'g'ri parametrlar bilan chaqiradi.

**Xato 2:** ma'lumotlar bazasi sessiyasi kabi resurslarni ochuvchi dependency'da, `yield` o'rniga `return` ishlatish, natijada resurs hech qachon yopilmasligi.
❌ `return db` — funksiya darhol tugaydi, `finally: db.close()` kabi tozalash kodi hech qachon ishga tushmaydi, bu esa vaqt o'tishi bilan "ochiq ulanishlar" to'planib, resurslar tugashiga olib kelishi mumkin.
✅ To'g'ri: resurs ochish/yopishni talab qiladigan har qanday dependency uchun, har doim `yield` naqshidan (`yield db` + `finally` bloki) foydalaning — bu, so'rov qanday tugashidan (muvaffaqiyatli yoki xato bilan) qat'i nazar, resurs to'g'ri yopilishini kafolatlaydi.

**Xato 3:** bir xil tekshiruv mantig'ini (masalan, autentifikatsiya) har bir endpoint'da alohida, qo'lda takrorlash, `dependencies=[Depends(...)]` orqali router darajasida umumiy qilib qo'ymaslik.
❌ Bu — 10-15 ta endpoint'ga ega router'da, bir xil `Depends(joriy_foydalanuvchi)` qatorini har joyda qo'lda yozishga majbur qiladi, va birontasini unutib qoldirish xavfsizlik teshigiga olib kelishi mumkin.
✅ To'g'ri: agar butun router (yoki ilova) bir xil dependency'ni talab qilsa, uni `APIRouter(dependencies=[...])` (yoki `FastAPI(dependencies=[...])`) darajasida, **bir marta** belgilang — bu, izchillikni ta'minlaydi va xatolarni kamaytiradi.

## Mashq/topshiriq

**(Oson)** `umumiy_savol_belgisi(x: int = 1, y: int = 2)` nomli oddiy dependency funksiyasini yarating (ikkala son yig'indisini qaytarsin) va uni bitta endpoint'da `Depends()` orqali ishlating.

**(O'rtacha)** `TilParametri` nomli klass-asosidagi dependency yarating (`til: str = "uz"` parametri bilan, faqat `"uz"`, `"ru"`, `"en"` qiymatlarini qabul qiladi, aks holda `400` xato). Uni ikkita turli endpoint'da qayta ishlating.

**(Qiyin)** Ikkita zanjirlashtirilgan dependency yarating: birinchisi (`sessiya_tekshirish`) — `Cookie()` orqali `sessiya_id`ni oladi va agar mavjud bo'lmasa `401` xato beradi; ikkinchisi (`admin_ekanini_tekshirish`) — birinchi dependency'ga bog'liq bo'lib, agar `sessiya_id != "admin-sessiya"` bo'lsa, `403` xato beradi. `DELETE /mahsulotlar/{id}` endpoint'ida, ikkinchi dependency'dan foydalaning va butun zanjir qanday ishlashini tushuntirib bering.

## Qisqacha xulosa

Dependency Injection (`Depends()`) — endpoint'lar orasida umumiy mantiqni (validatsiya, ma'lumotlar bazasi ulanishi, autentifikatsiya tekshiruvi) takrorlamasdan qayta ishlatish imkonini beradi; dependency — oddiy funksiya yoki klass bo'lishi mumkin, va u xuddi endpoint kabi, o'z parametrlarini so'rovdan avtomatik oladi. `yield` naqshi — resurslarni (ma'lumotlar bazasi sessiyasi) so'rov tugagandan keyin avtomatik tozalashni ta'minlaydi, dependency'larni zanjirlashtirish esa — murakkab, ko'p bosqichli tekshiruvlarni (masalan, autentifikatsiya → ruxsat tekshiruvi) tabiiy ifodalash imkonini beradi; `dependencies=[...]` orqali, butun router yoki ilova uchun umumiy talablarni bir marta belgilash mumkin. Keyingi darsda, so'rov/javob darajasida ishlaydigan Middleware va CORS sozlamalarini o'rganamiz.
