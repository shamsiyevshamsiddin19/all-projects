# FastAPI nima va nima uchun tanlanadi

## Bu darsda nimalarni o'rganasiz

- FastAPI nima ekanini va u qanday muammoni hal qilishini tushunasiz
- FastAPI'ning Flask va Django'dan asosiy farqlarini bilasiz
- Type hint'lar va asinxron (async) dasturlash tushunchalarining FastAPI'dagi o'rnini tushunasiz
- FastAPI qачон tanlash kerakligi haqida ongli qaror qabul qila olasiz

## Nazariy qism

### FastAPI nima

**FastAPI** — Python'da veb-API (ayniqsa REST API) yaratish uchun zamonaviy, yuqori unumdorlikka ega framework. U Sebastián Ramírez tomonidan 2018-yilda yaratilgan va, nomidan ko'rinib turganidek, ikkita asosiy ustunlik ustiga qurilgan: **tezlik** (ham dastur ishlash tezligi, ham dasturchi kod yozish tezligi) va **avtomatik hujjatlashtirish**.

FastAPI — Python'ning **type hint'lari** (`str`, `int`, `list[str]` kabi tur belgilari) ustiga qurilgan bo'lib, ular nafaqat kod o'qilishini yaxshilaydi, balki FastAPI'ga quyidagilarni **avtomatik** bajarish imkonini beradi:

- Kiruvchi ma'lumotlarni validatsiya qilish (masalan, foydalanuvchi yoshi matn emas, son bo'lishi kerak)
- Ma'lumotlarni to'g'ri turlarga o'giruvchi (masalan, URL'dan kelgan matnni butun songa)
- Interaktiv API hujjatlarini (Swagger UI, ReDoc) **avtomatik** yaratish

### Nima uchun "Fast"

Nomdagi "Fast" so'zi ikki ma'noga ega:

| Ma'no | Tavsif |
|---|---|
| **Ishlash tezligi** | FastAPI — Starlette (ASGI framework) va Pydantic ustiga qurilgan, bu esa uni Node.js va Go bilan taqqoslanadigan tezlikka ega qiladi (Python framework'lari orasida eng tezlaridan biri) |
| **Dasturlash tezligi** | Avtomatik validatsiya, avtomatik hujjatlar va IDE'ning to'liq qo'llab-quvvatlashi (autocomplete) tufayli, xato ehtimoli va yozish vaqti sezilarli kamayadi |

### FastAPI vs Flask vs Django — solishtirma

| Xususiyat | Flask | Django | FastAPI |
|---|---|---|---|
| Asosiy maqsad | Minimalistik, moslashuvchan veb-framework | To'liq qamrovli ("batteries included") veb-framework | Zamonaviy, tez API framework |
| Sinxron/Asinxron | Asosan sinxron (WSGI) | Asosan sinxron (WSGI), qisman async qo'llab-quvvatlash | To'liq asinxron (ASGI), sinxron kodni ham qo'llab-quvvatlaydi |
| Ma'lumot validatsiyasi | Qo'lda yoki qo'shimcha kutubxona (masalan, Marshmallow) | Django Forms/Serializers orqali | **Avtomatik**, Pydantic orqali |
| API hujjatlari | Qo'lda yoki qo'shimcha kutubxona | Django REST Framework orqali qisman avtomatik | **To'liq avtomatik** (OpenAPI standarti asosida) |
| Admin panel | Yo'q | **Bor** (kuchli, tayyor) | Yo'q |
| ORM | Yo'q (odatda SQLAlchemy qo'shiladi) | **Bor** (Django ORM, kuchli) | Yo'q (odatda SQLModel/SQLAlchemy qo'shiladi) |
| Eng mos vaziyat | Kichik xizmatlar, tezkor prototip | To'liq veb-ilova (admin panel, autentifikatsiya, shablon dvigateli bilan) | REST/GraphQL API'lar, mikroservislar, real vaqtli xizmatlar |

> 📌 **Muhim taqqoslash:** agar siz Python darsligi va Django darsligini o'rgangan bo'lsangiz, Django'ning to'liq, "hamma narsa tayyor" yondashuvini bilasiz — admin panel, ORM, shablon tizimi bir paketda. FastAPI esa — ataylab **faqat API qatlamiga** ixtisoslashgan: u sizga admin panel yoki HTML shablon tizimini bermaydi, o'rniga, sof, tez va yaxshi hujjatlashtirilgan API yaratish uchun eng yaxshi vositalarni beradi.

### Asinxron (async) dasturlash — nima uchun muhim

FastAPI — **ASGI** (Asynchronous Server Gateway Interface) standarti asosida ishlaydi, bu esa u bir vaqtning o'zida minglab so'rovlarni, ular ma'lumotlar bazasi yoki tashqi API javobini kutayotganda ham, samarali boshqarish imkonini beradi.

```python
# Sinxron (an'anaviy) yondashuv - so'rov navbatda kutadi
def get_user(user_id: int):
    user = database.query(user_id)  # bu yerda butun dastur "muzlab qoladi"
    return user

# Asinxron yondashuv - kutish vaqtida boshqa so'rovlar ham ishlanadi
async def get_user(user_id: int):
    user = await database.query(user_id)  # kutish vaqtida server band bo'lib qolmaydi
    return user
```

> 📌 **Muhim nuance:** FastAPI — `async def` va oddiy `def` funksiyalarning **ikkalasini ham** qo'llab-quvvatlaydi. Agar sizning kodingiz asinxron kutubxonalardan (masalan, `asyncpg`) foydalanmasa, oddiy `def` bilan yozish ham to'liq to'g'ri — FastAPI buni orqa fonda avtomatik, alohida oqim (thread pool) orqali samarali boshqaradi.

### Pydantic — FastAPI'ning yuragi

**Pydantic** — Python type hint'lariga asoslangan ma'lumotlarni validatsiya qilish kutubxonasi bo'lib, FastAPI'ning barcha "sehri" aslida shu kutubxona ustiga qurilgan. Keyingi bo'limda (02-bob) Pydantic bilan chuqur tanishamiz, lekin asosiy g'oya:

```python
from pydantic import BaseModel

class Foydalanuvchi(BaseModel):
    ism: str
    yosh: int
    email: str
```

Ushbu oddiy klass e'loni orqali, FastAPI avtomatik ravishda: kiruvchi JSON ma'lumotini tekshiradi, xato bo'lsa tushunarli xato xabari qaytaradi, va to'g'ri Python obyektiga aylantiradi — buning barchasi uchun bironta qo'shimcha kod yozish shart emas.

### Qачон FastAPI tanlash kerak

| Vaziyat | Tavsiya |
|---|---|
| REST yoki GraphQL API yaratish kerak | ✅ FastAPI ajoyib tanlov |
| Mikroservis arxitekturasi | ✅ FastAPI'ning yengilligi va tezligi mos keladi |
| Real vaqtli xizmatlar (WebSocket, streaming) | ✅ Asinxron tabiati tufayli juda mos |
| Mashina o'rganish modelini API sifatida taqdim etish | ✅ Sohada eng ko'p tanlanadigan yechimlardan biri |
| To'liq veb-sayt (HTML sahifalar, admin panel, autentifikatsiya tizimi bilan) | ⚠️ Django ko'proq mos kelishi mumkin (tayyor vositalar ko'proq) |
| Juda kichik, bir martalik skript | ⚠️ Flask yoki hatto framework'siz yechim yetarli bo'lishi mumkin |

### FastAPI qanday texnologiyalar ustiga qurilgan

```
FastAPI
  ├── Starlette   - ASGI veb-framework (routing, middleware, WebSocket)
  └── Pydantic    - ma'lumotlarni validatsiya qilish va sozlamalarni boshqarish
```

Bu — FastAPI'ning "g'ildirakni qayta ixtiro qilmasligi", aksincha ikkita ishonchli, sinovdan o'tgan kutubxonani birlashtirib, ularning ustiga qulay, deklarativ interfeys qo'shishini bildiradi.

## Amaliy misol

FastAPI'ning avtomatik hujjatlar va validatsiya imkoniyatini, hali o'rnatmasdan turib, konseptual jihatdan ko'rib chiqamiz (keyingi darsda amalda o'rnatamiz):

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/salom/{ism}")
def salom_ayt(ism: str, yosh: int | None = None):
    if yosh:
        return {"xabar": f"Salom, {ism}! Siz {yosh} yoshdasiz."}
    return {"xabar": f"Salom, {ism}!"}
```

Ushbu sakkiz qatorlik kod, FastAPI ishga tushirilgach, quyidagilarni **avtomatik** ta'minlaydi:

1. `/salom/Shamsiddin?yosh=25` so'rovini qabul qilish
2. `ism` — matn, `yosh` — butun son (yoki bo'sh) ekanini tekshirish
3. Agar `yosh` o'rniga matn yuborilsa — tushunarli xato xabari bilan avtomatik rad etish
4. `/docs` manzilida — shu endpoint uchun to'liq, sinab ko'rish mumkin bo'lgan interaktiv hujjat sahifasini yaratish

Solishtirish uchun, xuddi shu validatsiya va hujjatlashtirishni Flask'da qo'lda amalga oshirish — sezilarli darajada ko'proq kod va qo'shimcha kutubxonalarni talab qiladi.

## Keng tarqalgan xatolar

**Xato 1:** FastAPI'ni Django'ning to'liq o'rnini bosuvchi vosita deb tushunish, va undan HTML sahifalar, admin panel kutish.
❌ FastAPI — ataylab faqat API qatlamiga ixtisoslashgan; unda Django'dagi kabi tayyor admin panel yoki to'liq shablon tizimi mavjud emas (Jinja2 shablonlarini qo'shish mumkin, lekin bu — FastAPI'ning asosiy maqsadi emas).
✅ To'g'ri: agar loyihangizga to'liq veb-sayt (server tomonida render qilinadigan HTML sahifalar, admin panel) kerak bo'lsa, Django'ni ko'rib chiqing; agar sizga faqat tez, yaxshi hujjatlashtirilgan API kerak bo'lsa (masalan, mobil ilova yoki frontend uchun backend), FastAPI to'g'ri tanlov.

**Xato 2:** "async" so'zini ko'rib, barcha funksiyalarni majburiy ravishda `async def` qilib yozishga urinish, hatto sinxron kutubxonalar (masalan, oddiy `requests`) bilan ishlaganda ham.
❌ Agar `async def` funksiya ichida sinxron, "bloklovchi" kod (masalan, oddiy fayl o'qish yoki `time.sleep()`) ishlatilsa, bu — butun serverning samaradorligini **pasaytiradi**, chunki u boshqa so'rovlarni kutish vaqtida qayta ishlay olmay qoladi.
✅ To'g'ri: agar kodingiz asinxron kutubxonalardan (`asyncpg`, `httpx` asinxron rejimida) foydalanmasa, oddiy `def` bilan yozing — FastAPI buni to'g'ri, samarali tarzda boshqaradi.

**Xato 3:** FastAPI'ni faqat "tezligi" uchun tanlash, Pydantic orqali kelayotgan avtomatik validatsiya va hujjatlashtirish afzalliklarini e'tiborsiz qoldirish.
❌ Bu — FastAPI'ning eng katta amaliy foydasini (kamroq qo'lda yozilgan tekshirish kodi, avtomatik va doimo yangilanib turadigan hujjatlar) qo'ldan boy berishga olib keladi.
✅ To'g'ri: FastAPI'dan foydalanishda, Pydantic modellarini to'liq qamrab oluvchi tarzda loyihalashtirish — bu framework'ning eng katta qiymatini olishning kaliti (2-bobda batafsil ko'riladi).

## Mashq/topshiriq

**(Oson)** FastAPI, Flask va Django'ning uchtasini solishtiruvchi jadvalni o'z so'zlaringiz bilan qayta yozib chiqing va har biri qaysi vaziyatda mos kelishini tushuntiring.

**(O'rtacha)** Sinxron (`def`) va asinxron (`async def`) funksiyalar orasidagi farqni, "restoran ofitsianti" kabi kundalik hayotdan metafora orqali tushuntiring (masalan: bitta ofitsiant hamma stolga navbat bilan xizmat qiladimi, yoki bir stol buyurtmani tayyorlashini kutayotganda boshqa stollarga ham qaray oladimi).

**(Qiyin)** Tasavvur qiling — sizdan uchta turli loyiha uchun framework tanlash so'ralmoqda: (1) mashina o'rganish modelini boshqa dasturchilar ishlatishi uchun API sifatida chiqarish, (2) online-do'kon uchun to'liq veb-sayt (mahsulotlar katalogi, admin panel, buyurtmalar), (3) mobil ilova uchun backend, real vaqtli chat funksiyasi bilan. Har biri uchun qaysi framework'ni (FastAPI, Django yoki Flask) tanlagan bo'lardingiz va nima uchun, batafsil asoslab bering.

(3) FastAPI — chunki backend + real vaqtli funksiya (WebSocket) kerak, FastAPI'ning asinxron tabiati va WebSocket qo'llab-quvvatlashi bunga juda mos, mobil ilova esa HTML sahifalarni emas, balki JSON API'ni talab qiladi.

## Qisqacha xulosa

FastAPI — Python type hint'lari va Pydantic ustiga qurilgan, yuqori unumdorlikka ega, asinxron (ASGI) veb-API framework bo'lib, uning asosiy afzalligi — kiruvchi ma'lumotlarni avtomatik validatsiya qilish va OpenAPI standarti asosida interaktiv hujjatlarni (Swagger UI/ReDoc) avtomatik yaratish. Django'dan farqli o'laroq, FastAPI faqat API qatlamiga ixtisoslashgan (admin panel yoki shablon tizimisiz), Flask'dan farqli o'laroq esa, validatsiya va hujjatlashtirish "quti ichidan tayyor" keladi. FastAPI — REST API'lar, mikroservislar va real vaqtli xizmatlar uchun ayniqsa mos keladi, keyingi darsda uni Ubuntu muhitida o'rnatishdan boshlaymiz.
