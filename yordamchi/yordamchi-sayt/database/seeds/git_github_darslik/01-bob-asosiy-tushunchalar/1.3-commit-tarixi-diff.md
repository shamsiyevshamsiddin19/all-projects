# Commit tarixini ko'rish va o'zgarishlarni solishtirish (diff)

## Bu darsda nimalarni o'rganasiz

- `git log`ning turli formatlarini chuqurroq o'zlashtirasiz
- `git diff` orqali o'zgarishlarni qanday ko'rishni bilasiz
- `git show` bilan muayyan commit tafsilotlarini ko'rasiz
- Commit'larni taqqoslash va o'zgarishlarni tahlil qilishni o'rganasiz

## Nazariy qism

### `git diff` — nima o'zgargan

`git diff` — fayllardagi **hali commit qilinmagan** o'zgarishlarni ko'rsatadi. Bu — commit qilishdan oldin, aynan nima o'zgarganini tekshirishning eng muhim vositasi.

```bash
git diff
```

Turli holatlar uchun `diff`:

| Buyruq | Nimani ko'rsatadi |
|---|---|
| `git diff` | Working Directory vs Staging Area (hali `add` qilinmagan o'zgarishlar) |
| `git diff --staged` | Staging Area vs oxirgi commit (`add` qilingan, lekin hali commit qilinmagan) |
| `git diff HEAD` | Working Directory vs oxirgi commit (barcha o'zgarishlar, staged bo'lsin yoki yo'q) |
| `git diff <commit1> <commit2>` | Ikki commit orasidagi farq |
| `git diff -- fayl.py` | Faqat aniq bir faylning o'zgarishlari |

### `diff` natijasini o'qish

```diff
diff --git a/main.py b/main.py
index a1b2c3d..e4f5g6h 100644
--- a/main.py
+++ b/main.py
@@ -1,4 +1,5 @@
 def salom():
-    print("Salom")
+    print("Salom, dunyo!")
+    print("Bu - yangi qator")
```

| Belgi | Ma'nosi |
|---|---|
| `-` (qizil) | O'chirilgan qator |
| `+` (yashil) | Qo'shilgan qator |
| bo'sh boshlanuvchi | O'zgarmagan, kontekst uchun ko'rsatilgan qator |
| `@@ -1,4 +1,5 @@` | "Eski faylning 1-qatoridan 4 tasi, yangisining 1-qatoridan 5 tasi" |

### `git log` — chuqurroq imkoniyatlar

Oldingi darsda ko'rilgan `git log --oneline --graph`dan tashqari, yana foydali variantlar:

```bash
# Har bir commit'da qaysi fayllar o'zgarganini ko'rsatish
git log --stat

# Har bir commit'ning to'liq diff'ini ko'rsatish
git log -p

# Faqat muayyan faylga tegishli tarixni ko'rish
git log -- main.py

# Commit izohi ichida so'z qidirish
git log --grep="xato"

# Muayyan sanalar oralig'ida
git log --since="2026-01-01" --until="2026-02-01"

# Chiroyli, moslashtirilgan format
git log --pretty=format:"%h - %an, %ar : %s"
```

`--pretty=format` uchun asosiy belgilar:

| Belgi | Ma'nosi |
|---|---|
| `%h` | Qisqartirilgan commit hash |
| `%an` | Muallif ismi |
| `%ar` | Nisbiy vaqt ("2 kun oldin") |
| `%s` | Commit izohi (subject) |
| `%d` | Branch/tag ma'lumoti |

### `git show` — bitta commit haqida to'liq ma'lumot

```bash
git show a1b2c3d
```

Bu buyruq — muayyan commit haqida: kim, qachon, qanday izoh bilan, va **aynan qanday o'zgarishlar** kiritilganini (diff bilan birga) to'liq ko'rsatadi.

```bash
# Faqat oxirgi commit
git show HEAD

# Ikkita commit orqadagi
git show HEAD~2
```

`HEAD~1`, `HEAD~2` — "HEAD'dan 1 ta, 2 ta commit orqada" degan ma'noni bildiradi (bu belgilash keyingi darslarda `reset`/`revert` bilan ishlashda ham qo'llaniladi).

### `git diff` grafik vositalarda

Terminal diff'ini o'qish qiyin bo'lsa, VS Code kabi muharrirlar o'zgarishlarni rangli, qulay formatda ko'rsatadi (Source Control panel orqali) — amaliyotda ko'pchilik dasturchilar buni afzal ko'radi, ammo terminal `diff`ni tushunish — muammo tuzatishda (masalan, SSH orqali serverga ulanganda) muhim ko'nikma bo'lib qoladi.

## Amaliy misol

To'liq ish jarayoni — o'zgarishlarni bosqichma-bosqich tekshirish:

```bash
mkdir diff-mashqi && cd diff-mashqi && git init
echo "versiya = 1" > sozlamalar.py
git add sozlamalar.py
git commit -m "Boshlang'ich sozlamalar fayli"

# Faylni o'zgartiramiz
echo "versiya = 2" > sozlamalar.py

# Hali staged emas - working directory vs staging area
git diff
# -versiya = 1
# +versiya = 2

# Endi staging'ga qo'shamiz
git add sozlamalar.py

# git diff endi bo'sh - chunki o'zgarish staged bo'ldi
git diff
# (hech narsa ko'rsatmaydi)

# --staged bilan ko'ramiz
git diff --staged
# -versiya = 1
# +versiya = 2

git commit -m "Versiyani 2 ga oshirish"

# Butun tarixni ko'ramiz
git log --oneline
# e4f5g6h Versiyani 2 ga oshirish
# a1b2c3d Boshlang'ich sozlamalar fayli

# Oxirgi commit tafsilotlari
git show HEAD
```

Ikki muayyan commit orasidagi farqni solishtirish:

```bash
git diff a1b2c3d e4f5g6h
```

## Keng tarqalgan xatolar

**Xato 1:** `git diff` bo'sh natija berganidan hayron bo'lish, aslida o'zgarishlar `git add` qilingan bo'lganda.
❌ `git diff`ning o'zi faqat **staged bo'lmagan** o'zgarishlarni ko'rsatadi — agar allaqachon `git add` qilingan bo'lsa, u yerda ko'rinmaydi.
✅ To'g'ri: staged o'zgarishlarni ko'rish uchun `git diff --staged` (yoki `git diff --cached`, ular sinonim), barcha o'zgarishlarni (staged + staged bo'lmagan) ko'rish uchun `git diff HEAD` ishlatiladi.

**Xato 2:** `git log`ning uzun, standart chiqishidan (har bir commit uchun 5-6 qator) charchab, tarixni umuman tekshirmaslik.
❌ Standart `git log` — katta loyihalarda o'qish qiyin, ko'p joy egallaydi.
✅ To'g'ri: kundalik ishda `git log --oneline --graph` (qisqa va vizual), tafsilot kerak bo'lganda `git show <hash>` yoki `git log -p -- fayl.py` (faqat kerakli faylga) ishlatilishi kerak.

**Xato 3:** commit hash'ini to'liq (40 belgili) nusxalab, buyruqqa yopishtirish.
❌ Bu — ishlaydi, lekin noqulay va xato qilish ehtimoli yuqori (uzun qatorni noto'g'ri nusxalash).
✅ To'g'ri: Git — hash'ning **birinchi 7-8 belgisi** (masalan, `a1b2c3d`) allaqachon deyarli har doim yetarli darajada noyob ekanini tan oladi; `git log --oneline` natijasidagi qisqa hash'lardan foydalaning.

## Mashq/topshiriq

**(Oson)** Yangi faylda matn yozing, `git add` qilmasdan turib `git diff` buyrug'ini ishga tushiring va natijani tahlil qiling (qaysi qatorlar `+`, qaysilari kontekst).

**(O'rtacha)** Bir faylni ketma-ket 3 marta o'zgartirib, har safar commit qiling. So'ng `git log --oneline` bilan barcha commit hash'larini ko'ring va `git diff <birinchi-hash> <uchinchi-hash>` orqali eng birinchi va eng oxirgi holat orasidagi umumiy farqni ko'ring.

**(Qiyin)** `git log --pretty=format:"%h - %an, %ar : %s"` buyrug'ini ishga tushiring va uning standart `git log`dan nima farqi borligini, har bir `%` belgisi nimani anglatishini tushuntirib bering. Keyin `git show HEAD~1` bilan "oxirgidan bitta oldingi" commit ma'lumotini oling.

<details>
<summary>Javoblarni ko'rish</summary>

1. `echo "test = True" > yangi.py && git diff` — chunki fayl hali `git add` qilinmagan (untracked), oddiy `git diff` uni umuman ko'rsatmasligi mumkin (untracked fayllar `diff`da ko'rinmaydi, faqat allaqachon tracked fayllardagi o'zgarishlar ko'rinadi) — bu muhim nuance: yangi faylni ko'rish uchun avval `git add` qilib, keyin `git diff --staged` ishlatish kerak.
2. Uchta commit qilingandan so'ng `git log --oneline` uchta hash'ni ko'rsatadi (masalan `c3, b2, a1`, eng yangisi tepada); `git diff a1 c3` — eng birinchi va eng oxirgi commit orasidagi **umumiy** o'zgarishni (oraliqdagi barcha o'zgarishlarni jamlab) ko'rsatadi.
3. `--pretty=format` — standart ko'p qatorli formatni bitta qatorga, moslashtirilgan ko'rinishga siqadi: `%h` qisqa hash, `%an` muallif ismi, `%ar` nisbiy vaqt, `%s` commit izohi; `git show HEAD~1` — HEAD'dan bitta orqadagi (oxirgidan oldingi) commit haqida to'liq ma'lumot (muallif, sana, izoh, diff) beradi.

</details>

## Qisqacha xulosa

`git diff` — hali commit qilinmagan o'zgarishlarni ko'rsatadi (`--staged` bayrog'i bilan staged o'zgarishlarni, bayrogsiz esa staged bo'lmaganlarini), `+`/`-` belgilar orqali qo'shilgan/o'chirilgan qatorlarni aniq ajratib beradi; `git log`ning `--stat`, `-p`, `--grep`, `--pretty=format` kabi variantlari tarixni turli burchaklardan tahlil qilish imkonini beradi; `git show <hash>` esa muayyan bitta commit haqida to'liq (muallif, sana, diff) ma'lumot beradi — bu uchta vosita birgalikda, loyiha tarixida "nima, qachon va nima uchun o'zgargani"ni tushunishning asosiy vositalari hisoblanadi.
