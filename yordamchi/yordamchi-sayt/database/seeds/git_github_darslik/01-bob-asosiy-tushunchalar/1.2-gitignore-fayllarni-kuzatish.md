# .gitignore va fayllarni kuzatish holatlari

## Bu darsda nimalarni o'rganasiz

- Git'dagi fayllarning uch holatini (tracked/untracked/ignored) farqlaysiz
- `.gitignore` fayli qanday ishlashini va sintaksisini tushunasiz
- Python, Django va Docker loyihalari uchun amaliy `.gitignore` shabloni yaratasiz
- Allaqachon kuzatilayotgan faylni qanday e'tiborsiz qoldirishni bilasiz

## Nazariy qism

### Fayllarning uch holati

Git'da har bir fayl uchta holatdan birida bo'lishi mumkin:

| Holat | Ma'nosi |
|---|---|
| **Tracked** | Git bu faylni kuzatib boradi (avval `git add` qilingan) |
| **Untracked** | Git bu faylni bilmaydi, hali kuzatilmagan (`git status`da qizil rangda ko'rinadi) |
| **Ignored** | Git bu faylni ataylab e'tiborsiz qoldiradi (`.gitignore` orqali) |

Har bir loyihada Git kuzatishi **shart bo'lmagan** fayllar bo'ladi: vaqtinchalik fayllar, kompilyatsiya natijalari, shaxsiy sozlamalar, katta binary fayllar. Bunday fayllarni tasodifan commit qilib qo'yish — keng tarqalgan xato (masalan, parollarni o'z ichiga olgan `.env` faylini GitHub'ga yuklab yuborish).

### `.gitignore` nima

`.gitignore` — loyiha papkasining ildizida joylashgan oddiy matn fayli bo'lib, unda Git **e'tiborsiz qoldirishi kerak bo'lgan** fayl/papka naqshlari (patterns) ro'yxati keltiriladi.

```bash
# Loyiha ildizida yaratish
touch .gitignore
```

### Asosiy sintaksis

```gitignore
# Bu qator - izoh (# bilan boshlanadi)

# Aniq fayl nomi
sirli_parol.txt

# Kengaytma bo'yicha - barcha .pyc fayllar
*.pyc

# Butun papka
venv/
__pycache__/

# Papka ichidagi aniq joylashuv
config/local_settings.py

# Istisno - .gitignore qoidasidan chiqarish (! belgisi)
!config/local_settings.example.py

# Barcha darajadagi bir xil nomli papkalar
**/node_modules/
```

| Naqsh | Nimani anglatadi |
|---|---|
| `fayl.txt` | Aynan shu nomli fayl (istalgan papkada) |
| `*.log` | Kengaytmasi `.log` bo'lgan barcha fayllar |
| `papka/` | Oxiridagi `/` — bu papka ekanini bildiradi |
| `/fayl.txt` | Boshidagi `/` — faqat loyiha ildizidagi fayl |
| `**/papka/` | Istalgan chuqurlikdagi shu nomli papka |
| `!fayl.txt` | Yuqoridagi qoidadan istisno qilish |

### Python/Django loyihasi uchun amaliy `.gitignore`

```gitignore
# Python
__pycache__/
*.pyc
*.pyo
venv/
env/
.venv/

# Django
*.sqlite3
/media/
/staticfiles/
db.sqlite3

# Maxfiy ma'lumotlar
.env
*.env.local

# IDE
.vscode/
.idea/

# Docker
*.log

# OS
.DS_Store
```

> 📌 **Eslatma:** Bu ro'yxat — Python darsligi (2-bob, virtual muhitlar) va Django darsligida yaratilgan loyihalar bilan to'g'ridan-to'g'ri bog'liq: `venv/` va `__pycache__/` — har doim e'tiborsiz qoldirilishi kerak bo'lgan birinchi ikkita qator.

### Tayyor shablonlardan foydalanish

GitHub — turli dasturlash tillari uchun tayyor `.gitignore` shablonlar to'plamini taqdim etadi: [github.com/github/gitignore](https://github.com/github/gitignore). Yangi loyiha yaratganda, GitHub'da repository yaratish jarayonida ".gitignore template" bo'limidan tilni tanlash ham mumkin (3-bobda ko'ramiz).

### Allaqachon kuzatilayotgan faylni e'tiborsiz qoldirish

Muammo: agar fayl **avvalroq** `git add`/`git commit` qilingan bo'lsa, uni `.gitignore`ga qo'shish **kifoya qilmaydi** — Git uni baribir kuzatishda davom etadi, chunki u allaqachon "tracked" holatda.

Yechim — faylni Git kuzatuvidan chiqarish (lekin diskdan o'chirmasdan):

```bash
git rm --cached sirli_fayl.txt
```

Papka uchun:

```bash
git rm -r --cached venv/
```

Shundan so'ng, `.gitignore`ga qo'shilgan fayl endi kuzatilmaydi, lekin diskda joyida qoladi.

### `git status --ignored` — ignored fayllarni ko'rish

```bash
git status --ignored
```

Bu buyruq — odatiy `git status` yashiradigan (ignored) fayllarni ham ko'rsatadi, `.gitignore` to'g'ri ishlayotganini tekshirish uchun foydali.

## Amaliy misol

To'liq ish jarayoni — Django loyihasida `.gitignore` sozlash:

```bash
mkdir mening-django-loyiham && cd mening-django-loyiham
git init

# Loyiha fayllarini yaratamiz (misol uchun)
mkdir venv __pycache__
touch main.py db.sqlite3 .env

# Hozircha .gitignore yo'q - hamma narsa "untracked"
git status
# Untracked files: .env  __pycache__/  db.sqlite3  main.py  venv/

# .gitignore yaratamiz
cat > .gitignore << 'EOF'
venv/
__pycache__/
*.sqlite3
.env
EOF

git status
# Untracked files: .gitignore  main.py
# (venv/, __pycache__/, db.sqlite3, .env - endi ko'rinmaydi)

git add .gitignore main.py
git commit -m "Loyiha boshlang'ich tuzilmasi va .gitignore qo'shildi"
```

Agar `.env` fayli **tasodifan** avvalroq commit qilingan bo'lsa:

```bash
# Avval .gitignore-ga qo'shamiz
echo ".env" >> .gitignore

# Keyin Git kuzatuvidan olib tashlaymiz (diskdan o'chmaydi)
git rm --cached .env
git commit -m ".env faylini kuzatuvdan olib tashlash"
```

## Keng tarqalgan xatolar

**Xato 1:** `.env` yoki parollarni o'z ichiga olgan faylni `.gitignore`siz commit qilish, keyin GitHub'ga push qilish.
❌ Bu — maxfiy ma'lumotlar (API kalitlar, parollar, `SECRET_KEY`) butun internetga ochiq bo'lib qolishiga olib keladi, hatto faylni keyinroq o'chirsangiz ham, u commit tarixida saqlanib qoladi.
✅ To'g'ri: loyihani boshlashning **birinchi qadami** sifatida `.gitignore` faylini yarating va `.env`ni birinchi qatorlardan biri sifatida qo'shing — hech qachon maxfiy ma'lumotni birinchi commit'dan oldin tekshirmasdan qoldirmang.

**Xato 2:** faylni `.gitignore`ga qo'shib, lekin u baribir `git status`da ko'rinishidan hayron bo'lish.
❌ Sabab — fayl allaqachon "tracked" holatda (avvalroq `git add` qilingan), `.gitignore` faqat **hali kuzatilmagan** fayllarga ta'sir qiladi.
✅ To'g'ri: `git rm --cached <fayl>` buyrug'i bilan faylni kuzatuvdan chiqaring, keyin commit qiling.

**Xato 3:** `.gitignore`ni umuman yaratmaslik, natijada `venv/` (minglab fayl) yoki `__pycache__/` kabi papkalar repository'ga qo'shilib, loyiha hajmini keraksiz shishirib yuborish.
❌ Bunday holatda repository o'lchami g'ayritabiiy katta bo'ladi, `git clone` sekinlashadi, va boshqa dasturchilar bilan hamkorlikda keraksiz konfliktlar yuzaga keladi.
✅ To'g'ri: har qanday yangi loyihani boshlashda darhol tegishli `.gitignore` shablonini qo'shing (tilga mos: Python, Node.js va h.k.).

## Mashq/topshiriq

**(Oson)** Yangi papka yarating, ichida `sirli.txt` va `dastur.py` fayllarini yarating, so'ng `.gitignore` fayli yaratib, faqat `sirli.txt` e'tiborsiz qoldirilishini ta'minlang. `git status` orqali tekshiring.

**(O'rtacha)** Python/Django loyihasi uchun to'liq `.gitignore` faylini yozing — kamida `venv/`, `__pycache__/`, `.env`, `*.sqlite3`, `.vscode/` qatorlarini qo'shing.

**(Qiyin)** `maxfiy_kalit.txt` faylini yarating va uni **avval** `.gitignore`siz commit qiling (`git add`, `git commit`). Keyin uni `.gitignore`ga qo'shing va nima bo'lishini kuzating (`git status`). So'ng uni to'g'ri tarzda kuzatuvdan olib tashlang va sababini tushuntiring.

## Qisqacha xulosa

`.gitignore` fayli — Git'ga qaysi fayl va papkalarni **hech qachon kuzatmaslik** kerakligini aytadi (kengaytma, aniq nom yoki papka naqshlari orqali); bu — vaqtinchalik fayllar, virtual muhitlar (`venv/`) va eng muhimi, maxfiy ma'lumotlar (`.env`, parollar) tasodifan commit qilinib, GitHub'ga yuklanib ketishining oldini oladi. Muhim nozik jihat: `.gitignore` faqat **hali kuzatilmagan** fayllarga ta'sir qiladi — allaqachon kuzatilayotgan faylni chiqarib tashlash uchun `git rm --cached` buyrug'i kerak bo'ladi.
