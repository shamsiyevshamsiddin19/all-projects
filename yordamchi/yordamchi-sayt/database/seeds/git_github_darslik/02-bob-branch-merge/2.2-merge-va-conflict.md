# Merge va konfliktlarni hal qilish

## Bu darsda nimalarni o'rganasiz

- `git merge` orqali branch'larni birlashtirishni o'rganasiz
- Fast-forward va uch-tomonlama (3-way) merge farqini tushunasiz
- Merge conflict nima uchun yuzaga kelishini va uni qanday hal qilishni bilasiz
- Merge'ni bekor qilish (`--abort`) imkoniyatini o'rganasiz

## Nazariy qism

### Merge nima

**Merge** — ikkita branch'ning tarixini birlashtirish jarayoni. Odatda: feature branch'da tayyor bo'lgan ishni, qaytadan `main`ga qo'shish uchun ishlatiladi.

```bash
# Avval, qaysi branch'ga BIRLASHTIRMOQCHI bo'lsangiz, o'shanga o'ting
git switch main

# Boshqa branch'ni joriy branch'ga birlashtiring
git merge feature/yangi-funksiya
```

> ⚠️ **Muhim tartib:** `git merge <boshqa-branch>` — har doim **joriy** branch'ga, ko'rsatilgan branch'ni qo'shadi. Ya'ni avval `main`ga o'tib, keyin `git merge feature/x` qilinsa, `feature/x`dagi o'zgarishlar `main`ga qo'shiladi (aksincha emas).

### Fast-forward merge

Agar `main` branch'ida, feature branch ochilgandan beri **hech qanday yangi commit** bo'lmagan bo'lsa, Git eng oddiy usulni qo'llaydi — **fast-forward**: `main` ko'rsatkichi shunchaki feature branch'ning oxirgi commit'iga "siljitiladi", yangi merge commit yaratilmaydi.

```
Merge'dan oldin:
main:              A---B
                        \
feature:                 C---D

Fast-forward merge'dan keyin:
main:              A---B---C---D
```

### Uch-tomonlama (3-way) merge

Agar `main`da ham, feature branch'da ham **alohida yangi commit'lar** bo'lgan bo'lsa, Git ikkala tarixni birlashtirib, yangi **merge commit** yaratadi (ikkita ota-commit'ga ega bo'lgan maxsus commit):

```
Merge'dan oldin:
main:              A---B---E
                        \
feature:                 C---D

3-way merge'dan keyin:
main:              A---B---E---F  (F - merge commit, ikkita ota: E va D)
                        \       /
feature:                 C-----D
```

### Merge conflict — nima uchun yuzaga keladi

**Konflikt** — ikkala branch **bir xil faylning bir xil qatorini** turlicha o'zgartirganda yuzaga keladi. Git bu holatda, qaysi o'zgarish "to'g'ri" ekanligini **avtomatik hal qila olmaydi** va inson aralashuvini talab qiladi.

```bash
git switch main
git merge feature/narx-ozgarishi
```

```
Auto-merging narxlar.py
CONFLICT (content): Merge conflict in narxlar.py
Automatic merge failed; fix conflicts and then commit the result.
```

Konflikt yuzaga kelgan faylni ochsangiz, quyidagicha maxsus belgilar ko'rinadi:

```python
<<<<<<< HEAD
narx = 100000
=======
narx = 120000
>>>>>>> feature/narx-ozgarishi
```

| Belgi | Ma'nosi |
|---|---|
| `<<<<<<< HEAD` | Joriy branch (`main`)dagi versiya boshlanishi |
| `=======` | Ikki versiya orasidagi chegara |
| `>>>>>>> feature/...` | Birlashtirilayotgan branch'dagi versiya oxiri |

### Konfliktni hal qilish qadamlari

1. Konflikt bo'lgan faylni oching
2. Qaysi o'zgarish (yoki ikkalasining kombinatsiyasi) kerakligini **qo'lda** tanlang
3. `<<<<<<<`, `=======`, `>>>>>>>` maxsus belgilarini **butunlay o'chirib tashlang**
4. Faylni saqlang
5. `git add <fayl>` — konflikt hal qilinganini Git'ga bildirasiz
6. `git commit` — merge'ni yakunlaysiz (odatda tayyor izoh avtomatik taklif qilinadi)

```bash
# Konfliktni ko'rish
git status
# both modified: narxlar.py

# Faylni tahrirlab, konfliktni hal qilamiz (masalan, nano orqali)
nano narxlar.py

# Hal qilingandan keyin - natijada faqat:
# narx = 120000

git add narxlar.py
git commit -m "Merge feature/narx-ozgarishi: narx konfliktini hal qilish"
```

### Merge'ni bekor qilish

Agar konflikt murakkab bo'lib, hozircha uni hal qilishni istamasangiz, merge jarayonini **to'liq bekor qilish** mumkin:

```bash
git merge --abort
```

Bu buyruq — merge boshlanishidan oldingi holatga to'liq qaytaradi, hech qanday iz qoldirmaydi.

### `git status` — konflikt paytida yo'l ko'rsatuvchi

Konflikt vaqtida `git status` ishga tushirish — qaysi fayllarda konflikt borligini va keyingi qadamlar haqida foydali ko'rsatmalarni ko'rsatadi. Bu buyruqni tez-tez ishlatish tavsiya etiladi.

## Amaliy misol

To'liq ish jarayoni — konfliktni yaratish va hal qilish:

```bash
mkdir merge-mashqi && cd merge-mashqi && git init
echo "narx = 100000" > narxlar.py
git add narxlar.py
git commit -m "Boshlang'ich narx"

# Feature branch yaratamiz va o'zgartiramiz
git switch -c feature/narx-ozgarishi
echo "narx = 120000" > narxlar.py
git add narxlar.py
git commit -m "Narxni 120000 ga oshirish"

# main'ga qaytib, U YERDA HAM o'sha faylni o'zgartiramiz (konflikt uchun)
git switch main
echo "narx = 90000" > narxlar.py
git add narxlar.py
git commit -m "Narxni 90000 ga tushirish (chegirma)"

# Endi birlashtiramiz - KONFLIKT yuzaga keladi
git merge feature/narx-ozgarishi
# CONFLICT (content): Merge conflict in narxlar.py

cat narxlar.py
# <<<<<<< HEAD
# narx = 90000
# =======
# narx = 120000
# >>>>>>> feature/narx-ozgarishi

# Qo'lda hal qilamiz - masalan, ikkalasining o'rtachasini tanlaymiz
echo "narx = 105000" > narxlar.py

git add narxlar.py
git commit -m "Merge: narx konfliktini 105000 ga muvofiqlashtirish"

git log --oneline --graph
```

## Keng tarqalgan xatolar

**Xato 1:** konflikt belgilarini (`<<<<<<<`, `=======`, `>>>>>>>`) faylda **qoldirib**, shunchaki `git add` va `git commit` qilish.
❌ Bu — dastur kodida sintaksis xatosiga yoki noto'g'ri ishlaydigan mantiqqa olib keladi, chunki bu belgilar Python (yoki boshqa til) sintaksisi emas.
✅ To'g'ri: konfliktni hal qilishda, maxsus belgilarning **barchasini** o'chirib, faqat kerakli, ishlaydigan kodni qoldiring — commit qilishdan oldin faylni albatta ko'zdan kechiring.

**Xato 2:** katta, murakkab konfliktga duch kelganda, panika qilib, tasodifiy o'zgarishlar kiritish.
❌ Bu — kodning mantig'ini buzishi va yangi xatolarni keltirib chiqarishi mumkin.
✅ To'g'ri: agar konflikt murakkab bo'lsa, `git merge --abort` bilan xavfsiz orqaga qayting, vaziyatni tinch tahlil qiling (kerak bo'lsa, `git log`/`git diff` bilan ikkala branch tarixini o'rganing), so'ng qaytadan urinib ko'ring.

**Xato 3:** merge commit'siz, faqat fast-forward merge'ga tayanib, keyinchalik loyiha tarixida "qachon, qaysi feature qo'shilgani" haqidagi ma'lumotni yo'qotish.
❌ Fast-forward merge — tarixni "tekislaydi", ba'zan qaysi commit'lar aslida qaysi feature'ga tegishli ekanini aniqlash qiyinlashadi.
✅ To'g'ri: muhim feature'larni birlashtirishda, `git merge --no-ff feature/...` bayrog'idan foydalanish mumkin — bu fast-forward imkoni bo'lsa ham, **majburiy ravishda** merge commit yaratadi, natijada tarixda "bu yerda feature birlashtirilgan" degan aniq nuqta saqlanib qoladi.

## Mashq/topshiriq

**(Oson)** Ikkita branch yarating, ularda turli fayllarga (konflikt bo'lmaydigan) o'zgartirish kiriting, so'ng ularni `main`ga birlashtiring va natijani kuzating.

**(O'rtacha)** Amaliy misoldagi kabi, ataylab konflikt yarating (ikkala branch bir xil faylning bir xil qatorini o'zgartirsin), so'ng uni qo'lda hal qiling va merge commit yarating.

**(Qiyin)** Xuddi shunday konflikt yarating, lekin bu safar uni hal qilish o'rniga `git merge --abort` bilan bekor qiling. `git status` va `git log` orqali loyiha xuddi merge boshlanmagandek holatga qaytganini tasdiqlang. Keyin `--no-ff` bayrog'i bilan fast-forward mumkin bo'lgan holatda ham majburiy merge commit yaratib ko'ring va farqini tushuntiring.

## Qisqacha xulosa

`git merge <branch>` — joriy branch'ga ko'rsatilgan branch'ni birlashtiradi: agar oraliq yangi commit'lar bo'lmasa fast-forward (oddiy ko'rsatkich siljishi) sodir bo'ladi, aks holda yangi merge commit yaratiladi; ikkala branch bir xil qatorni turlicha o'zgartirganda **konflikt** yuzaga keladi, bu holatda Git faylni `<<<<<<<`/`=======`/`>>>>>>>` belgilari bilan belgilaydi va inson aralashuvini talab qiladi — konfliktni hal qilish uchun kerakli kodni qoldirib, maxsus belgilarni o'chirish, so'ng `git add` va `git commit` qilish kerak; murakkab holatlarda `git merge --abort` — xavfsiz orqaga qaytish imkonini beradi.
