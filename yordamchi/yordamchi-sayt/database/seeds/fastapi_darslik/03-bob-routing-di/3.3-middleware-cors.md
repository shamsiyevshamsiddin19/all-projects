# Middleware va CORS

## Bu darsda nimalarni o'rganasiz

- Middleware nima ekanini va u qачон ishlatilishini tushunasiz
- O'z maxsus middleware'ingizni yozishni o'rganasiz
- CORS (Cross-Origin Resource Sharing) muammosini va uning yechimini tushunasiz
- FastAPI'ning tayyor middleware'laridan (`CORSMiddleware`, `GZipMiddleware`) foydalanishni bilasiz

## Nazariy qism

### Middleware nima

**Middleware** — har bir HTTP so'rov, asosiy endpoint funksiyasiga yetib borishidan **oldin**, va javob mijozga qaytarilishidan **oldin**, ishga tushadigan oraliq qatlam. Uni "har bir so'rov o'tishi shart bo'lgan nazorat punkti" deb tasavvur qilish mumkin.

```
Mijoz so'rovi → [Middleware 1] → [Middleware 2] → Endpoint funksiya → [Middleware 2] → [Middleware 1] → Mijozga javob
```

### Dependency vs Middleware — farqi

| Xususiyat | Dependency (`Depends`) | Middleware |
|---|---|---|
| Qamrov | Muayyan endpoint(lar) uchun, aniq belgilanadi | **Barcha** so'rovlar uchun, avtomatik |
| Kirish huquqi | So'rov parametrlariga (aniq, tur bilan) | Xom so'rov/javob obyektiga |
| Odatiy qo'llanilishi | Validatsiya, autentifikatsiya, ma'lumotlar bazasi sessiyasi | Logging, CORS, siqish (compression), umumiy vaqt o'lchash |

### O'z middleware'ingizni yozish

```python
import time
from fastapi import FastAPI, Request

app = FastAPI()

@app.middleware("http")
async def vaqt_olchash_middleware(request: Request, call_next):
    boshlanish_vaqti = time.time()
    javob = await call_next(request)
    ishlash_vaqti = time.time() - boshlanish_vaqti
    javob.headers["X-Ishlash-Vaqti"] = str(round(ishlash_vaqti, 4))
    return javob
```

| Qism | Vazifasi |
|---|---|
| `request: Request` | Kiruvchi xom so'rov obyekti (URL, header'lar, va h.k.) |
| `call_next(request)` | Keyingi middleware'ni (yoki oxir-oqibat, endpoint funksiyasini) chaqiradi |
| `javob` | `call_next()`dan qaytgan javob — uni o'zgartirish (masalan, header qo'shish) mumkin |

Bu middleware — **har bir** so'rov uchun, javob header'iga qancha vaqt ketganini avtomatik qo'shadi, hech qanday endpoint funksiyasini o'zgartirmasdan.

### Logging middleware — amaliy misol

```python
import logging
from fastapi import FastAPI, Request

logger = logging.getLogger("fastapi_app")
app = FastAPI()

@app.middleware("http")
async def log_middleware(request: Request, call_next):
    logger.info(f"So'rov keldi: {request.method} {request.url.path}")
    javob = await call_next(request)
    logger.info(f"Javob yuborildi: {javob.status_code}")
    return javob
```

### CORS muammosi nima

**CORS (Cross-Origin Resource Sharing)** — brauzerlarning xavfsizlik mexanizmi bo'lib, standart holda, bir domendan (masalan, `https://frontend.uz`) yuklangan JavaScript kodi, **boshqa** domendagi (masalan, `https://api.backend.uz`) API'ga so'rov yuborishini **taqiqlaydi** — agar server bunga aniq ruxsat bermasa.

Bu — real loyihalarda juda tez-tez uchraydigan vaziyat: frontend (React, Vue) — bir manzilda (masalan, `localhost:3000`), backend (FastAPI) — boshqa manzilda (`localhost:8000`) ishlaydi. CORS sozlanmasa, brauzer konsolida quyidagiga o'xshash xato ko'rinadi:

```
Access to fetch at 'http://localhost:8000/mahsulotlar' from origin 
'http://localhost:3000' has been blocked by CORS policy
```

### `CORSMiddleware` — yechim

FastAPI, Starlette'dan meros olgan, tayyor `CORSMiddleware`ni taqdim etadi:

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

RUXSAT_ETILGAN_MANZILLAR = [
    "http://localhost:3000",
    "https://mening-saytim.uz",
]

app.add_middleware(
    CORSMiddleware,
    allow_origins=RUXSAT_ETILGAN_MANZILLAR,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

| Parametr | Vazifasi |
|---|---|
| `allow_origins` | Qaysi domenlardan so'rov qabul qilinishiga ruxsat berish |
| `allow_credentials` | Cookie va autentifikatsiya ma'lumotlarini yuborishga ruxsat berish |
| `allow_methods` | Qaysi HTTP metodlarga (`GET`, `POST`, va h.k.) ruxsat berish (`["*"]` — barchasiga) |
| `allow_headers` | Qaysi maxsus header'larga ruxsat berish |

> ⚠️ **Xavfsizlik ogohlantirishi:** `allow_origins=["*"]` (barcha domenlarga ruxsat) — faqat rivojlantirish (development) bosqichida yoki chinakam **ochiq, umumiy** API'lar uchun mos. Production'da, `allow_credentials=True` bilan birga `allow_origins=["*"]` ishlatish — brauzerlar tomonidan **taqiqlanadi** (xavfsizlik sababli) va, hatto ruxsat berilsa ham, jiddiy xavfsizlik xatosi hisoblanadi. Har doim, aniq, ishonchli domenlar ro'yxatini ko'rsating.

### Boshqa foydali tayyor middleware'lar

```python
from fastapi.middleware.gzip import GZipMiddleware
from fastapi.middleware.trustedhost import TrustedHostMiddleware

app.add_middleware(GZipMiddleware, minimum_size=1000)
app.add_middleware(TrustedHostMiddleware, allowed_hosts=["mening-saytim.uz", "*.mening-saytim.uz"])
```

| Middleware | Vazifasi |
|---|---|
| `GZipMiddleware` | Katta javoblarni (1000 baytdan katta) avtomatik siqib (compress) yuboradi, tarmoq trafigini kamaytiradi |
| `TrustedHostMiddleware` | Faqat ruxsat etilgan `Host` header'iga ega so'rovlarni qabul qiladi (soxta host hujumlaridan himoya) |

### Middleware'larning bajarilish tartibi

Bir nechta middleware qo'shilganda, ular **"pastdan yuqoriga"** (oxirgi qo'shilgan — birinchi ishlaydi) tartibida bajariladi:

```python
app.add_middleware(MiddlewareA)   # 2-chi bo'lib ishlaydi
app.add_middleware(MiddlewareB)   # 1-chi bo'lib ishlaydi
```

Bu tartib — ayniqsa CORS middleware'ini **eng oxirida** (yoki, amalda, odatda birinchi qo'shishni, chunki u eng tashqi qatlamda ishlashi kerak) qo'shishda muhim ahamiyatga ega; FastAPI'ning rasmiy hujjatlarida, CORS middleware odatda boshqa middleware'lardan oldin (yoki alohida, boshida) qo'shiladi.

## Amaliy misol

To'liq, real loyihada uchraydigan middleware sozlamalari:

```python
import logging
import time
from fastapi import FastAPI, Request
from fastapi.middleware.cors import CORSMiddleware
from fastapi.middleware.gzip import GZipMiddleware

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("mening_api")

app = FastAPI(title="To'liq sozlangan API")

# 1. CORS - frontend bilan ishlash uchun
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000", "https://mening-saytim.uz"],
    allow_credentials=True,
    allow_methods=["GET", "POST", "PUT", "DELETE"],
    allow_headers=["Authorization", "Content-Type"],
)

# 2. GZip - katta javoblarni siqish
app.add_middleware(GZipMiddleware, minimum_size=1000)

# 3. Maxsus - so'rovlarni loglash va vaqtni o'lchash
@app.middleware("http")
async def log_va_vaqt_middleware(request: Request, call_next):
    boshlanish = time.time()
    logger.info(f"So'rov: {request.method} {request.url.path}")

    javob = await call_next(request)

    davomiylik = round(time.time() - boshlanish, 4)
    javob.headers["X-Ishlash-Vaqti"] = str(davomiylik)
    logger.info(f"Javob: {javob.status_code} ({davomiylik}s)")

    return javob

@app.get("/mahsulotlar")
def mahsulotlar():
    return {"mahsulotlar": [{"id": i, "nomi": f"Mahsulot {i}"} for i in range(1, 200)]}
```

Sinash — CORS va vaqt o'lchash header'ini tekshirish:

```bash
curl -i http://127.0.0.1:8000/mahsulotlar \
  -H "Origin: http://localhost:3000"
```

Javob header'larida `X-Ishlash-Vaqti` va CORS uchun `access-control-allow-origin: http://localhost:3000` ko'rinadi.

## Keng tarqalgan xatolar

**Xato 1:** CORS xatosini "backend muammosi" deb emas, balki noto'g'ri, frontend kodini tuzatishga urinib hal qilishga harakat qilish.
❌ CORS — brauzerning xavfsizlik siyosati bo'lib, uni **faqat server tomonda** (`CORSMiddleware` orqali) to'g'ri sozlash orqali hal qilish mumkin; frontend kodini o'zgartirish bu muammoni hal qilmaydi.
✅ To'g'ri: CORS xatosi ko'rilganda, birinchi navbatda backend'da `CORSMiddleware`ning to'g'ri sozlanganini (frontend manzili `allow_origins` ro'yxatida borligini) tekshiring.

**Xato 2:** production muhitda ham `allow_origins=["*"]` bilan qoldirish, "ishlayapti-ku" deb, xavfsizlik oqibatlarini o'ylab ko'rmaslik.
❌ Bu — istalgan veb-saytdan, sizning API'ingizga so'rov yuborilishi (ba'zi hollarda, foydalanuvchi cookie'lari bilan birga) mumkinligini bildiradi, bu esa CSRF kabi hujumlarga yo'l ochishi mumkin.
✅ To'g'ri: production'da, `allow_origins`ni har doim **aniq, ishonchli domenlar ro'yxati** bilan cheklang (masalan, faqat o'zingizning frontend manzilingiz).

**Xato 3:** maxsus middleware ichida, `await call_next(request)`ni chaqirishni unutish yoki uning natijasini qaytarmaslik.
❌ Agar `call_next(request)` chaqirilmasa, so'rov hech qachon asosiy endpoint funksiyasiga yetib bormaydi va so'rov "osilib qoladi" yoki xato beradi.
✅ To'g'ri: har bir maxsus middleware, har doim `javob = await call_next(request)` qatorini o'z ichiga olishi va oxirida `return javob` (yoki uning o'zgartirilgan versiyasini) qaytarishi shart.

## Mashq/topshiriq

**(Oson)** `CORSMiddleware`ni, faqat `http://localhost:5173` (Vite'ning standart porti) manzilidan kelgan so'rovlarga ruxsat beradigan qilib sozlang.

**(O'rtacha)** Har bir javobga, `X-Ilova-Nomi: Mening-API` nomli maxsus header qo'shuvchi middleware yozing.

**(Qiyin)** Ikkita middleware yozing: birinchisi — har bir so'rov uchun, tasodifiy (yoki ketma-ket hisoblovchi) noyob so'rov ID'sini (`X-Request-ID`) generatsiya qilib, uni javob header'iga qo'shsin; ikkinchisi — agar so'rov `/admin` bilan boshlansa va `X-Admin-Token` header'i `"maxfiy"`ga teng bo'lmasa, `403` javobini to'g'ridan-to'g'ri middleware darajasida qaytarsin (endpoint funksiyasiga yetib bormasdan). Ikkinchi middleware'ning nima uchun bu vazifa uchun `Depends()`dan ko'ra middleware sifatida yozilishi ham mumkinligini (garchi odatda `Depends()` afzalroq bo'lsa ham) muhokama qiling.

## Qisqacha xulosa

Middleware — har bir HTTP so'rov/javob uchun, endpoint funksiyasidan **oldin va keyin** ishga tushadigan umumiy qatlam bo'lib, logging, vaqt o'lchash yoki umumiy header qo'shish kabi vazifalar uchun ishlatiladi; u `Depends()`dan farqli o'laroq, muayyan endpoint'ga emas, balki **barcha** so'rovlarga taalluqli. **CORS** — brauzerning xavfsizlik mexanizmi bo'lib, frontend va backend turli domenlarda joylashganda uchraydigan keng tarqalgan muammo, va u `CORSMiddleware` orqali, `allow_origins`ni **aniq, ishonchli manzillar** bilan sozlash orqali hal qilinadi — production'da `["*"]` ishlatishdan qochish muhim xavfsizlik amaliyoti hisoblanadi. Keyingi bobda, endpoint'larni haqiqiy ma'lumotlar bazasi (PostgreSQL) bilan bog'lashni, SQLModel orqali o'rganamiz.
