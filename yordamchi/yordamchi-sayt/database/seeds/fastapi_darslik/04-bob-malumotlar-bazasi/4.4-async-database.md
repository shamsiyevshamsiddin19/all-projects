# Asinxron ma'lumotlar bazasi (async SQLAlchemy + asyncpg)

## Bu darsda nimalarni o'rganasiz

- Nima uchun asinxron ma'lumotlar bazasi ulanishi FastAPI'da samaraliroq ekanini tushunasiz
- `asyncpg` drayveri va asinxron engine/session sozlashni o'rganasiz
- Sinxron CRUD kodni asinxron ko'rinishga o'girishni bilasiz
- Qачон sinxron, qачон asinxron yondashuvni tanlashni tushunasiz

## Nazariy qism

### Nima uchun asinxron ma'lumotlar bazasi

0.1-darsda ko'rilganidek, FastAPI — to'liq asinxron (ASGI) framework. Agar ma'lumotlar bazasi so'rovlari **sinxron** (4.1-4.3-darslarda ko'rilgan `psycopg2` orqali) bo'lsa, har bir so'rov, ma'lumotlar bazasi javob berishini **kutayotganda**, butun so'rovni qayta ishlovchi oqim (thread) band bo'lib qoladi.

**Asinxron** ma'lumotlar bazasi drayveri (`asyncpg`) bilan, server — ma'lumotlar bazasi javobini kutayotgan paytda, **boshqa so'rovlarni** qayta ishlashga o'tishi mumkin, bu esa, ayniqsa yuqori yuklama (high load) ostida, sezilarli unumdorlik farqini beradi.

> 📌 **Qачон bu muhim:** kichik, kam trafikli loyihalarda, sinxron (`psycopg2`) va asinxron (`asyncpg`) orasidagi farq deyarli sezilmaydi. Farq — yuqori parallel so'rovlar soni (masalan, bir vaqtning o'zida minglab foydalanuvchi) ostida yaqqol namoyon bo'ladi. Yangi loyihalar uchun, boshidanoq asinxron yondashuvni tanlash — kelajakdagi masshtablanish uchun tavsiya etiladi.

### Kerakli paketlarni o'rnatish

```bash
uv add sqlmodel asyncpg
```

| Paket | Vazifasi |
|---|---|
| `asyncpg` | PostgreSQL uchun **asinxron** drayver (4.1-darsdagi sinxron `psycopg2`ning muqobili) |

### Asinxron engine yaratish

```python
# app/database.py
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession
from sqlmodel.ext.asyncio.session import AsyncSession as SQLModelAsyncSession
from app.config import sozlamalar

# Diqqat: manzil "postgresql://" emas, "postgresql+asyncpg://" bilan boshlanadi
ASYNC_DATABASE_URL = sozlamalar.database_url.replace("postgresql://", "postgresql+asyncpg://")

async_engine = create_async_engine(ASYNC_DATABASE_URL, echo=True)
```

> ⚠️ **Muhim nuance:** asinxron ulanish uchun, manzil (`DATABASE_URL`) — `postgresql://` emas, balki `postgresql+asyncpg://` bilan boshlanishi shart. Bu, SQLAlchemy'ga qaysi drayverni (sinxron `psycopg2` yoki asinxron `asyncpg`) ishlatish kerakligini bildiradi.

### Asinxron session dependency

```python
from sqlmodel.ext.asyncio.session import AsyncSession
from sqlalchemy.ext.asyncio import async_sessionmaker

AsyncSessionLocal = async_sessionmaker(async_engine, class_=AsyncSession, expire_on_commit=False)

async def async_session_olish():
    async with AsyncSessionLocal() as session:
        yield session
```

E'tibor bering: 4.1-darsdagi `with Session(engine)` — bu yerda `async with AsyncSessionLocal()`ga aylandi. `yield` naqshi (3.2-darsda ko'rilgan) — bu yerda ham xuddi shunday ishlaydi, faqat endi **asinxron** kontekstda.

### Sinxron va asinxron CRUD — solishtirma

| Amaliyot | Sinxron (4.2-dars) | Asinxron |
|---|---|---|
| Session olish | `def f(session: Session = Depends(...))` | `async def f(session: AsyncSession = Depends(...))` |
| Bitta yozuv | `session.get(Kitob, id)` | `await session.get(Kitob, id)` |
| Ko'p yozuv | `session.exec(select(...)).all()` | `(await session.exec(select(...))).all()` |
| Saqlash | `session.commit()` | `await session.commit()` |
| Yangilash | `session.refresh(obj)` | `await session.refresh(obj)` |

### To'liq asinxron endpoint misoli

```python
from typing import Annotated
from fastapi import APIRouter, Depends, HTTPException, status
from sqlmodel import select
from sqlmodel.ext.asyncio.session import AsyncSession

from app.database import async_session_olish
from app.models import Kitob, KitobYaratish, KitobJavob

router = APIRouter(prefix="/kitoblar", tags=["Kitoblar"])

@router.post("/", response_model=KitobJavob, status_code=status.HTTP_201_CREATED)
async def yaratish(
    kitob: KitobYaratish,
    session: Annotated[AsyncSession, Depends(async_session_olish)],
):
    db_kitob = Kitob.model_validate(kitob)
    session.add(db_kitob)
    await session.commit()
    await session.refresh(db_kitob)
    return db_kitob

@router.get("/{kitob_id}", response_model=KitobJavob)
async def bitta_kitob(
    kitob_id: int,
    session: Annotated[AsyncSession, Depends(async_session_olish)],
):
    kitob = await session.get(Kitob, kitob_id)
    if not kitob:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "Kitob topilmadi")
    return kitob

@router.get("/", response_model=list[KitobJavob])
async def royxat(session: Annotated[AsyncSession, Depends(async_session_olish)]):
    natija = await session.exec(select(Kitob))
    return natija.all()
```

### Asinxron jadval yaratish (`lifespan` bilan)

4.1-darsda ko'rilgan `SQLModel.metadata.create_all(engine)` — sinxron funksiya. Asinxron engine bilan, buni quyidagicha qilish kerak:

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI
from sqlmodel import SQLModel
from app.database import async_engine

@asynccontextmanager
async def lifespan(app: FastAPI):
    async with async_engine.begin() as conn:
        await conn.run_sync(SQLModel.metadata.create_all)
    yield

app = FastAPI(lifespan=lifespan)
```

`conn.run_sync(...)` — sinxron funksiyani (`create_all`), asinxron kontekst ichida xavfsiz ishga tushirish uchun ishlatiladi.

### Alembic va asinxron — qisqacha

4.3-darsda ko'rilgan Alembic — asinxron loyihalar bilan ham ishlaydi, lekin maxsus shablon talab qiladi:

```bash
alembic init -t async migrations
```

`-t async` bayrog'i — `migrations/env.py`ni, asinxron engine bilan ishlashga moslashtirilgan holda generatsiya qiladi (`async_engine_from_config` va `run_sync()` orqali). Migratsiyalarni yaratish va qo'llash buyruqlarining o'zi (`alembic revision --autogenerate`, `alembic upgrade head`) — o'zgarishsiz qoladi.

### Qачон sinxron, qачон asinxron tanlash kerak

| Vaziyat | Tavsiya |
|---|---|
| Yangi loyiha, kelajakda yuqori trafik kutilmoqda | Asinxron (`asyncpg`) |
| Kichik ichki vosita, prototip | Sinxron (`psycopg2`) — soddaligi tufayli |
| Loyihada allaqachon ko'p sinxron kutubxona (masalan, eski tashqi API mijozlari) ishlatilmoqda | Sinxron — aralashtirish murakkablikni oshiradi |
| O'quv/o'rganish maqsadida, FastAPI'ning to'liq imkoniyatlarini ko'rish | Asinxron — FastAPI'ning "tabiiy" uslubi |

> 📌 **Muhim eslatma:** ikkalasi ham **to'liq to'g'ri** yondashuv hisoblanadi. FastAPI'ning o'zi ikkalasini ham teng darajada yaxshi qo'llab-quvvatlaydi (0.1-darsda ko'rilganidek). Loyihani boshlashda, jamoa tajribasi va loyiha talablariga qarab tanlov qilinadi — muhimi, bitta loyiha ichida ikkalasini **aralashtirmaslik** (bir joyda sinxron, boshqa joyda asinxron session ishlatish — chalkashlik va xatolarga olib keladi).

## Amaliy misol

To'liq, asinxron FastAPI + PostgreSQL loyihasi:

```python
# app/config.py
from pydantic_settings import BaseSettings

class Sozlamalar(BaseSettings):
    database_url: str
    model_config = {"env_file": ".env"}

sozlamalar = Sozlamalar()
```

```python
# app/database.py
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker
from sqlmodel.ext.asyncio.session import AsyncSession
from app.config import sozlamalar

ASYNC_URL = sozlamalar.database_url.replace("postgresql://", "postgresql+asyncpg://")
async_engine = create_async_engine(ASYNC_URL, echo=False)
AsyncSessionLocal = async_sessionmaker(async_engine, class_=AsyncSession, expire_on_commit=False)

async def async_session_olish():
    async with AsyncSessionLocal() as session:
        yield session
```

```python
# app/main.py
from contextlib import asynccontextmanager
from fastapi import FastAPI
from sqlmodel import SQLModel
from app.database import async_engine
from app.routers import kitoblar

@asynccontextmanager
async def lifespan(app: FastAPI):
    async with async_engine.begin() as conn:
        await conn.run_sync(SQLModel.metadata.create_all)
    yield
    await async_engine.dispose()   # ilova to'xtaganda, ulanishlarni tozalash

app = FastAPI(title="Asinxron Kutubxona API", lifespan=lifespan)
app.include_router(kitoblar.router)
```

```bash
uv add sqlmodel asyncpg pydantic-settings
uv run fastapi dev app/main.py
```

## Keng tarqalgan xatolar

**Xato 1:** `DATABASE_URL`da `postgresql+asyncpg://` o'rniga, oddiy `postgresql://` qoldirish, keyin `asyncpg` bilan bog'liq xatolarga duch kelish.
❌ Standart `postgresql://` — SQLAlchemy'ni sinxron `psycopg2` drayverini qidirishga undaydi, bu esa asinxron engine bilan mos kelmaydi.
✅ To'g'ri: asinxron engine yaratishda, har doim manzilni `postgresql+asyncpg://` ko'rinishiga o'girishni unutmang (yuqoridagi misoldagi `.replace()` naqshi orqali, yoki `.env`da to'g'ridan-to'g'ri shu formatda yozib).

**Xato 2:** asinxron `session.get()`, `session.exec()`, `session.commit()` chaqiruvlarida `await` kalit so'zini unutish.
❌ `await`siz chaqirilgan asinxron funksiya — natija o'rniga, hali bajarilmagan "coroutine" obyektini qaytaradi, bu esa keyingi kodda tushunarsiz xatolarga (masalan, `'coroutine' object has no attribute ...`) olib keladi.
✅ To'g'ri: asinxron session bilan ishlaganda, har bir ma'lumotlar bazasi operatsiyasidan (`get`, `exec`, `commit`, `refresh`, `delete`) oldin, har doim `await` qo'yishni tekshiring.

**Xato 3:** bitta loyihada, ba'zi endpoint'larda sinxron `Session`, boshqalarida asinxron `AsyncSession`ni tasodifan aralashtirib ishlatish.
❌ Bu — ikkita alohida ulanish pool'ini (sinxron va asinxron) boshqarishga majbur qiladi, kodni tushunishni qiyinlashtiradi, va ba'zi holatlarda kutilmagan ulanish muammolariga olib kelishi mumkin.
✅ To'g'ri: loyiha boshida, sinxron yoki asinxron yondashuvdan **birini** tanlang va uni **butun loyiha davomida izchil** qo'llang; agar keyinchalik o'tish kerak bo'lsa, buni bosqichma-bosqich, ongli ravishda (barcha endpoint'larni birga o'zgartirib) amalga oshiring.

## Mashq/topshiriq

**(Oson)** 4.1-darsdagi sinxron `database.py` faylini, asinxron ko'rinishga (`create_async_engine`, `async_sessionmaker`) o'girib qayta yozing.

**(O'rtacha)** 4.2-darsdagi sinxron `POST /kitoblar` va `GET /kitoblar/{id}` endpoint'larini, to'liq asinxron ko'rinishga (`async def`, `await session...`) o'giring.

**(Qiyin)** `GET /kitoblar` (ro'yxat) endpoint'ini asinxron ko'rinishda yozing, unda `muallif` bo'yicha filtr va sahifalash (4.2-darsdagi kabi) ham bo'lsin. Nima uchun `session.exec(so_rov)` chaqiruvidan **keyin** `await` qo'yilishi, lekin natijaviy `.all()` chaqiruvida `await` kerak emasligini (yuqoridagi amaliy misoldagi `royxat` funksiyasiga qarab) tushuntirib bering.

## Qisqacha xulosa

Asinxron ma'lumotlar bazasi ulanishi (`asyncpg` + `create_async_engine`) — FastAPI'ning to'liq asinxron tabiatidan foydalanib, yuqori parallel yuklama ostida serverning samaradorligini oshiradi; bu, `postgresql+asyncpg://` manzil formati, `AsyncSession` va har bir ma'lumotlar bazasi operatsiyasidan oldin `await` qo'yishni talab qiladi. Sinxron (4.1-4.3-darslar) va asinxron yondashuvlarning ikkalasi ham to'liq to'g'ri hisoblanadi — tanlov, loyiha talablari va kutilayotgan yuklamaga bog'liq, lekin bitta loyiha ichida ularni aralashtirmaslik muhim. Bu bilan 4-bob (ma'lumotlar bazasi) yakunlanadi — keyingi bobda, foydalanuvchilarni autentifikatsiya qilish va API'ni himoya qilishni (OAuth2, JWT) o'rganamiz.
