# Pydantic v2 chuqur: Field, validatorlar va ichma-ich modellar

## Bu darsda nimalarni o'rganasiz

- `Field()` orqali modellarga qo'shimcha validatsiya va metama'lumot qo'shasiz
- `field_validator` va `model_validator` orqali maxsus validatsiya mantiqini yozasiz
- Ichma-ich (nested) Pydantic modellarini yaratishni o'rganasiz
- `ConfigDict` orqali model xatti-harakatini sozlashni bilasiz

## Nazariy qism

### Pydantic v2 — qisqa eslatma

1.3-darsda Pydantic modellarining eng oddiy qo'llanilishini ko'rgan edik. Ushbu darsda — **Pydantic v2** (FastAPI'ning joriy versiyasi ustiga qurilgan standart) ning chuqurroq imkoniyatlarini o'rganamiz.

### `Field()` — maydonlarga qo'shimcha qoidalar qo'shish

`Field()` — 1.2-darsda ko'rilgan `Query()`/`Path()`ga o'xshab, Pydantic model maydonlariga validatsiya qoidalari va metama'lumot qo'shish imkonini beradi:

```python
from pydantic import BaseModel, Field

class Mahsulot(BaseModel):
    nomi: str = Field(min_length=2, max_length=100)
    narx: float = Field(gt=0, description="Narx so'mda, 0 dan katta bo'lishi shart")
    chegirma_foizi: float = Field(default=0, ge=0, le=100)
    tavsif: str | None = Field(default=None, max_length=500)
```

| `Field()` parametri | Vazifasi |
|---|---|
| `default` | Standart qiymat |
| `min_length`, `max_length` | Matn/ro'yxat uzunligi chegarasi |
| `gt`, `ge`, `lt`, `le` | Son uchun chegaralar (qat'iy/qat'iy bo'lmagan) |
| `pattern` | Regulyar ifoda orqali matnni tekshirish |
| `description` | Avtomatik hujjatlarda (`/docs`) ko'rinadigan tavsif |
| `examples` | Swagger UI'da ko'rsatiladigan namuna qiymat |

### Majburiy maydon uchun `Field(...)`

Agar maydon majburiy bo'lib, lekin unga qo'shimcha validatsiya (masalan, `min_length`) qo'shish kerak bo'lsa:

```python
class Foydalanuvchi(BaseModel):
    ism: str = Field(..., min_length=2, max_length=50)
```

`...` (Ellipsis) — "standart qiymat yo'q, bu maydon **majburiy**" degan ma'noni bildiradi.

### `field_validator` — bitta maydon uchun maxsus validatsiya

Ba'zan, oddiy `Field()` chegaralaridan (uzunlik, son oralig'i) ko'ra murakkabroq tekshiruv kerak bo'ladi — masalan, email formatini yoki maxsus biznes qoidasini tekshirish:

```python
from pydantic import BaseModel, field_validator

class Foydalanuvchi(BaseModel):
    ism: str
    email: str
    parol: str

    @field_validator("email")
    @classmethod
    def email_tekshirish(cls, qiymat: str) -> str:
        if "@" not in qiymat:
            raise ValueError("Email manzilida '@' belgisi bo'lishi shart")
        return qiymat.lower()

    @field_validator("parol")
    @classmethod
    def parol_tekshirish(cls, qiymat: str) -> str:
        if len(qiymat) < 8:
            raise ValueError("Parol kamida 8 belgidan iborat bo'lishi kerak")
        if not any(c.isdigit() for c in qiymat):
            raise ValueError("Parolda kamida bitta raqam bo'lishi kerak")
        return qiymat
```

> 📌 **Muhim naqsh:** validator funksiya, tekshiruvdan o'tgan qiymatni **qaytarishi** shart (`return qiymat`) — bu, validator ichida qiymatni o'zgartirish (masalan, `email.lower()` orqali kichik harflarga o'tkazish) imkonini ham beradi.

### `model_validator` — bir nechta maydonni birgalikda tekshirish

Agar validatsiya, bitta emas, balki **bir nechta maydonning birgalikdagi** holatiga bog'liq bo'lsa (masalan, "parol" va "parol_tasdiqlash" bir xil bo'lishi kerak):

```python
from pydantic import BaseModel, model_validator

class RoyxatdanOtish(BaseModel):
    parol: str
    parol_tasdiqlash: str

    @model_validator(mode="after")
    def parollar_moslashi(self) -> "RoyxatdanOtish":
        if self.parol != self.parol_tasdiqlash:
            raise ValueError("Parollar bir-biriga mos kelmadi")
        return self
```

| Rejim | Qачон ishlaydi | Nimaga kirish huquqi bor |
|---|---|---|
| `mode="after"` | Barcha maydonlar alohida tekshirilgandan **keyin** | `self` orqali, allaqachon validatsiya qilingan barcha maydonlarga |
| `mode="before"` | Har qanday tekshiruvdan **oldin**, xom ma'lumot ustida | Xom (dict shaklidagi) kiruvchi ma'lumotga |

### Ichma-ich (nested) modellar

Real loyihalarda, ma'lumotlar tuzilmasi ko'pincha ierarxik bo'ladi. Pydantic — modellarni bir-biriga "ichma-ich" joylashtirishni tabiiy qo'llab-quvvatlaydi:

```python
class Manzil(BaseModel):
    shahar: str
    kocha: str
    uy_raqami: str

class Foydalanuvchi(BaseModel):
    ism: str
    email: str
    manzil: Manzil
    qoshimcha_manzillar: list[Manzil] = []
```

Kiruvchi JSON:

```json
{
  "ism": "Shamsiddin",
  "email": "shamsiddin@example.com",
  "manzil": {
    "shahar": "Toshkent",
    "kocha": "Amir Temur",
    "uy_raqami": "12"
  },
  "qoshimcha_manzillar": []
}
```

FastAPI/Pydantic — bu ichma-ich strukturani **avtomatik ravishda**, to'liq validatsiya qilib, mos Python obyektlariga aylantiradi (`foydalanuvchi.manzil.shahar` orqali kirish mumkin bo'ladi).

### `ConfigDict` — model xatti-harakatini sozlash

Pydantic v2'da, model sozlamalari (eski `class Config:` o'rniga) `model_config` atributi orqali, `ConfigDict` yordamida belgilanadi:

```python
from pydantic import BaseModel, ConfigDict

class Mahsulot(BaseModel):
    model_config = ConfigDict(str_strip_whitespace=True, extra="forbid")

    nomi: str
    narx: float
```

| `ConfigDict` parametri | Vazifasi |
|---|---|
| `str_strip_whitespace=True` | Matn maydonlaridagi ortiqcha bo'sh joylarni avtomatik olib tashlaydi |
| `extra="forbid"` | Modelda e'lon qilinmagan qo'shimcha maydonlar kelsa, xato beradi (standart holda ular e'tiborsiz qoldiriladi) |
| `frozen=True` | Modelni "o'zgarmas" (immutable) qiladi — yaratilgandan keyin maydonlarni o'zgartirib bo'lmaydi |
| `from_attributes=True` | Modelni, oddiy `dict`dan emas, balki ORM obyektlaridan (masalan, SQLAlchemy) ham yaratish imkonini beradi (4-bobda muhim bo'ladi) |

### Foydali Pydantic metodlari

```python
mahsulot = Mahsulot(nomi="Noutbuk", narx=8500000)

mahsulot.model_dump()          # -> Python dict'iga aylantirish
mahsulot.model_dump_json()     # -> JSON matniga aylantirish
Mahsulot.model_validate(dict_malumot)   # -> dict'dan model yaratish (validatsiya bilan)
```

## Amaliy misol

To'liq, real loyihada uchraydigan murakkab model — validatorlar va ichma-ich modellar bilan:

```python
from pydantic import BaseModel, Field, field_validator, model_validator, ConfigDict

class ManzilModeli(BaseModel):
    shahar: str = Field(min_length=2)
    pochta_indeksi: str = Field(pattern=r"^\d{6}$")

class BuyurtmaYaratish(BaseModel):
    model_config = ConfigDict(str_strip_whitespace=True)

    mijoz_ismi: str = Field(min_length=2, max_length=100)
    email: str
    mahsulot_soni: int = Field(gt=0, le=100)
    yetkazish_manzili: ManzilModeli
    izoh: str | None = Field(default=None, max_length=300)

    @field_validator("email")
    @classmethod
    def email_validatsiya(cls, qiymat: str) -> str:
        if "@" not in qiymat or "." not in qiymat.split("@")[-1]:
            raise ValueError("Yaroqli email manzili kiriting")
        return qiymat.lower()

    @model_validator(mode="after")
    def buyurtma_qoidalari(self) -> "BuyurtmaYaratish":
        if self.mahsulot_soni > 50 and not self.izoh:
            raise ValueError("50 tadan ortiq buyurtma uchun izoh majburiy")
        return self
```

FastAPI endpoint'ida ishlatilishi:

```python
from fastapi import FastAPI, status

app = FastAPI()

@app.post("/buyurtmalar", status_code=status.HTTP_201_CREATED)
def buyurtma_yaratish(buyurtma: BuyurtmaYaratish):
    return {
        "xabar": "Buyurtma qabul qilindi",
        "mijoz": buyurtma.mijoz_ismi,
        "shahar": buyurtma.yetkazish_manzili.shahar,
    }
```

Agar 60 dona mahsulot, izohsiz buyurtma qilinsa, `model_validator` avtomatik ravishda `422` xatosini, aniq sabab bilan qaytaradi.

## Keng tarqalgan xatolar

**Xato 1:** `field_validator` ichida `return qiymat`ni unutish.
❌ Agar validator funksiya hech narsa qaytarmasa (`None` qaytarsa), o'sha maydonning qiymati **`None`ga aylanib qoladi** — bu, kutilmagan va topish qiyin bo'lgan xatolarga olib keladi.
✅ To'g'ri: har bir `field_validator` funksiyasi, tekshiruv muvaffaqiyatli o'tgan taqdirda, **har doim** tekshirilgan (yoki o'zgartirilgan) qiymatni qaytarishi shart.

**Xato 2:** bir nechta maydonni birgalikda tekshirish kerak bo'lganda, buni noto'g'ri, alohida `field_validator`lar orqali amalga oshirishga urinish.
❌ `field_validator` — faqat **bitta** maydonga kirish huquqiga ega, boshqa maydonlarning qiymatiga ishonchli tarzda murojaat qila olmaydi (ularning tekshiruv tartibi kafolatlanmagan).
✅ To'g'ri: bir nechta maydonni birgalikda tekshirish uchun har doim `model_validator(mode="after")` ishlatiladi — bu yerda barcha maydonlar, `self` orqali, allaqachon tekshirilgan holda mavjud bo'ladi.

**Xato 3:** ichma-ich modellarni yaratishda, tashqi modelning maydon turini oddiy `dict` deb belgilash, alohida Pydantic modelini yaratmaslik.
❌ `manzil: dict` — bu holda, `manzil` ichidagi ma'lumotlar uchun **hech qanday validatsiya, tur tekshiruvi yoki avtomatik hujjat** yaratilmaydi.
✅ To'g'ri: har qanday ichma-ich, tuzilgan ma'lumot uchun alohida Pydantic modelini (`class Manzil(BaseModel): ...`) yarating va uni tashqi modelda tur sifatida ishlating — bu, to'liq validatsiya va aniq `/docs` hujjatini ta'minlaydi.

## Mashq/topshiriq

**(Oson)** `Mahsulot` modelini yarating, `narx` maydoni `Field(gt=0)` bilan, `nomi` esa `Field(min_length=3, max_length=100)` bilan cheklangan bo'lsin.

**(O'rtacha)** `field_validator` yordamida, `telefon_raqam` maydoni har doim `"+998"` bilan boshlanishini tekshiruvchi va, agar boshlanmasa, xato qaytaruvchi validatorni yozing.

**(Qiyin)** `Chegirma` nomli model yarating: `asl_narx: float`, `chegirmali_narx: float` maydonlari bilan. `model_validator(mode="after")` yordamida, `chegirmali_narx` har doim `asl_narx`dan **kichik** bo'lishini tekshiring (aks holda, tushunarli xato xabari bilan rad eting). Bu tekshiruvni, nima uchun alohida `field_validator`lar orqali emas, balki `model_validator` orqali amalga oshirish kerakligini tushuntirib bering.

from pydantic import BaseModel, model_validator

Bu — `model_validator` orqali amalga oshirilishi kerak, chunki tekshiruv **ikkita** maydonning (`asl_narx` va `chegirmali_narx`) **birgalikdagi** nisbatiga bog'liq; alohida `field_validator("chegirmali_narx")` — o'sha paytda `asl_narx` qiymati hali "tayyor" (ishonchli tarzda mavjud) bo'lishini kafolatlay olmaydi, `model_validator(mode="after")` esa, barcha maydonlar allaqachon o'zining alohida tekshiruvidan o'tgandan keyin ishlaganligi sababli, ikkalasiga ham xavfsiz murojaat qilish imkonini beradi.

## Qisqacha xulosa

`Field()` — model maydonlariga uzunlik, son chegaralari va hujjat tavsifi kabi qo'shimcha qoidalarni qo'shadi; `field_validator` — bitta maydon uchun maxsus (murakkab) tekshiruv mantiqini, `model_validator(mode="after")` esa — bir nechta maydonning birgalikdagi holatini tekshirish uchun ishlatiladi. Ichma-ich Pydantic modellari — real loyihalardagi ierarxik ma'lumot tuzilmalarini (masalan, foydalanuvchi ichida manzil) to'liq validatsiya bilan tabiiy ifodalash imkonini beradi, `ConfigDict` esa — modelning umumiy xatti-harakatini (bo'sh joylarni kesish, qo'shimcha maydonlarni taqiqlash, ORM'dan o'qish) sozlaydi. Keyingi darsda, validatsiya xato bo'lganda foydalanuvchiga qanday tushunarli xato xabarlarini qaytarishni (`HTTPException`) va fayl yuklashni o'rganamiz.
