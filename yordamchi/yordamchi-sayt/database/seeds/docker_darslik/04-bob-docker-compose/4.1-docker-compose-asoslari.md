# Docker Compose asoslari

## Bu darsda nimalarni o'rganasiz

- Docker Compose nima ekanini va u nima uchun kerakligini tushunasiz
- `compose.yaml` faylini yoza olasiz va asosiy direktivalarni qo'llay olasiz
- `docker compose up`/`down` va boshqa asosiy buyruqlarni ishlata olasiz
- Compose orqali tarmoq va volume'lar avtomatik qanday boshqarilishini tushunasiz

## Nazariy qism

### Muammo — qo'lda ko'p konteynerni boshqarish noqulay

3.2-darsda ko'rganimizdek, uchta konteynerni (tarmoq, volume, portlar bilan) qo'lda ishga tushirish uchun **bir necha uzun buyruq** kerak bo'ldi. Real loyihalarda esa ko'pincha 5-10 tagacha xizmat (Django, PostgreSQL, Redis, Celery, Nginx va h.k.) birgalikda ishlashi kerak — buni har safar qo'lda, uzun `docker run` buyruqlari bilan boshqarish **amaliy emas** va xatoga moyil.

### Docker Compose — yechim

**Docker Compose** — bir nechta konteynerni **bitta** YAML formatidagi konfiguratsiya fayli orqali tavsiflab, ularni **bitta buyruq** bilan ishga tushirish, to'xtatish va boshqarish imkonini beruvchi vosita. 0.2-darsda ko'rganimizdek, zamonaviy Docker Compose — `docker compose` (bo'sh joy bilan) plagin ko'rinishida ishlaydi.

### `compose.yaml` — asosiy tuzilma

Loyiha papkasi:

```
mening-loyiham/
├── compose.yaml
├── Dockerfile
├── requirements.txt
└── main.py
```

`compose.yaml`:

```yaml
services:
  veb:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_HOST=db
    depends_on:
      - db

  db:
    image: postgres:16
    environment:
      - POSTGRES_PASSWORD=parol123
      - POSTGRES_DB=mening_bazam
    volumes:
      - pg_data:/var/lib/postgresql/data

volumes:
  pg_data:
```

> 📌 **`version:` kaliti endi kerak emas.** Eski qo'llanmalarda `compose.yaml` fayli boshida `version: "3.8"` kabi qator ko'rasiz — bu **eskirgan** (obsolete) va zamonaviy Docker Compose'da endi e'tiborga olinmaydi (yozilsa, ogohlantirish chiqishi mumkin). Ushbu kursda `version:` kaliti **ishlatilmaydi** — zamonaviy Compose fayl formati avtomatik eng so'nggi sxemani ishlatadi.

### Asosiy direktivalar

| Direktiva | Vazifasi |
|---|---|
| `services:` | Har bir konteyner ("xizmat") tavsifi shu bo'lim ostida |
| `build: .` | Bu xizmat uchun image joriy papkadagi `Dockerfile`dan **qurilishi** kerak |
| `image: postgres:16` | Bu xizmat uchun tayyor image (Docker Hub'dan) ishlatiladi, qurish shart emas |
| `ports:` | Port mapping (1.1-darsdagi `-p` bilan bir xil) |
| `environment:` | Muhit o'zgaruvchilari (1.1-darsdagi `-e` bilan bir xil) |
| `volumes:` (xizmat ichida) | Volume yoki bind mount ulash |
| `volumes:` (fayl oxirida) | Loyihada ishlatiladigan **nomli volume'larni** e'lon qilish |
| `depends_on:` | Bu xizmat boshqa xizmat(lar)dan **keyin** ishga tushishi kerakligini bildiradi |
| `networks:` | Maxsus tarmoq(lar) ko'rsatish (agar ko'rsatilmasa, Compose **avtomatik** umumiy tarmoq yaratadi) |

### Muhim — Compose avtomatik tarmoq yaratadi

3.2-darsda biz `docker network create` orqali qo'lda tarmoq yaratgan edik. **Docker Compose buni avtomatik bajaradi** — `compose.yaml`dagi barcha xizmatlar standart holda **bitta umumiy tarmoqqa** ulanadi, va ular bir-birini **xizmat nomi** (`veb`, `db`) orqali topa oladi — xuddi 3.2-darsdagi qo'lda yaratilgan tarmoqdagi kabi, lekin hech qanday qo'shimcha buyruq yozmasdan.

### Asosiy Compose buyruqlari

```bash
docker compose up              # barcha xizmatlarni ishga tushirish (konsolni band qiladi)
docker compose up -d            # fon rejimida (detached) ishga tushirish
docker compose up --build        # ishga tushirishdan oldin image'larni QAYTA quradi

docker compose down              # barcha xizmatlarni to'xtatib, konteyner va tarmoqlarni o'chiradi
docker compose down -v             # + volume'larni HAM o'chiradi (ehtiyot bo'ling!)

docker compose ps                  # ishlayotgan xizmatlar holatini ko'rish
docker compose logs                 # barcha xizmatlarning loglarini ko'rish
docker compose logs -f veb            # faqat "veb" xizmatining loglarini, real vaqtda kuzatish

docker compose stop                  # xizmatlarni to'xtatish (o'chirmasdan)
docker compose start                  # to'xtatilgan xizmatlarni qayta ishga tushirish
docker compose restart veb              # faqat bitta xizmatni qayta ishga tushirish

docker compose exec veb bash              # ishlayotgan "veb" xizmati ichiga kirish (docker exec bilan bir xil)
```

### `docker compose up` vs `docker run` — nima farq qiladi

```bash
# docker run bilan (qo'lda, uzun):
docker network create mening_tarmoq
docker volume create pg_data
docker run -d --name db --network mening_tarmoq -e POSTGRES_PASSWORD=parol -v pg_data:/var/lib/postgresql/data postgres:16
docker build -t veb .
docker run -d --name veb --network mening_tarmoq -p 8000:8000 veb

# docker compose bilan (bitta buyruq, YUQORIDAGI compose.yaml asosida):
docker compose up -d
```

Bu — Docker Compose'ning asosiy amaliy qiymati: **murakkab, ko'p qadamli** konteyner sozlashlarini **bitta, o'qilishi oson, versiyalash mumkin bo'lgan** (Git'ga commit qilinadigan) fayl ichiga jamlash.

### `depends_on` — ishga tushirish tartibi (va uning cheklovi)

```yaml
services:
  veb:
    build: .
    depends_on:
      - db
  db:
    image: postgres:16
```

`depends_on: [db]` — Compose'ga `veb` xizmatidan **oldin** `db` konteynerini ishga tushirishni buyuradi. 

> ⚠️ **Muhim cheklov: `depends_on` faqat konteynerning ISHGA TUSHISHINI kutadi, xizmatning TO'LIQ TAYYOR bo'lishini emas.** Masalan, PostgreSQL konteyneri "ishga tushdi" deb belgilanishi mumkin, lekin ma'lumotlar bazasi hali **to'liq initsializatsiya bo'lmagan** bo'lishi mumkin (bir necha soniya kerak). Agar `veb` xizmati shu paytda bazaga ulanishga urinsa, xato chiqishi mumkin. Bu muammoning to'liq yechimi — `healthcheck` (6-bobda / keyingi darslarda ko'riladi).

## Amaliy misol

To'liq, ishlaydigan Python + PostgreSQL + Redis loyihasi Compose bilan:

```
mening-loyiham/
├── compose.yaml
├── Dockerfile
├── requirements.txt
└── main.py
```

`requirements.txt`:

```
psycopg2-binary==2.9.9
redis==5.0.1
```

`main.py`:

```python
import os
import time
import psycopg2
import redis

# Baza va Redis tayyor bo'lishini biroz kutish (soddalashtirilgan yechim)
time.sleep(3)

db_ulanish = psycopg2.connect(
    host=os.environ.get("DATABASE_HOST", "db"),
    dbname=os.environ.get("DATABASE_NAME", "mening_bazam"),
    user="postgres",
    password=os.environ.get("DATABASE_PASSWORD", "parol123"),
)
print("PostgreSQL bilan ulanish muvaffaqiyatli!")

redis_ulanish = redis.Redis(host=os.environ.get("REDIS_HOST", "kesh"), port=6379)
redis_ulanish.set("salom", "dunyo")
print(f"Redis'dan olingan qiymat: {redis_ulanish.get('salom').decode()}")
```

`Dockerfile`:

```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python3", "main.py"]
```

`compose.yaml`:

```yaml
services:
  veb:
    build: .
    depends_on:
      - db
      - kesh
    environment:
      - DATABASE_HOST=db
      - DATABASE_NAME=mening_bazam
      - DATABASE_PASSWORD=parol123
      - REDIS_HOST=kesh

  db:
    image: postgres:16
    environment:
      - POSTGRES_PASSWORD=parol123
      - POSTGRES_DB=mening_bazam
    volumes:
      - pg_data:/var/lib/postgresql/data

  kesh:
    image: redis:7-alpine

volumes:
  pg_data:
```

Ishga tushirish:

```bash
docker compose up --build

# Natija taxminan:
# db-1    | ... database system is ready to accept connections
# kesh-1  | ... Ready to accept connections
# veb-1   | PostgreSQL bilan ulanish muvaffaqiyatli!
# veb-1   | Redis'dan olingan qiymat: dunyo
```

Diqqat qiling: `main.py`da `host="db"` va `host="kesh"` — bular **compose.yaml'dagi xizmat nomlari**, va 3.2-darsda o'rgangan Docker networking tufayli, Compose bu nomlarni avtomatik DNS orqali to'g'ri IP manzillarga yo'naltiradi.

Barchasini tozalash:

```bash
docker compose down       # konteyner va tarmoqni o'chiradi, VOLUME saqlanib qoladi
docker compose down -v     # + volume'ni ham o'chiradi (ma'lumot butunlay yo'qoladi!)
```

## Keng tarqalgan xatolar

**Xato 1:** xizmat ichida `host` sifatida `localhost`ni ishlatish (3.2-darsdagi xatoning Compose kontekstidagi versiyasi).
❌ `DATABASE_HOST=localhost` — bu ishlamaydi, chunki `veb` konteyneri ichida `localhost` faqat o'zini anglatadi, `db` esa alohida konteyner.
✅ To'g'ri: `compose.yaml`dagi **xizmat nomini** (`db`, `kesh`) host sifatida ishlating — Compose buni avtomatik to'g'ri manzilga yo'naltiradi.

**Xato 2:** `depends_on`ni "baza to'liq tayyor bo'lguncha kutadi" deb noto'g'ri tushunish.
❌ Ilova kodi `depends_on: [db]` borligiga ishonib, darhol bazaga ulanishga urinadi, lekin PostgreSQL hali to'liq initsializatsiyadan o'tmagan bo'lishi mumkin, va ulanish xatosi chiqadi.
✅ To'g'ri: yuqoridagi misolda ko'rganimizdek vaqtinchalik `time.sleep()` (sodda, lekin ishonchsiz yechim) yoki (tavsiya etiladigan, to'g'ri yechim) `healthcheck` va qayta urinish mantig'ini (Python kursining 5.4-darsidagi `qayta_urin` dekoratoriga o'xshash) qo'shing.

**Xato 3:** `docker compose down -v`ni beparvolik bilan ishlatib, muhim ma'lumotni yo'qotish.
❌ Development paytida odatlanib, `docker compose down -v`ni doimiy ishlatish — bu har safar ma'lumotlar bazasidagi **barcha** ma'lumotni o'chiradi.
✅ To'g'ri: agar shunchaki konteynerlarni to'xtatish kerak bo'lsa, oddiy `docker compose down` (volume'siz) yetarli; `-v` faqat ma'lumotlarni ham **ataylab, aniq maqsad bilan** tozalamoqchi bo'lganda qo'shilishi kerak.

## Mashq/topshiriq

**(Oson)** 2.1-darsdagi `salomlashuv-app` loyihasi uchun oddiy `compose.yaml` yozing (`build: .` bilan, boshqa xizmatlarsiz) va `docker compose up --build` orqali ishga tushiring.

**(O'rtacha)** Yuqoridagi amaliy misoldagi loyihani o'zingiz qayta yarating (barcha fayllar bilan), `docker compose up --build` orqali ishga tushiring, so'ng `docker compose logs veb` orqali faqat `veb` xizmatining loglarini ko'ring.

**(Qiyin)** Yuqoridagi loyihaga to'rtinchi xizmat — `pgadmin` (PostgreSQL uchun veb-asosli boshqaruv paneli, `dpage/pgadmin4` image'i, `PGADMIN_DEFAULT_EMAIL` va `PGADMIN_DEFAULT_PASSWORD` muhit o'zgaruvchilari va `5050:80` port bilan) qo'shing, `docker compose up -d` bilan ishga tushiring va brauzerda `http://localhost:5050` orqali ochilishini tekshiring.

## Qisqacha xulosa

Docker Compose — bir nechta konteynerni `compose.yaml` (zamonaviy formatda, `version:` kaliti **kerak emas**) fayli orqali tavsiflab, `docker compose up`/`down` bilan bitta buyruqda boshqarish imkonini beradi; `services:` ostida har bir xizmat (`build:` yoki `image:`, `ports:`, `environment:`, `volumes:`, `depends_on:`) tavsiflanadi, Compose esa avtomatik umumiy tarmoq yaratib, xizmatlarni bir-biriga **nom orqali** (3.2-darsdagi Docker networking asosida) bog'laydi; `depends_on` faqat ishga tushirish **tartibini**, xizmatning to'liq tayyorligini emas, ta'minlaydi — bu keyingi darsda (`healthcheck` bilan) to'liqroq hal qilinadi.
